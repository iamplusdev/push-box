自托管 · 单向消息推送

PushBox

任何程序一条 POST /message，消息就推送到你自己的手机和电脑。服务端存下来、抓图转存、加密下发，多端几乎同时到账。

快速上手 → 它怎么工作
  • 三端源码：Java 服务端 · Android · Windows
  • 只要一个 MySQL 8，图片可以落本地目录
  • 不接厂商推送，不经第三方转发

它做的三件事

把"第三方产生的消息"送到"你人在的那块屏幕"上，中间不留别人的服务器。

01 收得进来

一个频道号加一个密钥，脚本、Grafana、CI、cron 都能发。同一条消息带同一个 msg_key 重复提交只会入库一次。

02 存得明白

正文与图片都在你自己的机器上：MySQL 里全文可搜，摘要由服务端生成，外链图片抓回来转存。

03 送得到位

长连接加密下发到每台设备，手机与 PC 同时出通知；一边点开会话，另一边红点随即消失。断线后按游标补齐。

一条消息走过的路

校验通过就立刻回执，抓图和下发都在回执之后——第三方等不起的那几秒不由它承担。

你的程序Grafana、CI、cron、内网服务
受理校验凭据、幂等、分配 seq、生成摘要，立即 200
抓图转存外链图片并发抓取 → 缩略图 → 存进你的存储

客户端入库、出通知；点进会话后别的端红点消失

先发一条试试

入站接口是 POST {base}/message，不在 /api/v1 下，凭据写在请求体里。

  1. 在管理台建一个频道，拿到频道号和密钥 浏览器打开服务端根路径 /，登录后「频道 → 新建」。密钥只显示一次。
  2. 把凭据写进 payload.json 
    {
  "channel": "12345678",
  "secret": "<频道密钥>",
  "type": "markdown",
  "level": "error",
  "sender_id": "grafana",
  "sender_name": "Grafana 告警",
  "title": "CPU 使用率超过 90%",
  "content": "主机 prod-03 · 近 5 分钟均值 92.4%"
}
  3. 发出去 
    curl -sS http://127.0.0.1:7404/message \
  -H 'Content-Type: application/json' \
  --data-binary @payload.json
    别用 -d 内联 JSON：Git Bash 会改动引号里的内容，服务端只会回「请求体必须是合法 JSON」。
  4. 回来看这一行的 code 200 表示已入库并排进下发；401 是频道号或密钥不对；429 是超过了频道的限速。
约 50 ms受理到通知到账（服务端与 MySQL 同机）
3 s图文合并窗口：正文先到，抓好的图并进同一帧

三端各自的安装步骤见 安装与部署；字段全表、响应形状与错误码见 入站 API。

一个要知道的取舍

服务端到设备这一跳是加密的（X25519 + AES-256-GCM 帧通道）；服务端库里存的是明文。

明文换来了什么

全文索引能命中正文、服务端能生成摘要、能替你抓取外链图片。这三件事都要读得到内容。

密钥只能写不能读

拿到 secret 能往这个频道推，但读不到任何历史。读历史要设备密钥或恢复码。

请上 HTTPS

帧加密补的是链路，TLS 补的是「服务端本身可信」，两者互不替代。证书做法见 安装与部署。

展开版在 概览 · 信任边界。

源码仓库

三端与文档在同一个仓库里。地址只有两个：GitHub 是主仓，Gitee 是给国内网络准备的镜像。

GitHub主仓

提交历史、Issue 与 CI 都在这边。安装包（APK / Windows Setup）与 Docker 镜像由 CI 在打标签时产出：只发服务端打 server-v*，只发 Android 打 android-v*，只发 Windows 打 windows-v*，三端一起发仍然用 v*。

git clone https://github.com/iamplusdev/push-box.git github.com/iamplusdev/push-box ↗
Gitee国内镜像

国内拉取更快。同步是手动的，所以它可能落后主仓；提 Issue 请回 GitHub。

git clone https://gitee.com/iamplus/push-box.git gitee.com/iamplus/push-box ↗

服务端与管理台不用自己构建：一个镜像同时含两者，跑法见 Docker 部署。
