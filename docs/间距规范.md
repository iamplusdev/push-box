# PushBox 间距规范

## 设计原则

- **基准单位**：8dp（对应1x密度下的8px）
- **所有间距必须是8的倍数或一半**：即 {4, 8, 12, 16, 24, 32, 48, 64}
- **避免使用奇数或非标准值**：如 6、10、14、20 等应替换为最接近的标准值

## 间距层级

| 层级 | 值 | 用途 |
|------|-----|------|
| XS | 4dp | 紧密元素内部间距（图标与文字、标签之间） |
| SM | 8dp | 常规内边距、列表项垂直间距、按钮内边距 |
| MD | 12dp | 中等间距（较少使用，用于需要比SM稍大但不到LG的场景） |
| LG | 16dp | 页面内边距、卡片外边距、Section间距 |
| XL | 24dp | Section标题间距、对话框内边距 |
| XXL | 32dp | 页面级分组间距、空状态上下边距 |
| XXXL | 48dp | 超大空白区域（欢迎页、错误页） |

## 常见场景

### 1. 列表项
- 垂直间距：`Arrangement.spacedBy(8.dp)`
- 水平内边距：`padding(horizontal = 16.dp)`
- 垂直内边距：`padding(vertical = 8.dp)`

### 2. 页面容器
- 外层内边距：`padding(horizontal = 16.dp, vertical = 12.dp)`
- Section间距：`Arrangement.spacedBy(16.dp)`

### 3. 卡片/气泡
- 内边距：`padding(12.dp)` 或 `padding(16.dp)`
- 元素间距：`Arrangement.spacedBy(8.dp)`

### 4. 按钮/操作区
- 水平间距：`Arrangement.spacedBy(8.dp)`
- 垂直间距：`padding(vertical = 8.dp)`

### 5. 图标与文字
- 间距：`padding(start = 8.dp)` 或 `Arrangement.spacedBy(4.dp)`

## 禁止使用的值

以下间距值应在代码审查中被替换：
- ❌ 1dp, 2dp → ✅ 4dp
- ❌ 6dp → ✅ 8dp
- ❌ 10dp → ✅ 8dp 或 12dp
- ❌ 14dp → ✅ 12dp 或 16dp
- ❌ 20dp → ✅ 16dp 或 24dp

- 已有代码里的内联值不保证逐处对表，改到哪一处就顺手把它对到最近的档；
- 间距目前三端都没有闸（字号有），所以对表这件事暂时只靠代码评审。

## Windows 实现

同样，`Tokens.xaml` 里**没有** `Spacing.*` 这些 key（2026-10-26 复核：那本字典里唯一的 `Thickness` 是控件模板里的 `BorderThickness`），间距是 XAML 里内联的 `Margin` / `Padding` 字面量（`apps/windows/PushBox.Windows` 下 175 处）。字号与行高已经收口（`MarkdownStyle` 常量 + `Text.*` 样式，由 `TypographyTest.cs` 钉住），间距的 token 化与 Android 一起另排；在此之前口径同上：新写的值按表取，改到哪处对到哪处。

**2026-10-27 补：间距有了第一处闸。** `PushBox.Crypto.Tests/PaneGapTest.cs` 钉的是"会话列表内容与消息头像之间那条空白带"——它不是一个值，是三处内联字面量相加（会话行右边距 + `GridSplitter` 手柄列 + 时间线 `ScrollViewer` 左内边距），原来 16+4+12=32，用户读成"头像离左侧列表太远"；三段各让一档到 8+4+8=20，都还在表的档上。选它做第一处，是因为这类"跨文件的和"最容易各改各的：单看任何一处都合理，加起来才太宽，而单点断言拦不住。其余 170 多处仍是内联字面量，token 化照旧另排。

## Web 实现

管理台没有 token 字典，间距直接写在 `components/PageHeader.vue` 与 `styles/typography.css` 里，值仍从上表取：

| 位置 | 值 | 说明 |
|------|-----|------|
| 页头下间距 | 24px (XL) | `PageHeader` 的 `margin-bottom`，标题块与第一张表/卡之间 |
| 页头内标题与说明 | 4px (XS) | 说明紧贴标题，不该被读成另一段 |
| 页头左右两块 | 16px (LG) | 标题区与 `#actions` 之间的 `gap` |
| 动作按钮组 | 12px (MD) | `#actions` 内部，Element 默认的 12px |
| 表格单元格左右 | 12px (MD) | `.el-table .cell` 的水平内边距 |
| 表格单元格上下 | **11px（例外）** | 见下 |

**11px 是唯一一处不在表里的值，理由是行高而不是间距**：行高由内容撑出来（13px 正文 / 18px 行高 + 上下内边距 + 1px 边框），所以内边距每动 1px 行高就动 2px——实测 11px 得到 44px 的数据行（表头 41px），按同一算法 12px 是 46px、8px 是 38px。扫一屏二十行时 46 太松、38 太挤，44 是 Element 默认 8px 行距之上"能一眼分清行"的最小档。改这个值之前先在真浏览器量一次行高，别按表格算。

**对话框只允许一层滚动**：`.el-dialog__body` 挂 `max-height: calc(100vh - 300px)` + `overflow-y: auto`，里面的 tab 面板、表单区不再各设 `max-height`。两层滚轮嵌在一起时，指针停在哪一层决定滚谁，填表的人得先"找滚动条"。唯一保留的内滚是预览气泡那 320px——它模拟的就是气泡自己的视口，属于内容而不是容器。
