## 运行测试

### 1. 服务端与加密库

```bash
# 先加载环境变量（一定要 `set -a`：local.env 里的 export 决定这些键能不能进到 JVM 进程环境）
set -a && . deploy/env/local.env && set +a

# 运行全部 Java 测试
JAVA_HOME=/path/to/jdk-21 mvn -B -pl core,server test
```

期望结果：**308/308**（core 43 + server 265）。碰库/碰桶的 114 条挂 `PB_S3_ACCESS_KEY` 门控，未配置时是 **194 执行 + 114 跳过**——而 `mvn test` 的退出码仍然是 0，所以总数变小先查环境变量，别改测试。`JAVA_HOME` 必须是 JDK 21（机器默认那个 1.8 会让编译器报出一片看不懂的语法错）。

### 2. 端到端探针

```bash
node deploy/probe/p0-e2e.mjs
```

探针会：
- 注册一个新设备
- 建一个频道
- 发 12 条消息（含外链图片）
- 断开重连验证补拉
- 验证接入过滤（错密钥 401、空号 400、跨组 404）
- 验证幂等 leave
- 验证列表标记翻转

期望结果：**末行 `N/N` 且 0 失败**。带序号的标签就是 `N`，它会随探针加用例一起涨，所以别把某个固定数字当判据。

### 3. Windows 客户端

```bash
dotnet test windows/PushBox.sln
```

期望结果：**554/554**（去掉「全部/未读/已读」筛选的两条用例之后的现值）。包括：
- 协议向量取证（`testvectors/vectors.json` 逐字节对账）
- 删除与清空回滚逻辑
- 搜索 query 转义与签名
- 媒体链路与缓存
- 通知策略与托盘
- UI 渲染断言（Markdown、主题、气泡）

### 4. 真服务体检

```bash
dotnet run --project windows/PushBox.LiveCheck -- http://127.0.0.1:8081
```

十二条判据：
1. 延迟 < 50ms
2. 签名正确
3. 字节接口返回原始 jpg/png
4. DELETE 单条消息
5. DELETE 清空会话
6. 接入频道（错密钥 401）
7. 接入频道（空号 400）
8. 接入频道（跨组 404）
9. 404 hint=message 不回滚
10. deleted=0 幂等成功
11. 接入后面板回显不含 secret
12. 投递面：同一条连接上未接入频道的实时帧缺席

期望结果：**12/12**。

### 5. 桶能力回归

```bash
node deploy/probe/rustfs-capability.mjs
```

验证三点：
- 多部分上传
- 生命周期规则
- SSE-C 加密

### 6. Android 编译

```bash
cd android
./gradlew :app:assembleDebug
```

Android 没有自动化 UI 测试，真机行为靠模拟器/手机走查。

## 真机走查清单

以下项目只能在真机或模拟器上验收，自动化测试覆盖不到：

### Android

| 项目 | 验收方法 |
|------|----------|
| 厂商保活矩阵（小米/华为/OPPO/vivo） | 杀后台后 1h/8h/24h 到账率与被杀率 |
| 深色模式与字体放大 | 系统设置里切换，UI 不崩坏 |
| 通知带头像 | 下拉通知栏看 `largeIcon` 是否为发送者头像 |
| 角标排除静音 | 静音频道的未读不计入桌面角标 |
| 会话内搜索定位 | 全局搜索命中后点击，会话滚到那一行并粉色高亮 |
| 每槽媒体状态 | 九宫格一格显示"已失效"/"加载失败"短词，单图用完整话术 |
| 负缓存只认 404 | 超时/5xx/401 不记 `.absent`，404 才记 |
| 更新确认框 | 关于页点「检查更新」，有新版弹「发现新版本 X，是否下载并安装？」，点「稍后」不下载、点「下载并安装」才取包并拉系统安装面板 |
| 启动自动检查开关 | 关掉「启动时自动检查更新」后冷启动不再发 GitHub 请求（可断网/抓包验证），手动按钮仍可用 |

### Windows

| 项目 | 验收方法 |
|------|----------|
| 托盘图标 | 左键唤起主窗，右键四个勾 + 打开/退出 |
| 通知点击落回会话 | 点通知后主窗自动滚到那条消息 |
| 静默时段 | 在设置里开整天，新消息不弹通知但入库 |
| 自启默认关 | 装完后 HKCU\...\Run 里没有 PushBox |
| 卸载保留数据 | 卸载后 `%LOCALAPPDATA%\PushBox` 还在，重装能认回同一个 Space |
| 更新确认框 | 设置→关于点「检查更新」，确有可装安装包时弹 `UpdatePromptWindow`；点「下载并安装」下 `PushBox-Setup-*-win-x64.exe` → 静默覆盖安装 → `ExitApp` 让开 mutex；不点确认不下载 |
| 启动自动检查开关 | 关掉「启动时自动检查更新」（`settings.json` 的 `auto_check_update`）后冷启动不发 GitHub 请求；开着时启动发现新版弹同一只确认框 |

## 常见测试陷阱

### 探针假失败

`leave` 的判据原先读的是 unseal 之后的 body 上的 `.status`，永远 `undefined`。helper 已改成同时带回 status 与 body（§8.2 第 66 条）。

### resume_gap 落后判定

`resume_gap` 的落后判定拿全局 `MAX(seq)` 减组内游标，dev 库攒到 2300 多条后，一个刚注册的新 Space 每次连接都被判成"落后一大堆"。修法是 `PbStore.latestSeq(groupId)` 只用在 WS 那一侧，REST 的 `latest_seq` 继续用全局值（§8.2 第 65 条）。

### STA 测试的 dispatcher 泵

`DispatcherTimer` 会把整个 xunit 测试主机弄崩。换成 `BeginInvoke(…, DispatcherPriority.SystemIdle)` + `PushFrame` 每圈必退。

### 头像色随机化

`string.GetHashCode()` 在 .NET 默认按进程随机化种子，同一名字两次运行换色。改成复刻 Java 的 31 多项式并把 `"hello".hashCode()==99162322` 钉成固定向量。
