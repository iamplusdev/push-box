## 测试分层

| 层级 | 工具 | 覆盖范围 | 判据 |
|------|------|----------|------|
| 单元测试 | JUnit 5 / xunit | `packages/core/` 加密库、`apps/server/` 业务逻辑、`apps/windows/` 客户端逻辑 | 断言通过数 |
| 前端排版断言 | node:test | `apps/web-admin/` 源码里的字号、行高、页头、表格节奏、对话框滚动层数 | 条数不低于 `ci.yml` 的 `WEB_BASELINE` |

## 运行测试

### 1. 服务端与加密库

```bash
# 不再 source 任何环境变量：测试读的是 surefire 工作目录下的那份配置，
# 也就是 apps/server/data/config/pushbox.json（安装页写出的同一份文件，见「配置文件」一节）。
# 想让测试连别的库/桶，改这个文件，或者用 -Dpb.config-file= 指另一份。

# 运行全部 Java 测试
JAVA_HOME=/path/to/jdk-21 mvn -B -pl :pushbox-core,:pushbox-server test
```

期望结果：**375/375**（core 50 + server 325）。门控分两档：只需连得上库的 14 个类挂 `databaseReady`，开发机照跑；要真桶的 media 5 个类挂 `objectStorageReady`（它们验的是 SSE-C 客户钥、封装格式、无钥读 400 这类 S3 语义，本地目录照不出来），本地存储模式下是 **342 执行 + 33 跳过**——而 `mvn test` 的退出码仍然是 0，所以总数变小先查 `apps/server/data/config/pushbox.json`，别改测试。CI 两档都满足（service container 起真 MySQL + 真 RustFS），跳过必须为 0。`JAVA_HOME` 必须是 JDK 21（机器默认那个 1.8 会让编译器报出一片看不懂的语法错）。

### 2. 端到端探针

```bash
node infra/probe/p0-e2e.mjs
```

探针会：
- 注册一个新设备
- 建一个频道
- 发 12 条消息（含外链图片）
- 断开重连验证补拉
- 验证接入过滤（错密钥 401、空号 400、跨组 404）
- 验证幂等 leave
- 验证列表标记翻转

期望结果：**末行 `N/N` 且 0 失败**。带序号的标签就是 `N`，它会随探针加用例一起涨，所以别把某个固定数字当判据。

### 3. Windows 客户端

```bash
dotnet test apps/windows/PushBox.sln
```

期望结果：**554/554**（去掉「全部/未读/已读」筛选的两条用例之后的现值）。包括：
- 协议向量取证（`contracts/testvectors/vectors.json` 逐字节对账）
- 删除与清空回滚逻辑
- 搜索 query 转义与签名
- 媒体链路与缓存
- 通知策略与托盘
- UI 渲染断言（Markdown、主题、气泡）

### 4. 真服务体检

```bash
dotnet run --project apps/windows/PushBox.LiveCheck -- http://127.0.0.1:8081
```

十二条判据：
1. 延迟 < 50ms
2. 签名正确
3. 字节接口返回原始 jpg/png
4. DELETE 单条消息
5. DELETE 清空会话
6. 接入频道（错密钥 401）
7. 接入频道（空号 400）
8. 接入频道（跨组 404）
9. 404 hint=message 不回滚
10. deleted=0 幂等成功
11. 接入后面板回显不含 secret
12. 投递面：同一条连接上未接入频道的实时帧缺席

期望结果：**12/12**。

### 5. 桶能力回归

```bash
node infra/probe/rustfs-capability.mjs
```

验证三点：
- 多部分上传
- 生命周期规则
- SSE-C 加密

### 6. Android 编译与 JVM 单测

```bash
cd apps/android
JAVA_HOME=/path/to/jdk-21 ./gradlew :app:testDebugUnitTest :app:assembleDebug
```

- `:app:testDebugUnitTest` 跑 `app/src/test` 下的纯 JVM 用例（29 条、6 个类：`TypographyTest`、`TimeLabelsTest`、`ViewedConversationTest`、`MediaSaveNamingTest`、`A11ySourceTest`、`ConversationStateSourceTest`），不需要模拟器。`A11ySourceTest` 读的是源码文本而不是 semantics 树（没有为四条断言引 Robolectric），它钉的是"返回键文案 / 底栏 Tab 语义 / 红点报条数这三行别被顺手删掉"。`ConversationStateSourceTest` 用同一个办法：切会话这件事的可观测量在 `LazyListState` 里，JVM 侧拿不到，于是钉源码里那三个约定（外层 `key(两把 id)`、详情页不许拿会话行当键、开屏用 `scrollToItem`），**计数与断言都在文本上，不在屏幕上**。
- Android 没有自动化 UI 测试，真机行为靠模拟器/手机走查。

### 7. Web 管理台

```bash
cd apps/web-admin
npm test
```

11 条排版断言，`node --test` 直接跑 `tests/*.test.mjs`，零依赖、只读源码，不构建也不起服务：六档字号与行高逐值对表、Element 的六档必须全部指回 `--pb-font-*`、`.vue` 里不许出现裸字号与裸行高、等宽字体族只在 `typography.css` 写一次、页头那四个数只有 `PageHeader.vue` 一个来源、定时任务对话框只有两处滚动、`typography.css` 必须排在 `element-plus` 之后。判据是条数不低于 `ci.yml` 里的 `WEB_BASELINE`——`node --test` 在一条用例都没发现时同样退 0，光看退出码分不出"全绿"和"整份文件没被跑到"。

它断的是源码里的数，不是渲染出来的像素，所以量渲染仍要真浏览器：本机 mock 管理台 API 挂 8081，`PB_ADMIN_API=http://127.0.0.1:8081 npm run dev` 起 7403，再按 `docs/字体规范.md` §机器把关那三处抽查 `getComputedStyle`。

类型检查与构建是另一道闸，改完样式一起跑：

```bash
cd apps/web-admin
npm run build
```

| 启动三态 | 冷启动不闪注册页，也不先闪"还没有会话 / 还没有消息"；真空空间才显示空态插画与"前往「频道」创建或加入频道" |

| 更新确认框 | 关于页点「检查更新」，有新版弹「发现新版本 X，是否下载并安装？」，点「稍后」不下载、点「下载并安装」才取包并拉系统安装面板 |

## 常见测试陷阱

### 探针假失败

`leave` 的判据原先读的是 unseal 之后的 body 上的 `.status`，永远 `undefined`。helper 已改成同时带回 status 与 body（§8.2 第 66 条）。

### resume_gap 落后判定

`resume_gap` 的落后判定拿全局 `MAX(seq)` 减组内游标，dev 库攒到 2300 多条后，一个刚注册的新 Space 每次连接都被判成"落后一大堆"。修法是 `PbStore.latestSeq(groupId)` 只用在 WS 那一侧，REST 的 `latest_seq` 继续用全局值（§8.2 第 65 条）。

### STA 测试的 dispatcher 泵

`DispatcherTimer` 会把整个 xunit 测试主机弄崩。换成 `BeginInvoke(…, DispatcherPriority.SystemIdle)` + `PushFrame` 每圈必退。

### 头像色随机化

`string.GetHashCode()` 在 .NET 默认按进程随机化种子，同一名字两次运行换色。改成复刻 Java 的 31 多项式并把 `"hello".hashCode()==99162322` 钉成固定向量。
