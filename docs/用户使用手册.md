## 1. 快速开始

### 1.1 你需要什么

- **一台 Android 手机**（Android 8.0+）
- **一台 Windows 电脑**（Windows 10/11）
- **一个自托管的 PushBox 服务端**（或联系管理员获取服务器地址）

### 1.2 三步上手

#### 步骤 1：在 Android 上注册空间

1. 打开 App，关掉"使用 HTTPS（SSL/TLS）"开关（本机/内网测试通常是纯 HTTP），填主机与端口，下面会实时拼出完整地址（例如 `http://<服务端所在机器的内网 IP>:7404`）
2. 填写设备名称（默认填好当前手机型号，可改）
3. 点击"创建我的空间"
4. **抄下恢复码**（这是找回历史的唯一凭据，泄露等于任何人可读你的消息）

> 换过网络或重打地址很烦：注册过一次后，首启页会出现"最近使用"一排按钮，点一下就整条回填（含协议与端口）。

#### 步骤 2：在 Windows 上加入同一空间

1. 打开 Windows 客户端
2. 输入相同的服务器地址
3. 点击"我有恢复码"
4. 粘贴从 Android 复制的恢复码
5. 填写设备名称，点击"加入"

Android 侧同一条路：首启页"加入已有空间" → 展开后手输恢复码，或直接点"扫码填入"扫 Windows 上展示的那枚二维码。

#### 步骤 3：发送第一条消息

在任意终端执行：

```bash
curl -X POST https://pushbox.example.com/message \
  -H 'content-type: application/json' \
  -d '{
    "channel": "YOUR_CHANNEL_NO",
    "secret": "YOUR_SECRET",
    "type": "text",
    "content": "Hello PushBox!"
  }'
```

你应该在**两端同时收到通知**（实测延迟 < 50ms）。

## 2. Android 客户端使用

### 2.1 主界面

底部三个 Tab：

- **消息**：显示所有收到的消息会话
- **频道**：接入这件事都在这里 —— 新建频道、加入频道、我的频道
- **设置**：设备与恢复码、通知、后台常驻、外观、数据、关于

顶栏只有 App 名和连接状态（●已连接 / 连接中 / 离线 / 异常）。

### 2.2 创建频道

1. 点底部"频道"
2. 输入频道名称（可选）
3. 点击"新建频道"
4. 抄下频道号和密钥（用于第三方推送）

### 2.3 加入频道

如果你的朋友创建了一个频道并分享了频道号+密钥：

1. 点底部"频道"
2. 在"加入频道"区域输入频道号和密钥
3. 点击"加入频道"

### 2.4 只接收已接入的频道

默认情况下，你会收到 Space 内所有频道的消息。如果想过滤：

1. 点底部"频道"
2. 打开"只接收已接入的频道"开关

> **注意**：开启后，未接入的频道消息将不会显示，但不会影响其他设备。一台都没接入就开启的话，页面会直接红字提醒你"现在收不到任何消息"。

### 2.5 管理我的频道

「频道」页下半部分是**我的频道**列表，每行只显示名称、频道号与提醒上限，所有动作收在行尾那枚 `⋮` 里。点开是一张分组弹窗：

| 分组 | 里面有什么 |
|------|-----------|
| 接入与命名 | 接入 / 取消接入、重命名、复制频道号 |
| 密钥 | **复制密钥**、重置密钥 |
| 治理 | 治理设置（限流、白名单、提醒上限、静音）、发送者白名单、容量报表 |
| 改号与清理 | 换发新频道号、清空、归档（后两项红色，都要二次确认） |

**关于"复制密钥"**：密钥只在**创建、重置、你手动加入**的那一刻出现过，服务端此后只存它的哈希，所以这一项复制的是**本机留存的那一份**，不是去服务端查的。由此有两件事要提前知道：

- 换了一台设备、或者把 App 的数据清过，本机就没有这份密钥了 —— 那一组会显示"本机没有这份密钥"，此时唯一的出路是**重置密钥**，然后把新密钥重新配到第三方推送方。
- **换发新频道号**会把这份留存一起搬到新号上，不会因为改号而丢失；但**重置密钥**会让旧密钥立刻失效，正在用旧密钥推送的那一侧要跟着改。

### 2.6 会话操作

长按会话行可弹出菜单：

- **置顶**：将会话固定在列表顶部
- **免打扰**：该会话不弹通知，但消息仍入库
- **重命名**：自定义会话显示名称
- **设头像**：为发送方设置本地头像
- **清空聊天记录**：删除该会话的所有消息（服务端也会同步删除）

### 2.7 搜索消息

1. 进入某个会话，点右上角的放大镜
2. 输入关键词，实时显示本会话已缓存的消息，命中的词变蓝加粗
3. 点"关闭"退出搜索态

> 会话页不再有"全部 / 未读 / 已读"筛选：消息一少，筛选换来的只是"我怎么只看得到一半"的困惑（D17，PC 与 Android 已各自撤掉）。

### 2.8 设置

点底部"设置"：

- **连接状态**：显示当前与服务端的连接情况
- **服务器**：查看/更换服务器地址
- **设备信息**：查看设备 ID、恢复码
- **通知**：开关新消息通知、设置静默时段
- **保活**：引导关闭电池优化、允许自启
- **外观**：深色模式、字体大小
- **数据**：查看本地消息数、清除缓存、导出 JSON
- **关于**：显示当前版本号；「启动时自动检查更新」开关（默认开）决定是否在冷启动时安静地查一次 GitHub Releases，关掉就只能手动点。点「检查更新」拉到比当前新的版本时弹出确认框「发现新版本 X，是否下载更新？」，点「下载并安装」才取包（会请求"安装未知应用"权限，最后一步由系统安装面板确认）；启动时静默查到的新版也走同一只确认框，不自动下载

## 3. Windows 客户端使用

### 3.1 主界面布局

PC 端采用微信风格的三栏布局：

- **最左侧菜单栏**（60px）：设置按钮 + 连接状态
- **中间消息列表**（260px）：所有会话
- **右侧对话区**：选中会话的消息时间线

### 3.2 窄窗口模式

当窗口宽度 < 720px 时，自动退化为单栏：

- 显示会话列表时隐藏对话区
- 点击会话后显示对话区，按"←"返回

### 3.3 会话操作

右键会话行可弹出菜单：

- **置顶**：固定到列表顶部
- **免打扰**：不弹通知
- **重命名**：自定义名称
- **设头像**：选择本地图片作为头像
- **清空聊天记录**：删除该会话所有消息

### 3.4 对话区

> 这里原来有一节"全部 / 未读 / 已读"筛选，已经整条撤掉（D17）：消息一少，筛选换来的只是"我怎么只看得到一半"的困惑。时间线就是全部消息，看历史往上滚、要找内容用搜索。

选中一条会话后，右侧显示该会话的消息时间线：

- **消息气泡**：每条消息左侧显示发送者头像（44px 圆角 6），右侧是气泡本体；气泡内上方可能显示图片，下方是正文；气泡左侧有 3px 竖条标识级别（warning 琥珀色、error 红色）
- **右键菜单**：在消息上点右键可「删除这条消息」（确认后从服务端和本地同时移除）
- **搜索**：顶栏搜索框输入关键词即时命中本地缓存，回车后合并服务端结果；搜索结果按日期分节，点击定位到命中消息
- **新消息提示**：正在往上翻历史时，底部会出现胶囊"X 条新消息"，点它回到底部

### 3.5 设置

点击左下角 `⚙` 按钮打开设置窗口：

#### 频道页

- **新建频道**：创建新频道并获取频道号+密钥
- **加入频道**：输入频道号+密钥加入已有频道
- **频道管理**：对已创建的频道进行治理（限流、白名单、归档等）

#### 设备页

- **设备列表**：查看 Space 内所有设备
- **吊销设备**：远程踢掉某台设备（需凭恢复码重新加入）
- **恢复码**：查看/轮换/复制恢复码

#### 通知页

- **新消息通知**：开关 Toast 通知
- **静默时段**：设置免打扰时间段（例如 23:00 - 07:00）
- **开机自启**：是否在登录时自动启动
- **关闭窗口时最小化到托盘**：关窗不等于退出

#### 关于页

- **当前版本**：显示本机版本号
- **启动时自动检查更新**：开关（默认开）决定是否在冷启动时安静地查一次 GitHub Releases；关掉后只在启动时不发请求，这里的手动按钮仍可用
- **检查更新**：从 GitHub Releases 查询是否有新版本；确有可下载的 Windows 安装包时弹出确认框「发现新版本 X，是否下载并安装？」
- **下载并安装**（在确认框里点）：把 `PushBox-Setup-*-win-x64.exe` 下到本地后静默覆盖安装，App 随即退出，安装完成后手动重新启动即可；没点确认就不会取包
- App 冷启动时若开着自动检查，发现新版也弹同一只确认框，下载这一步仍要用户当场点（更新检查走 GitHub 公开接口，与自建服务器无关，只在启动和手动点两处触发）

### 3.6 退出空间

如果需要完全清空本地数据并回到首启界面：

1. 打开设置窗口
2. 滚动到底部
3. 点击"退出空间（清空数据）"
4. 确认后将清空所有会话、消息、身份，回到注册页

> **警告**：此操作不可撤销。如需保留历史，请先在其他设备上备份恢复码。

## 4. Web 管理台

管理台和服务端是**同一个进程、同一个端口**：`infra/Dockerfile` 的构建阶段会把前端产物打进 jar，所以只要服务端在跑，浏览器打开**根路径 `/`** 就能用（不是 `/admin`，那个地址现在直接 404）。第一次启动还没有配置文件时，同一个地址上出现的是**安装页**——填完提交，进程接着往下走，刷新就是管理台。

**登录**只有一样东西：管理台口令，也就是安装页里填、写进 `data/config/pushbox.json` 的 `admin.password`。它换一个 24 小时的令牌，令牌由同一份配置里那把 `admin.jwtKey` 签（首次启动自动生成，不用你填），到期或换浏览器就重新登一次。**口令留空的安装等于没开管理台**：所有管理台请求一律 403，登录永远不成功——这是默认状态，不是故障。

| 页面 | 能做什么 | 看不到什么 |
|------|----------|------------|
| 概览 | 全局计数与近 14 天趋势 | 具体某条消息 |
| 频道 | 按号码/名称/空间搜，看详情与该频道已接入的设备 | **不能建频道、不能重置密钥**（见下） |
| 设备 | 按设备 ID/名称/空间搜，吊销某台设备 | 不能替设备重新注册 |
| 消息 | 跨所有空间全文搜索（关键词 / 频道号 / 类型 / 起始时间） | 只读，不能删、不能改 |
| 定时任务 | 新建、编辑、启停、删除带 cron 的推送任务 | 列表不含正文，要点进详情才看得到 |

**建频道与重置密钥这一版只有接口、没有界面按钮**（`POST /api/v1/admin/channels`、`POST /api/v1/admin/channels/{channelNo}/rotate-secret`）。日常不必绕这一圈：在 Android 或 Windows 客户端的「频道」页就能新建，密钥也在那里重置（Android 那一份还支持"复制密钥"，读的是本机留存）。要走接口的场合是写运维脚本，口径与响应形状见 [管理台 API](https://iamplusdev.github.io/push-box/admin-api.html)。

**重置密钥意味着什么**：旧密钥立刻签不进新消息，所有还拿着旧串的发送方（第三方脚本、curl 那一条）都要换成新的，否则从下一次请求起统一被拒。这一次调用还会顺带解除该频道的凭据锁定，所以不会遇到"钥换了、频道还锁着"这种两头各等一次的局面。**历史消息不受影响**——已经收进设备里的那些不靠这把钥解。

## 5. 常见问题

### Q1：为什么只有一端收到消息？

**可能原因**：

1. **身份文件被复制**：如果把 Android 的 `identity.json` 复制到另一台设备，得到的不是"两台设备"而是"两台轮流持有同一条连接"。症状是只有一端收得到，且随启动顺序漂移。
   
   **解决**：第二台设备必须通过"恢复码加入"流程注册，而不是复制身份文件。

2. **开启了"只接收已接入的频道"**：如果一台设备接入了某个频道，另一台没有，那么没接入的那台就收不到该频道的消息。
   
   **解决**：检查两端的"只接收已接入的频道"开关状态，确保都接入了目标频道。

### Q2：通知不响怎么办？

**检查清单**：

1. 系统通知权限是否开启
2. App 内"新消息通知"开关是否打开
3. 是否在静默时段内
4. 该会话是否设置了"免打扰"
5. Android 电池优化是否限制了后台活动

### Q3：重装后如何恢复历史？

1. 在新设备上安装 App
2. 输入相同的服务器地址
3. 点击"我有恢复码"
4. 粘贴之前抄下的恢复码
5. 等待同步完成（取决于消息数量）

> **重要**：恢复码是找回历史的唯一凭据，请妥善保管。

### Q4：如何彻底删除一条消息？

1. 右键消息（PC）或长按消息（Android）
2. 选择"删除"
3. 确认后，消息会从：
   - 本机立即消失
   - 服务端标记为 tombstone
   - 其他设备在下次同步时消失
   - S3 对象在宽限期后删除

### Q5：图片加载失败怎么办？

- **显示"已失效"**：表示服务端已删除该图片，无法再取回
- **显示"加载失败"**：可能是网络问题，点击重试按钮
- **一直转圈**：检查网络连接，或服务端抓取尚未完成

## 6. 故障排查

### 5.1 连接状态显示"离线"

**可能原因**：

1. 服务器地址错误
2. 服务端未启动
3. 网络不通（防火墙/代理）
4. 设备被吊销

**排查步骤**：

1. 检查服务器地址是否正确（包含 `http://` 或 `https://`）
2. 在浏览器访问服务器地址，确认服务在运行
3. 检查网络连接（ping 服务器）
4. 查看日志（Android: Logcat；Windows: `%LOCALAPPDATA%\PushBox\logs`）

### 5.2 消息延迟超过 1 秒

**可能原因**：

1. 网络延迟高
2. 服务端负载高
3. 客户端处于省电模式

**排查步骤**：

1. 检查网络质量（ping 服务器）
2. 查看服务端日志（是否有慢查询）
3. Android：关闭电池优化，允许后台活动
4. Windows：检查是否开启了"极致省电轮询模式"

### 5.3 搜索不到消息

**可能原因**：

1. 关键词拼写错误
2. 消息在服务端但本地未同步
3. 中文分词问题（少于 2 个字符的词可能搜不到）

**排查步骤**：

1. 尝试更短的关键词
2. 下拉刷新会话列表触发同步
3. 检查服务端搜索是否正常（curl 测试）

### 5.4 Windows 客户端启动报错

**常见错误**：

- **"The SSL connection could not be established"**：自签证书未安装到受信任根存储
- **"FileNotFoundException: identity.json"**：首次启动正常，应该显示首启界面
- **"Access to the path is denied"**：以管理员身份运行一次

**解决**：参考 [Windows 开发环境安装教程](Windows开发环境安装教程.md)
