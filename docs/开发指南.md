## 前置条件

| 组件 | 版本要求 | 用途 |
|------|----------|------|
| JDK | 21（推荐 21.0.8） | 编译 `packages/core/` 与 `apps/server/` |
| Maven | 3.6+ | 构建 Java 模块 |
| Node.js | 18+ | 运行探针脚本与网站 |
| Android SDK | API 34 | 编译 Android 客户端 |
| Gradle | 8.x（由 wrapper 提供） | 构建 Android |
| .NET SDK | 8.0 | 编译 Windows 客户端 |
| MySQL | 8.0（`ngram_token_size=2`） | 服务端数据库 |
| S3 兼容存储 | RustFS / MinIO | 图片转存桶（**本机开发可不装**，dev 默认落本地文件） |

### 配置文件

服务端**不读任何环境变量**。全部配置来自一份 JSON：工作目录下的 `data/config/pushbox.json`。
第一次启动没有这个文件时，进程先在 7404 上开一个安装页，你在浏览器里填完提交，它把结果写进那个文件
然后**接着启动 Spring，不用重启**。之后再启动就直接读文件、不再出现安装页。

本机开发的工作目录是 `apps/server/`（`infra/run-dev.sh` 会 `cd` 进去，surefire 也一样），所以那份文件是
`apps/server/data/config/pushbox.json`。整个 `apps/server/data/` 已 gitignore——里面有明文口令。

起步**只必填库那五项**：

| 项 | 说明 |
|------|------|
| `database.host` / `port` / `name` / `username` / `password` | 五段分开填，JDBC URL 由 `RuntimeConfig.jdbcUrl()` 拼。**别填 `127.0.0.1` 又指望它连宿主**——那是给容器写的口径，本机跑 jar 时环回就是这台机器，填 `127.0.0.1` 是对的 |
| `storage.s3` | `false`（默认）= 本地目录，图片落 `data/media`，**不需要任何桶就能起一个能收消息的服务端**；`true` = 下面那几项必填 |
| `storage.endpoint` / `region` / `bucket` / `accessKey` / `secretKey` / `pathStyle` | 只有勾了对象存储才读 |
| `storage.encrypted` + `passphrase` | 勾上就是 SSE-C，口令由 Argon2id 派生 KEK（≥12 字符），盐与校验值存 `app_state`。**KEK 一旦有对象落库就不可轮换** |
| `storage.masterKey` | 高级项，base64 的 32 字节，与 `passphrase` 二选一 |
| `admin.password` | 留空 = 管理台不开放（登录 403）。`admin.jwtKey` 不用填，服务端自动生成并回写 |
| `security.internalCidrs` | `/healthz` 与 `/actuator/**` 的额外放行网段，环回永远放行 |
| `port` | 默认 7404。要临时换端口也可以照旧传 `--server.port=8081`，命令行优先级高于这份文件 |

模板见 `infra/pushbox.json.example`；想指另一份文件用 `--pb.config-file=/path/to/pushbox.json`
（或 `-Dpb.config-file=…`，测试侧走的是这个系统属性）。

**明文是刻意的。** 生产部署一定要有可复核的凭据落点，而"只从环境变量读"换来的是一堆占位值和一个拒绝启动的
入口脚本——部署者仍然要把真值写在某个文件里（compose 的 `environment`、NAS 的表单），只是那个文件没人管权限。
所以判据从"配置里不许有明文"换成"**明文只在这一个地方，权限 600，且它进不了提交**"。

`infra/env/local.env` 还留在本机上当凭据备忘录，但**已经没有任何代码或脚本读它**——
WSL 那套测试栈读的是 `infra/wsl-test.env`，服务端与单测读的是上面那份 JSON。
`local.env.example` 与 `set-user-env.ps1` 已随旧模型一起删除。

### Gradle 依赖仓库

`apps/android/settings.gradle.kts` 默认只用官方源（`google()` / `mavenCentral()` / `gradlePluginPortal()`），
CI 与境外使用者都走这一份口径。在国内开发机上拉依赖慢的话，在 `apps/android/local.properties`（已 gitignore，
与签名配置同一个文件）加一行开镜像：

```properties
pb.maven.cnMirror=true
```

不要为了自己方便把镜像地址写回 `settings.gradle.kts` 的默认路径：2026-10-20 `build-apk.yml` 在 runner 上红
了一整轮，就是因为镜像排在 `pluginManagement` 最前面而 GitHub 的机器打它整片返 502，插件被报成"哪个仓库都
没有"——本机在墙内看不见这个 502，所以本地一直是绿的。

## 目录结构

```
apps/
  server/     Spring Boot 服务端：入站 API、设备与频道、WS 下发、抓取转存、搜索、治理接口
  web-admin/  Web 管理台（Vue 3 + Element Plus），构建产物打进服务端 jar 的 classpath:/static/
  android/    Android 客户端（Kotlin + Compose），Gradle 工程，:pbcore 直接编译 ../../packages/core 的同一份源码
  windows/    Windows 客户端（.NET 8 + WPF），独立解决方案；协议对齐由 contracts/testvectors/vectors.json 校验
packages/
  core/       Java 加密与协议库（X25519 / Ed25519 / AES-GCM 帧通道 / canonical 签名 / 帧 DTO / 测试向量）
infra/        探针、Dockerfile、compose、Caddyfile、自签 CA、备份脚本、Prometheus/Grafana
assets/       多端共用的图标与导出稿（Android 自适应图标、Web favicon、Play 商店图）
contracts/    跨端契约；testvectors/ 由 core 的单测产出，供 Windows 侧对字节，必须能检出与 diff
docs/         软件设计方案（唯一权威文档）、Windows 开发环境安装教程；docs/release/ 放发布清单与准备报告
site/         对外介绍的官网 + 文档站源码（零构建，index.html 是首页；线上地址 https://iamplusdev.github.io/push-box/）
scripts/      构建与发版脚本（release*.sh、set-version.sh、install-page-smoke.sh）
output/       各端编译产物（jar / apk / exe），不入库，由 release 脚本写入
```

`packages/core/` 与 `apps/server/` 是同一个 Maven reactor（根 `pom.xml` 聚合）；`apps/android/` 与 `apps/windows/` 各有独立的构建体系。三端**不是三份协议实现**：Java 与 Kotlin 共享同一份 `packages/core` 源码，C# 那一侧靠 `contracts/testvectors/vectors.json` 逐字节对账。

`vectors.json` 是**按 key 排序**写出的（`CryptoVectorsTest` 里显式开了 Jackson 的 `ORDER_MAP_ENTRIES_BY_KEYS`）。别去掉这一行：文件里那些嵌套块用 `Map.of()` 构造，它的迭代顺序 JDK 不保证、跨进程还会变，不排序就是"每次跑完 core 测试，向量文件换一套 key 顺序"——内容一模一样却报出满屏 diff，下一版真改了某个字节没人分得清。

## 编译与运行

### 1. 构建服务端

```bash
# 确保 JAVA_HOME 指向 JDK 21
JAVA_HOME=/path/to/jdk-21 mvn -B -DskipTests package

# 起服务端（监听 7404；第一次启动会停在安装页上，浏览器打开 http://127.0.0.1:7404/ 填完配置它自己接着启动）
bash infra/run-dev.sh
```

### 2. 构建 Android

```bash
cd apps/android
./gradlew :app:assembleDebug
```

APK 输出在 `apps/android/app/build/outputs/apk/debug/`。

### 3. 构建 Windows

```bash
cd apps/windows
dotnet build -c Release
```

可执行文件在 `apps/windows/PushBox.Windows/bin/Release/net8.0-windows/`。

### 4. 验收探针

```bash
node infra/probe/p0-e2e.mjs
```

探针会模拟一个"软件版 Android 设备"，逐字节复刻握手、签名、帧加密与补拉。判据是**末行 `N/N` 且 0 失败**，别把某个具体条数当判据（用例只许涨，但脚本里带序号的标签比 23 多）。

| 跑法 | 判什么 |

| `cd apps/web-admin && npm test` | 管理台排版断言（**11 条**，`node --test` 零依赖、只读源码、不构建不起服务）：六档字号与行高、Element 六档的指向、`.vue` 里不许有裸字号与裸行高、等宽字体族单一来源、页头只有 `PageHeader.vue`、对话框滚动层数、CSS 导入顺序。条数下限由 `ci.yml` 的 `WEB_BASELINE` 钉住——`node --test` 一条都没发现时同样退 0 |

## 开发工作流

### 改协议字段

改了协议字段要**三处同步**：

1. `packages/core/src/main/java/dev/pushbox/core/protocol/Frames.java`
2. `apps/android/app/src/main/java/cn/iamplus/pushbox/net/Wire.kt`
3. `infra/probe/p0-e2e.mjs`

漏改会被探针判红，这是好事。

### 调试服务端

服务端日志用 `%pbmsg`/`pbex` 转换器兜底，`application.yml` 刻意不写 `logging.pattern.*`。**正文不进日志**是设计如此。

启动时加 `--debug` 可看更详细的 WS 握手过程。

### 调试 Android

Android 使用 Compose，建议在 Android Studio 中打开 `apps/android/` 目录。`:pbcore` 模块直接引用 `../../packages/core`，改 Java 代码后重新 `:app:assembleDebug` 即可。

### 调试 Windows

Windows 使用 WPF，建议在 Rider 或 Visual Studio 中打开 `apps/windows/PushBox.sln`。`PushBox.LiveCheck` 项目用于真服务端体检，跑在自起的 8081 端口上。

## 常见坑

### JDK 版本

机器默认 `JAVA_HOME` 常是 JDK 8，必须显式覆盖到 jdk-21，否则报成片乱码语法错。

### 端口占用

用户自己手动起的那个实例占 7404；代理与真服务体检另起 8081，跑完只杀自己叫起来的 PID。

### 路径大小写

NTFS 大小写不敏感但会记住工具写进去的新大小写，写错就等于悄悄改名。编辑文件时注意照磁盘原样。

### 证书校验

绝不绕过证书校验。找不到 `ServerCertificateCustomValidationCallback`、`DangerousAcceptAnyServerCertificate`、`ServicePointManager` 的钩子是设计如此，不是遗漏。自签场景只有一种接法：把 CA 装进信任根。

## 发布流程

三条发布链互相独立：服务端、Android、Windows 各有自己的版本号与标签前缀（`server-v*` / `android-v*` /
`windows-v*`），**只改一端就只打那一端的标签**，另外两条流水线不会被触发；旧的 `v*` 标签仍然保留，
一次发三端（旧标签只带一个号，所以三端版本号都得先写成这个 `X.Y.Z`）。打标签才会发版：服务端推 Docker
镜像，两端发布 GitHub Release（那份 Release 就是「检查更新 / 启动时自动检查更新」读取的更新源）——版本号
抬了没打标签，应用内是查不到的。

### 通用步骤

1. 写版本号，只动这一端：
   ```bash
   bash scripts/set-version.sh --only=server 1.2.0    # pom / web-admin / 两份 compose / site 徽章
   bash scripts/set-version.sh --only=android 1.2.0   # versionName + versionCode
   bash scripts/set-version.sh --only=windows 1.2.0   # csproj + Inno
   ```
   三端一起发时去掉 `--only=…`。脚本只接受严格 `X.Y.Z`，`versionCode = major*10000 + minor*100 + patch`
   且必须大于上一版；解析不出就报错退出、不改任何文件。
2. 提交改动，跑 `bash scripts/release-verify.sh` 到零 FAIL（它按端检查各自的版本自洽，不要求三端同号）。
3. 打对应标签并推送：
   ```bash
   git tag server-v1.2.0   && git push origin server-v1.2.0
   git tag android-v1.2.0  && git push origin android-v1.2.0
   git tag windows-v1.2.0  && git push origin windows-v1.2.0
   ```
   三端一起发才用 `v1.2.0`（三个 workflow 都认这个旧前缀）。客户端 tag 里的版本建议与 `versionName` /
   `<Version>` 相同；服务端 tag **必须**与 `pom.xml` 相同，否则版本闸门会在构建前拦红。

### 各端本地构建（不经过 CI）

1. 服务端：`mvn -B package -DskipTests`，打 Docker 镜像或直接部署 jar。
2. Android：`./gradlew :app:assembleRelease`，用正式 keystore 签名。
3. Windows：`dotnet publish -c Release -r win-x64 --self-contained`，再用 Inno Setup 打包安装包。

### 客户端更新检查的取数方式

分端发布后每个平台各占一个 Release，所以两端读的是 `releases?per_page=30` 列表，按资产名
（`pushbox-release-*.apk` / `PushBox-Setup-*-win-x64.exe`）挑出自己那条，再从 tag 里去掉
`android-v` / `windows-v` / `v` 前缀得到版本号。**不要改回 `/releases/latest`**：那个接口只返回最后发的
那个 Release，另一平台会读到别人的 tag 或看不到自己的新版本，而且不会报错。
