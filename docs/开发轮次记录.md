## v1.27（2026-10-18）—— PC端应用层心跳看护机制

### 新增
- **Windows**：`PushConnection.HeartbeatSenderAsync()` — 按 hello 下发的 `heartbeat_sec` 主动发送 ping 帧，解决 TCP 半开场景下"顶栏显示已连接但消息不再来"的问题；与 Android 的 `keepAlive` 对齐的是**出站节奏**，判死仍然只有 `QuietWatchdogAsync` 一处（heartbeat+15s 无息），不再叠加第二个"2 个周期"的截止线 ([PushConnection.cs:348](file:///D:/Projects/Android/PushBox/windows/PushBox.Windows/Sync/PushConnection.cs#L348))
- **Windows**：`Wire.Ping()` — 补充缺失的ping帧构造方法 ([Wire.cs:30](file:///D:/Projects/Android/PushBox/windows/PushBox.Windows/Net/Wire.cs#L30))
- **Windows 测试**：`PushConnectionTest.TheClientSpeaksOnTheHeartbeatTheServerAskedFor` — 服务端 hello 说 1 秒，本机就必须在那条连接上真的发出 `{"t":"ping"}`（这条抓到了"起跑时按默认 25s 睡整觉"那个自伤缺陷）

### 修改
- `PushConnection.ConnectAndReadAsync()` — 同时启动看门狗和心跳发送器，读循环退出后用 `Task.WhenAll` 收拢两者
- **Windows**：`PushConnection._sendGate`（`SemaphoreSlim(1,1)`）成为唯一出站入口。`ClientWebSocket` 一条 socket 同时只能有一个 `SendAsync` 在飞，心跳任务与"收到 ping 回 pong"分属两条线程，少了这道门一次相位撞上的 ping/pong 会让整条同步循环带异常收工而不是重连
- **Windows**：心跳起跑时 hello 还没到，间隔按 1 秒一小段滚动重读，避免整条连接被钉在默认 25 秒节奏上；发送失败只静默退出，不向 `Task.WhenAll` 抛

### 验证
- `dotnet build -c Release` 通过（0警告0错误）
- `dotnet test PushBox.Crypto.Tests`（`PushConnectionTest|SyncEngineTest`）49/49
- 核心逻辑与 Android SyncEngine.keepAlive 对齐的是**主动ping + inbound超时检测 + 带since_seq补拉**这三件事；**判死阈值两端不同**：Android 是 `interval × STALE_HEARTBEATS(2)`（默认 50s），PC 沿用 §5.3 的 `heartbeat + 15s`（默认 40s），PC 比 Android 更快认输、补拉也更早，这一条差异是刻意的（协议文档写的就是 40s）
- 断线判死的运行时验证留待用户实机（xunit 只锁协议行为，拔网线那一条走 `PushBox.LiveCheck`）
