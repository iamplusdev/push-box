# PushBox 字体规范

本文档定义三端统一的字体层级系统、字号基准、行高比例与字体族选择，确保中英文混排的可读性与视觉一致性。

## 设计原则

1. **基准字号 15sp/px**：正文使用 15 单位字号，这是移动端与桌面端都能舒适阅读的最小值
2. **行高 1.53×**：正文行高 23 ÷ 15 ≈ 1.53，符合中文排版的黄金比例（1.5–1.6）
3. **四档标题**：H1=20, H2=18, H3=16, H4+=15，每级差 2pt，避免跳跃过大
4. **等宽字体只用于代码与标识符**：日志、命令、token、恢复码、设备 ID / 频道号 / cron 表达式必须用等宽字体，其余正文禁用（中文名用等宽会很难看）
5. **中英混排优先**：西文字体选无衬线体，中文字体选微软雅黑/思源黑体，不单独指定英文字体

## 字体层级表

| 用途 | 字号 | 行高 | 字重 | 示例场景 |
|------|------|------|------|----------|
| **H1** | 20 | 28 | Bold | 页面大标题、空状态主文案 |
| **H2** | 18 | 25 | Bold | 设置页分组标题、频道治理标题 |
| **H3** | 16 | 22 | Medium/SemiBold | 会话名称、次级标题 |
| **Body** | 15 | 23 | Normal | 消息正文、说明文字 |
| **Small** | 13 | 18 | Normal | 摘要、辅助说明、列表项副文本 |
| **Label** | 12 | 16 | Normal/Medium | 时间戳、角标、提示文字、按钮小字 |
| **Code** | 13 | 18 | Normal (Monospace) | 代码块、恢复码、设备 ID、curl 命令 |

### 字号使用规则

- **禁止出现 14sp/px**：要么 13（Small），要么 15（Body），14 是尴尬的中间态
- **时间戳统一 12sp**：会话行的右侧时间、消息气泡内的时间都必须是 12
- **摘要/副文本统一 13sp**：比正文小一档，但比标签大一档
- **标题只分四档**：不要为每个业务场景发明新字号，套用 H1–H4

## 字体族选择

### Android

```kotlin
// UI 文本：系统默认（Roboto + Noto Sans CJK）
FontFamily.Default

// 代码/等宽：系统默认等宽
FontFamily.Monospace
```

**理由**：Android 系统字体已针对屏幕渲染优化，无需额外指定。Material Design 推荐使用系统默认。

### Windows

```csharp
// UI 文本：Segoe UI（西文）+ Microsoft YaHei UI（中文）
new FontFamily("Segoe UI, Microsoft YaHei UI")

// 代码/等宽：Consolas（西文）+ Microsoft YaHei UI（中文注释）
new FontFamily("Consolas, Microsoft YaHei UI")
```

**理由**：
- Segoe UI 是 Windows 原生 UI 字体，ClearType 渲染最佳
- YaHei UI 是专为屏幕优化的中文版型，比传统 YaHei 更清晰
- Consolas 是等宽字体中的经典，适合代码与 token 显示

### Web（管理台）

```css
/* UI 文本：--pb-font-ui */
font-family: -apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, "Helvetica Neue",
  "Microsoft YaHei UI", "Microsoft YaHei", Arial, sans-serif;

/* 代码/标识符：--pb-font-mono */
font-family: ui-monospace, "SFMono-Regular", "SF Mono", Menlo, Consolas,
  "Microsoft YaHei UI", "Microsoft YaHei", monospace;
```

**理由**：西文优先用系统 UI 字体（Windows 落到 Segoe UI、macOS 落到 SF），中文回退到 YaHei UI；等宽栈里也带中文字体，`cron 表达式 · 说明` 这类混排才不会一半换字形。

## 行高与间距

### 行高公式

```
行高 = 字号 × 1.53（向上取整到偶数）
```

| 字号 | 计算值 | 实际采用 | 原因 |
|------|--------|----------|------|
| 20 | 30.6 | 28 | H1 紧凑些更好看 |
| 18 | 27.5 | 25 | H2 同上 |
| 16 | 24.5 | 22 | H3/会话名 |
| 15 | 23.0 | 23 | Body 严格遵循 |
| 13 | 19.9 | 18 | Small 略收紧 |
| 12 | 18.4 | 16 | Label 更紧凑 |

### 段落间距

- **块级元素之间**：4px（`BlockGap = 4`）
- **列表项之间**：2px（`ListGap = 2`）
- **引用块缩进**：8px（`QuoteIndent = 8`）
- **代码块内边距**：8px（`CodePadding = 8`）

## 平台实现

### Android (Theme.kt)

`PushBoxTypography` 把 Material3 的 **15 个槽位全部写掉**。不写的槽位会落回基线值，而基线的 `headlineSmall` 是 24sp、`titleSmall` 与 `labelLarge` 是 14sp——24 与 14 都不在六档里，编译期不报、预览也不一定看得出来：

| 槽位 | 字号/行高 | 用途 |
|------|-----------|------|
| `displayLarge/Medium/Small`、`headlineLarge` | 20/28 | 规范里没有 display 层级，统一压到 H1 |
| `headlineMedium` | 18/25 | H2 |
| `headlineSmall`、`titleLarge`、`titleMedium` | 16/22 | H3 / 会话名 |
| `titleSmall` | 15/23 | 可点标题 |
| `bodyLarge` | 15/23 | 正文 |
| `bodyMedium`、`bodySmall` | 13/18 | 摘要、副文本 |
| `labelLarge` | 13/18 | 按钮（12sp 的中文按钮笔画会糊） |
| `labelMedium`、`labelSmall` | 12/16 | 时间戳、角标、提示；这一档**不写颜色**，由调用方给 |

**Markdown 标题映射**（`MainActivity.kt`）走的就是本表那三支槽位，不再写裸字号：

```kotlin
val base = when (block.level) {
    1 -> MaterialTheme.typography.headlineLarge   // 20/28
    2 -> MaterialTheme.typography.headlineMedium  // 18/25
    3 -> MaterialTheme.typography.headlineSmall   // 16/22
    else -> MaterialTheme.typography.bodyLarge    // 15/23
}
```

### Windows (MarkdownStyle 常量 + Tokens.xaml 样式)

字号与行高只在 `Controls/MarkdownView.cs` 的 `MarkdownStyle` 上写一份，XAML 与代码都引它：

```csharp
public const double H1Size = 20;
public const double H1Line = 28;
public const double H2Size = 18;
public const double H2Line = 25;
public const double H3Size = 16;
public const double H3Line = 22;
public const double BodySize = 15;
public const double BodyLine = 23;
public const double SmallSize = 13;
public const double SmallLine = 18;
public const double LabelSize = 12;
public const double LabelLine = 16;
```

`Themes/Tokens.xaml` 与 `Tokens.Dark.xaml` 各有一套 `Text.H1/H2/H3/Body/Small/Label/Code` 样式，字号、行高、字体族全在样式里；窗口只需 `FontFamily="{DynamicResource Font.UI}"`（等宽是 `Font.Code`）：

```xml
<!-- Themes/Tokens.xaml -->
<Style x:Key="Text.Body" TargetType="TextBlock">
  <Setter Property="FontSize" Value="{x:Static controls:MarkdownStyle.BodySize}" />
  <Setter Property="LineHeight" Value="{x:Static controls:MarkdownStyle.BodyLine}" />
  <Setter Property="FontFamily" Value="{StaticResource Font.UI}" />
</Style>

<!-- 窗口/控件 -->
<TextBlock Style="{DynamicResource Text.Body}" Text="..." />
```

> `{x:Static}` 取的是 C# 常量的**值**，BAML 加载时不走资源查找；`{DynamicResource}` 指向不存在的键不会抛，只会静默落回默认值——所以键名由 `TypographyTest` 借 `ThemeTest.TokenFiles` 读这两本字典逐条断言，而不是靠眼睛。

### Web (Element Plus 覆盖)

`src/styles/typography.css` 是管理台唯一的排版层，必须在 `element-plus/dist/index.css` **之后**引入——两边都在 `:root` 上写自定义属性，同权重时后写的赢：

```css
:root {
  /* 六档字号与行高：与两端同一张表 */
  --pb-font-h1: 20px;    --pb-line-h1: 28px;
  --pb-font-h2: 18px;    --pb-line-h2: 25px;
  --pb-font-h3: 16px;    --pb-line-h3: 22px;
  --pb-font-body: 15px;  --pb-line-body: 23px;
  --pb-font-small: 13px; --pb-line-small: 18px;
  --pb-font-label: 12px; --pb-line-label: 16px;

  /* Element 的六档指过来：base 的 14 抬到 15（14 不在表里）。
     字体族是上一节那两条栈，落在 --pb-font-ui / --pb-font-mono 上 */
  --el-font-family: var(--pb-font-ui);
  --el-font-size-base: var(--pb-font-body);
  --el-font-size-small: var(--pb-font-small);
  --el-font-size-extra-small: var(--pb-font-label);

  /* #909399 在白底上只有 2.9:1，12 号副文本几乎糊掉 */
  --el-text-color-secondary: #5f5f5f;
}
```

页面的字号与文字色只写 `var(--pb-font-*)` / `var(--el-text-color-*)`，不再出现裸字号；设备 ID、频道号等标识符加 `.pb-mono`（等宽 + `tabular-nums`），方便逐字符核对。表格统一 13px 正文 + 600 表头 + 11px 上下内边距（实测行高 44px），表格内的按钮跟随行字号。

三个配套细节，都是踩过才知道的：

- **`.pb-mono` 要连内部控件一起写**：`el-input` / `el-textarea` 的字在自己的 `input`、`textarea` 上，不继承外层容器的 `font-family`，所以规则里带一条 `.pb-mono input, .pb-mono textarea`。频道详情那个只读的频道号框靠它才是等宽。
- **页面标题只有一个来源**：内页页头一律走 `components/PageHeader.vue`（`title` + 可选 `description` + `#actions` 插槽），标题 `--pb-font-h1`（20/28）字重 600、说明 `--pb-font-small`（13/18）配 `--el-text-color-secondary`。视图里不再自己写 `.page-header h2`——六个页面各抄一遍的结果是标题只有 18px，和 13px 的表格正文只差 5px，页面上找不到"这是哪一页"的落点。
- **长文列用 `.pb-clamp2` 而不是 `show-overflow-tooltip`**：Element 那个属性只支持单行截断，长正文一行之后能看到的只剩开头十来个字。`.pb-clamp2`（`-webkit-line-clamp: 2`）配原生 `title` 属性兜住全文，行高从 44px 涨到 59px，仍然是一屏能扫的密度。名称、分类这类短列保留单行 tooltip。

## 常见错误

### ❌ 错误 1：硬编码字号

```xml
<!-- Windows XAML -->
<TextBlock FontSize="14" Text="..." />  <!-- 14 是不存在的字号 -->
```

**修复**：
```xml
<TextBlock FontSize="{x:Static controls:MarkdownStyle.SmallSize}" Text="..." />
```

### ❌ 错误 2：行高缺失

```kotlin
// Android Compose
Text("...", fontSize = 15.sp)  // 缺 lineHeight，会用 Material 默认 1.4×
```

**修复**：
```kotlin
Text("...", fontSize = 15.sp, lineHeight = 23.sp)
```

### ❌ 错误 3：等宽字体滥用

```xml
<TextBlock FontFamily="Consolas" Text="用户名：张三" />  <!-- 中文名用等宽会很难看 -->
```

**修复**：
```xml
<TextBlock FontFamily="Segoe UI, Microsoft YaHei UI" Text="用户名：张三" />
```

### ❌ 错误 4：字号层级混乱

```
页面标题 18sp
会话名 17sp    ← 17 是非法字号
摘要 14sp      ← 14 是非法字号
时间 11sp      ← 太小，看不清
```

**修复**：
```
页面标题 18sp (H2)
会话名 16sp (H3)
摘要 13sp (Small)
时间 12sp (Label)
```

## 验收清单

在 PR 中检查以下项：

- [ ] 所有字号来自 {12, 13, 15, 16, 18, 20}，无 11/14/17 等非法值
- [ ] 正文行高 ≥ 23sp（15 × 1.53）
- [ ] 代码/恢复码/token 使用等宽字体
- [ ] 中文文本不使用等宽字体
- [ ] Windows XAML 引用 `MarkdownStyle.*` 而非硬编码数字
- [ ] Android Compose 显式指定 `lineHeight`
- [ ] 标题级别不超过 4 档（H1–H4）

### 机器把关

人眼只看结论，下面三条是把结论钉住的闸：

| 端 | 闸 | 断的是什么 |
|----|----|-----------|
| Android | `app/src/test/.../ui/TypographyTest.kt` | 15 个槽位逐一比字号与行高；**新增槽位要同时加进 `all`**，否则等于没有闸 |
| Windows | `PushBox.Crypto.Tests/TypographyTest.cs` | 两本字典的 `Text.*` 逐条比表；XAML/C# 里不许出现数字 `FontSize`；四个窗口的字体族必须走 `Font.UI`；聊天标题走同一张表；更新确认框在 STA 线程上真构造一次 |
| Web | 无单测（CSS 不在断言范围） | 靠 `npm run build` + 真浏览器 `getComputedStyle` 抽查；改 `typography.css` 后至少要量 body、表格、页头三处，动过 `.pb-mono` / `.pb-clamp2` 再各量一处（等宽看 `font-variant-numeric` 是不是 `tabular-nums`，截断看渲染高是不是 `scrollHeight` 的一小截）。起法：本机 mock 管理台 API 挂 8081，`PB_ADMIN_API=http://127.0.0.1:8081 npm run dev` 起 7403 |

Android 与 Windows 的闸都只认"表里那六个字号"，所以往画面里加一个新字号，最先红的不是眼睛，是 CI。
