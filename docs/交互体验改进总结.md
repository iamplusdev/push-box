# PushBox 交互体验改进总结

**日期**：2026-10-18
**范围**：Android 与 Windows 两端
**主题**：从初始化到日常使用这条链路上的用户体验优化

---

## 总览

本文记录两端（Android 与 Windows）上成体系落地的交互体验改进，目标有三件：解决"入口找不到、下一步不知道点哪"的可发现性问题，降低新用户第一次使用的困惑，收敛首次上手的引导。改动按优先级与影响面分档。

---

## 优先级 1：空列表引导（✅ 已完成）

### 问题
首次进入时会话列表是空的，界面不给任何下一步提示，用户不知道要先建频道才能收消息，于是卡在这一屏直接流失。

### 做法

#### Android（`MainActivity.kt` 651–670 行）
**改前：**
```kotlin
Text(stringResource(R.string.empty_conversations),
    Modifier.fillMaxWidth().padding(24.dp), textAlign = TextAlign.Center,
    style = MaterialTheme.typography.bodyMedium)
```

**改后：**
```kotlin
Column(Modifier.fillMaxWidth().padding(24.dp),
    horizontalAlignment = Alignment.CenterHorizontally) {
    Icon(Icons.Default.Hub, contentDescription = null,
        modifier = Modifier.size(64.dp), tint = MaterialTheme.colorScheme.onSurfaceVariant)
    Spacer(Modifier.height(16.dp))
    Text(stringResource(R.string.empty_conversations),
        style = MaterialTheme.typography.titleMedium,
        color = MaterialTheme.colorScheme.onSurface)
    Spacer(Modifier.height(8.dp))

        style = MaterialTheme.typography.bodySmall,
        color = MaterialTheme.colorScheme.onSurfaceVariant,

    OutlinedButton(onClick = { onNavigateToMine?.invoke() }) {

```

**效果：**
- 图标先抓住注意力，标题 / 说明 / 按钮三层分明
- 文案直接写出该走哪条路径
- 多了一个直达按钮，操作从 3 次点击降到 1 次
- 新增标签页跳转回调（`onNavigateToMine`）

## 优先级 2：危险操作的语义色（✅ 已完成）

### 问题
删除、清空、归档这类不可逆操作，在界面上没有统一的视觉警示，点错一步就可能丢数据。

### 做法

#### 颜色令牌定义
沿用设计系统里已有的取值：
- **警示**：`#FF8C00`（浅色）/ `#FFB74D`（深色），橙黄
- **错误**：`#F5222D`（浅色）/ `#FF5252`（深色），红

#### Windows（`SettingsWindow.xaml`）
四个危险按钮统一套红色错误样式：
1. **「清空」**（清空频道）——287–290 行
2. **「取消接入」**（退出频道）——289–292 行
3. **「归档」**——291–294 行
4. **「吊销这台」**（吊销设备）——368–371 行

写法：
```xml
<Button Content="清空" Margin="10,0,0,0" Click="OnClearChannel"
        Background="Transparent" BorderBrush="{DynamicResource Level.Error}"
        Foreground="{DynamicResource Level.Error}" />
```

#### Android（`MainActivity.kt`）
四个关键操作改用错误色：

1. **删除会话对话框**（1037–1041 行）：
```kotlin
TextButton(onClick = { confirmDelete = false; onDismiss(); onDelete() },
    colors = ButtonDefaults.textButtonColors(
        contentColor = MaterialTheme.colorScheme.error
    )) {
    Text(stringResource(R.string.confirm_ok))
}
```

2. **频道归档对话框**（1631–1645 行）
3. **频道清空对话框**（1686–1698 行）
4. **频道管理按钮**（2048–2058 行）：
```kotlin
OutlinedButton(enabled = !busy, onClick = onClear,
    colors = ButtonDefaults.outlinedButtonColors(
        contentColor = MaterialTheme.colorScheme.error
    )) {
    Text(stringResource(R.string.channel_clear))
}
```

**新增导入**：`androidx.compose.material3.ButtonDefaults`

**效果：**
- 两端视觉口径一致
- 颜色本身就成了警示，误触带来的破坏性操作变少
- 与 Material Design 3 和 Fluent Design 的规范一致

## 优先级 3：尽力而为型操作的失败反馈（✅ 部分完成）

### 问题
后台同步类操作（清空会话、上报已读）失败时没有任何提示，用户不知道"这台清了、别的设备上还在"这种情况。

### 做法

#### Android（`MainActivity.kt` 708–728 行）
**改前：**
```kotlin
onClear = {
    scope.launch(Dispatchers.IO) {
        app.dao.conversationMedia(menuRow.channelNo, menuRow.senderId)
            .forEach { ImageCache.evictMessage(it.msgId, it.mediaCount) }
        app.dao.clearConversation(menuRow.channelNo, menuRow.senderId)
        runCatching {
            PushBoxApi(identity.baseUrl, app.http)
                .clearConversation(identity, menuRow.channelNo, menuRow.senderId)
        }
    }
}
```

**改后：**
```kotlin
onClear = {
    val contextForToast = app.applicationContext
    scope.launch(Dispatchers.IO) {
        app.dao.conversationMedia(menuRow.channelNo, menuRow.senderId)
            .forEach { ImageCache.evictMessage(it.msgId, it.mediaCount) }
        app.dao.clearConversation(menuRow.channelNo, menuRow.senderId)
        val result = runCatching {
            PushBoxApi(identity.baseUrl, app.http)
                .clearConversation(identity, menuRow.channelNo, menuRow.senderId)
        }
        result.onFailure {
            android.os.Handler(android.os.Looper.getMainLooper()).post {
                android.widget.Toast.makeText(contextForToast,
                    "本地已清空，但同步到其他设备失败：${it.message}",
                    android.widget.Toast.LENGTH_LONG).show()
            }
        }
    }
}
```

**设计取舍：**
- 本地操作永远先成功、不阻塞界面
- 服务端同步失败只弹一个非阻塞 Toast
- 文案把"本地已清空"与"远端同步失败"分开讲清楚
- 后台协程里弹 Toast 要回到主线程 Handler

**有意不改的：**
- 已读上报失败仍然静默（后台同步，弹出来只是噪音）
- 其余尽力而为型操作按同一原则处理：加反馈只在用户能据此做点什么的时候才加

**效果：**
- 多设备同步失败时用户知情
- 主流程不被打断（本地清空照常生效）
- 把系统边界如实说出来，比假装没发生更能建立信任

## 剩余高优先级事项（后续工作）

### RI-1：首次使用引导向导
**状态**：未开始
**问题**：用户分不清 Space / 频道 / 会话这三层的关系
**方案**：注册完成后走一个三步向导，讲清概念并引导建第一个频道
**预估工作量**：2–3 天

### RI-2：统一的频道管理入口
**状态**：未开始
**问题**：建频道藏得太深（Android：我的 → 接入；Windows：设置 → 频道）
**方案**：
- Android：消息页加悬浮按钮（FAB）
- Windows：顶部工具栏加一个按钮
**预估工作量**：1 天

### RI-3：频道治理项的渐进披露
**状态**：未开始
**问题**：12 个以上的治理字段一屏摆出来，普通用户会懵
**方案**：拆成「基础 / 高级」两段，高级段默认折叠
**预估工作量**：0.5 天

### P0-1：恢复码警示加强
**状态**：未开始
**问题**：用户可能不理解恢复码的重要性，等看到它时已经来不及
**方案**：展示恢复码之前，先弹一层"这是唯一一次"的确认框
**预估工作量**：0.5 天

## 应用的设计原则

1. **渐进披露**：先给必要信息，高级选项按需展开
2. **可供性**：可点的东西要和静态内容有视觉区别
3. **反馈**：任何操作的结果都要告诉用户，失败更要说
4. **一致性**：同一语义在两端含义相同（红 = 危险）
5. **可挽回**：不可逆操作要么能撤销，要么执行前明确警示

## 附录：各端实现细节

### Android 对 Material Design 3 的遵循
- 语义色一律取 `MaterialTheme.colorScheme.error`
- 间距走 8dp 栅格（8 / 16 / 24dp）
- 字号层级：标题用 `titleMedium`，说明用 `bodySmall`
- 按钮变体：次要操作用 `OutlinedButton`，对话框里用 `TextButton`

### Windows 对 Fluent Design 的遵循
- 主题感知的颜色一律用 `{DynamicResource}` 取
- 维持 8px 间距体系（与 Android 一致）
- Path 插图贴合 Fluent 图标风格（简单几何形状）
- 按钮样式走 WinUI 3 的写法（透明底 + 强调色描边）
