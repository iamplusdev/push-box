入站 API（写入）

入站 API：发一条消息

入站只有一个写入口：POST {base}/message。凭据是频道号加频道密钥，写在请求体里。

端点

POST   {base}/message

  • 路径是 /message，不在 /api/v1 下。
  • 前缀由 pb.ingest.base-path 决定，默认 /message。
  • 只有这一个写入口：图片走同一端点的 images[] 字段。
  • 请求头只需要 Content-Type: application/json。
  • 凭据只放 body，不要放 URL 或 header。

健康检查

GET   {base}/healthz

  1. 敲一次 
    curl -sS http://127.0.0.1:7404/healthz
    期望 200；库或存储任一项不通回 503。 
{
  "ok": true,
  "db": "up",
  "storage": "up",
  "uptime_ms": 123456
}
  • 它会真的对库做一次连通探测（2 秒超时），本地存储时还会往目录里写一个探测文件。
  • 所以把它当就绪探针，别当存活探针。
  • 无 token，但默认只放行环回来源；其它网段要在安装页的「运维网段」里写成 CIDR（配置文件里的 security.internalCidrs），不在白名单里直接回 404。
  • 响应只有上面这四个键。

凭据：从哪来、怎么换

凭据从哪来怎么轮换
channel8 位频道号，客户端「频道 → 新建」时分配POST /api/v1/channels/{no}/reset-channel-no 换发新号
secret创建频道那一次回显，只显示一次客户端「频道 → 重置密钥」，或 POST /api/v1/channels/{no}/rotate-secret
  • 忘了密钥没有查看入口，只能重置；重置后旧密钥即刻作废。
  • 拿到这两个值只能往这个频道写，读不到任何历史。
  • 读侧接口见 客户端 API，那是另一套鉴权。

发一条：三步

  1. 把凭据与正文写进 payload.json 
    {
  "channel": "12345678",
  "secret": "<频道密钥>",
  "type": "markdown",
  "level": "error",
  "sender_id": "grafana",
  "sender_name": "Grafana 告警",
  "title": "CPU 使用率超过 90%",
  "content": "主机 prod-03 · 近 5 分钟均值 92.4%"
}
  2. 发出去 
    curl -sS http://127.0.0.1:7404/message \
  -H 'Content-Type: application/json' \
  --data-binary @payload.json
    别用 -d 内联 JSON：Git Bash 会改动引号里的内容，服务端只会回「请求体必须是合法 JSON」。
  3. 看回的那一行 200 表示已入库并排进下发；401 是频道号或密钥不对；429 是超过了限速。

请求体字段

字段类型必填说明
channelstring必填频道号，8 位数字
secretstring必填频道密钥
contentstring必填正文，上限 32768 字节
typestring可选text（默认）/ markdown / link / file
levelstring可选info（默认）/ warning / error
sender_idstring可选会话归属，截断 64 字符
sender_namestring可选显示名，截断 64 字符
sender_avatarstring可选头像外链，由服务端抓回
titlestring可选标题，截断 512 字符
urlstring可选客户端「打开链接」按钮的目标
images[]string[]可选图片外链数组，默认最多 4 条，见图片
msg_keystring可选幂等键，截断 64 字符，见幂等
tsnumber可选业务时间，秒或毫秒都收，见时间戳
noncestring条件频道开了 strict_auth 时必填，见签名
signstring条件
  • content 超限直接回 413，不会被静默截断后收下。
  • 频道可以把 32768 这个上限下调。
  • type 里出现未知值时降级为 text，不拒绝整条消息。
  • level 会被频道的 max_level 向下截断，响应回显的是生效值。
  • sender_id 决定这条消息落进哪个会话；省略或空归到 unknown，也就是同一个会话。
  • sender_id 可以含中文与 /，它不进 URL。
  • 同一 sender_id 的 sender_name 后续可以改，客户端看到的是最新那份。
  • 头像抓取失败不拦消息，只是这条不带头像。
  • images[] 单条 URL ≤1024 字符，只允许 http/https；data: 内联图不支持。

未知字段会被忽略，不报错

拼错字段名不会有任何提示。「我明明传了 sendername 为什么没显示名字」这类问题先核对拼写。

响应

受理成功一律回 200，不是 201；幂等重放也是 200。含义是「正文与抓取任务已入库」，不代表任何一台设备已收到。

{
  "ok": true,
  "id": "01J8ZK3Q7M2XW4V9HTNBSFY6PA",
  "seq": 1042,
  "summary": "CPU 使用率超过 90%",
  "media_status": "pending",
  "media_count": 2,
  "level": "warning"
}
  • id：ULID，可用它取全文（GET /api/v1/messages/{id}，读取要设备签名）。
  • seq：Space 内单调递增的水位号。
  • summary：服务端生成的摘要，标题优先；上限 pb.notify.summary-chars，默认 60 字符。
  • media_status：无图为 none，有图在受理瞬间为 pending。
  • media_count：图片槽位数；头像不占槽位。
  • level：max_level 截断后的实际生效值。
  • 幂等重放命中历史记录时，回的是那条原始记录的 id / seq / summary。

失败时形状固定，三个键恒在：

{
  "ok": false,
  "error": "invalid_credential",
  "hint": ""
}
  • hint 永远是字符串；没有提示时是空串，不是 null。
  • 429 另外带一个 Retry-After 响应头。
  • 任何错误都不会回显你提交过的字段值。

错误码

HTTPerror什么时候该怎么做
400invalid_paramchannel/secret 缺失、content 空、图片超条数或非 http(s)、请求体不是合法 JSON修脚本，重试没有意义
401invalid_credential频道不存在与密钥错是同一句话核对频道号与密钥；连错 5 次会触发锁定
403channel_locked凭据错误达到阈值（默认 5 次 / 5 分钟窗口，锁 5 分钟），或频道已归档等窗口过去；归档的频道不会再开
403forbidden频道开了「只允许白名单发送者」，这个 sender_id 不在名单里去客户端频道 →「发送者白名单」加进去
413too_largecontent 超过频道 max_body_bytes正文自己裁，或调频道上限
429rate_limited来源 IP / 频道 / 日配额任一超限；hint 是可重试秒数按 hint 退避；日配额只能等次日
400clock_skewstrict_auth 频道没给 ts，或 ts 越出 ±300s校时；非 strict 频道不会遇到
400replaystrict_auth 下 nonce 10 分钟内重复每次请求生成新 nonce
500—服务端异常响应不带 stacktrace 与 message，看服务端脱敏日志

幂等：msg_key

同一频道内相同 msg_key 重复提交，服务端直接返回原结果：不重复入库、不重复通知、不重复抓图。

{
  "channel": "12345678",
  "secret": "<频道密钥>",
  "content": "node-3 CPU 持续 > 90%",
  "msg_key": "HighCPU-node-3"
}
  • 会重试的投递方都该带上它：Alertmanager、队列消费者、CI runner。
  • Alertmanager 可以用告警 fingerprint 当键：重启或 resend 风暴不会刷屏。
  • 不带 msg_key 就是「至多一次入库」：超时后你自己重试，很可能落两条。

时间戳 ts

  • 省略或 ≤0：用服务端接收时间。
  • 秒或毫秒都收，< 1e11 视为秒并自动乘 1000。
  • 越出 ±300s 的一律回落到服务端时间。
  • 所以 ts 只适合表达「事件在这 5 分钟内的哪一刻」，不适合回填历史。
  • 要回填历史：省略 ts，把真实时间写进正文。

strict_auth：可选的请求签名

默认关闭，频道密钥本身已经是能写的凭据。开启后（频道治理 →「强制校验 sender」），ts/nonce/sign 三件套必须同时给。

canonical = channel + "\n" + ts + "\n" + nonce + "\n" + sha256_hex(content)
sign      = hex( HMAC-SHA256( key = secret, data = canonical ) )
  • sha256_hex(content) 是正文 UTF-8 字节的小写十六进制 sha256。
  • ts 必须存在且在 ±300s 内。
  • nonce 10 分钟内不得重复。
  • 签名不匹配回 401 invalid_credential，与密钥错同一句话。
import hashlib, hmac, json, time, urllib.request, uuid

secret, channel = "<频道密钥>", "12345678"
content = "构建失败：unit-test 3 个用例不过"
ts, nonce = int(time.time() * 1000), uuid.uuid4().hex

canonical = "\n".join([channel, str(ts), nonce,
                       hashlib.sha256(content.encode()).hexdigest()])
sign = hmac.new(secret.encode(), canonical.encode(), hashlib.sha256).hexdigest()

body = json.dumps({"channel": channel, "secret": secret, "content": content,
                   "type": "text", "level": "error", "sender_id": "ci",
                   "ts": ts, "nonce": nonce, "sign": sign}).encode()
req = urllib.request.Request("https://pushbox.internal/message", body,
                             {"Content-Type": "application/json"})
print(urllib.request.urlopen(req).read().decode())

图片：images[] 与 sender_avatar

两个字段传的都是外链，图片本体由服务端抓回来转存。

入站校验

规则默认可调配
条数上限4pb.media.max-images + 频道 max_images
单条 URL 长度1024 字符硬编码
scheme只允许 http/https硬编码
单张 / 单条消息总大小10MB / 32MBpb.media.max-image-bytes / max-total-bytes
抓取超时 / 跳数10s / 2pb.media.timeout / max-redirects

要让服务端抓内网图片

  1. 把主机名精确加进 pb.media.allow-hosts 
    bash infra/run-dev.sh --pb.media.allow-hosts=grafana.internal:3000
    默认禁抓私网与 100.64.0.0/10。写的是精确 host 或 host:port，不是前缀匹配；留空表示图片来源全为公网。

什么时候能看到图

  • 200 不等抓图；槽位先落 pending。
  • 等待队列有上限（pb.media.queue-capacity），排满时槽位记 queue_full，消息照常下发。
  • 带图的消息进合并窗口（pb.notify.media-wait，默认 3s）：图文齐全只发一帧，纯文字立刻下发。
  • pb.media.retry-max 是含入站首次在内的总次数（默认 3），用完停在 failed。
  • 删除后先标 deleted，过了 pb.s3.delete-grace（默认 168h）真删并变 purged。

图片是「尽力而为」的附件

正文可用性优先：抓图失败不会让消息消失，坏头像也不会拒绝整条投递。失败的格子在客户端画成「已失效」。

限流与配额

闸门默认配置键
每频道每分钟60 + 突发 20pb.ratelimit.per-channel-per-min / burst / 频道 rate_limit
每来源 IP 每分钟120 + 同一份突发量pb.ratelimit.per-ip-per-min
每频道图片抓取见配置pb.media.fetch-rate-per-channel-per-min
每日条数 / 图片 / 字节0 = 不限频道 daily_msg_limit / daily_image_limit / daily_bytes_limit
凭据错误锁定5 次 / 5 分钟窗口 → 锁 5 分钟pb.ingest.credential-fail-lock / lock-window

闸门是进程内的 60 秒滚动窗口

多实例部署时实际放行量约等于「单实例阈值 × 实例数」，别把它当成对外承诺的配额。

429 的 hint 里就是可重试秒数：频道与 IP 是 60，日配额是 86400。
