客户端 API（读取）

客户端 API：设备读取

这一套给自己的设备用：拉历史、搜全文、建频道、标已读、删除、取图片字节。第三方够不到这里。

两条鉴权路径

路径 A · 第三方写入

POST /message
凭据 = 频道号 + 频道密钥，只放 body
响应是明文 JSON
见入站 API

路径 B · 设备读写 本页

/api/v1/**
凭据 = 设备 token + Ed25519 请求签名
响应体过一次性密封盒
私钥不离开设备，服务端只存公钥

路径 B 要挡的是服务端之外的人。它不是端到端加密：服务端要能做中文全文检索，库里存的是明文。

凭据：从哪来、怎么换

凭据从哪来怎么轮换
设备 tokenregister / join 的响应，只存在设备上没有自助换 token 的口：吊销这台，再注册一台
恢复码（group_secret）首次注册时由服务端生成，只在那一次回明文POST /api/v1/devices/rotate-recovery-code；旧码即刻失效
设备私钥设备上生成，公钥随注册上传不上传、不可恢复；丢了只能换机或清数据后重新注册
频道 secret建频道那一次回显，只显示一次POST /api/v1/channels/{no}/rotate-secret
  • 恢复码是换机、重装、忘记设备密钥时唯一的找回途径，请抄在纸上。
  • 连 register 与 join 的响应也是密封盒：token 与恢复码等价于账号口令。

请求要带的五个头

位置内容服务端怎么校验
Authorization: Bearer <token>注册时下发的设备令牌令牌须存在、未吊销，且设备 ID 与它匹配
X-PB-Device设备 ID与令牌指向的设备一致
X-PB-Tsepoch 毫秒与服务端时间差 ≤ 300s
X-PB-Noncebase64，≥ 16 字节进 10 分钟去重缓存
X-PB-Sigbase64 的 Ed25519 签名用注册时上传的签名公钥验
  • 四个签名头缺任何一个都是同一句 缺少签名头 X-PB-Device/Ts/Nonce/Sig，不会告诉你缺哪个。
  • 每个设备每分钟限 300 次，不叠突发。
  • 响应体一律是密封盒，要用设备自己的加密私钥解；算法与帧通道见 长连接与加密。

签的是哪些字节

逐字节拼出来，换行分隔，UTF-8：

pushbox-rest-auth-v1
{deviceId}
{METHOD 大写}
{requestURI}
{原始 query 串，无 query 时是空行}
{sha256_hex(body)，无 body 时对空字节串取 sha256}
{ts}
{base64(clientNonce)}
  • path 用请求的 URI，含 servlet context path。
  • query 用原始串，不是解析后重新拼的那份。
  • GET /api/v1/search 的参数顺序固定为 q, channel_no, sender_id, type, since, limit，换序就整片验签失败。
  • q 含中文或空格时，按百分号编码后的形态进 canonical。
  • GET、DELETE 以及三个「点一下就行」的 POST 都对空字节串的 sha256 取哈希：无 body 不等于不签。
  • ts 是数字：1000 与 "1000" 的 sha256 不同。

响应：一次性密封盒

除两个字节接口外，所有 /api/v1 响应体都包在同一个信封里。

{
  "v": 1,
  "eph_pub": "base64(32B X25519 临时公钥)",
  "salt":    "base64(32B = sha256(eph_pub))",
  "data":    "base64(AES-256-GCM 密文)",
  "n": 0
}
  • 用设备的加密私钥与 eph_pub 算出会话钥，再以 n 解开。
  • 每次响应现生成一对临时密钥，所以一次请求一个会话。
  • 解开后的键名见下面端点全表的「成功时回什么」列。

两个例外：字节接口不是密封盒

GET /api/v1/media/{msgId}/{idx} 与 GET /api/v1/avatars/{token} 回原始字节加真实 Content-Type，并带 Cache-Control: no-store。它们仍然完整鉴权，只是响应不加密。

端点全表

鉴权列：开放 = 只按来源 IP 限流；设备 = 上面那五个头。

设备与空间

方法 · 路径鉴权做什么成功时回什么
POST /api/v1/devices/register开放首启注册一台设备device_id / group_id / token / recovery_code / server_pub_fp
POST /api/v1/devices/join开放换机或加第二台同上
GET /api/v1/devices设备列本 Space 的设备每台：device_id / name / platform / created_at / last_seen_at / revoked_at / current
DELETE /api/v1/devices/{deviceId}设备吊销一台{ok, device_id}
POST /api/v1/devices/rotate-recovery-code设备换恢复码{ok, recovery_code}
  • 两个开放接口的 body：enc_pubkey、sign_pubkey（base64url 无填充的 32 字节原始公钥）、name、platform；join 的 group_secret 必填。
  • register 不带 group_secret 就是新建一个 Space；带了等价于 join。
  • 同一 Space 的活动设备上限 5 台。
  • 吊销即刻生效：token 作废、在线连接当场踢掉，其余端即刻收到 config/device_revoked。
  • rotate-recovery-code 无请求体；旧码即刻失效，新码只在这一次回明文。

频道

方法 · 路径请求做什么成功时回什么
POST /api/v1/channelsname? · max_level? · max_images?建一条频道频道治理面 + secret（仅此一次）
GET /api/v1/channels—本 Space 频道面channels[] + 根上的 subscribed_only
POST /api/v1/channels/join{channel_no, secret}接入一条频道该频道治理面 + subscribed_only
POST /api/v1/channels/leave{channel_no}取消接入{ok, channel_no, removed}
POST /api/v1/channels/subscription-mode{subscribed_only: 0|1}切这台设备的投递过滤{ok, subscribed_only}
PUT /api/v1/channels/{no}治理位 patch改频道配置改后的频道治理面
POST /api/v1/channels/{no}/rotate-secret无请求体换密钥{ok, channel_no, secret}
POST /api/v1/channels/{no}/reset-channel-no无请求体换对外号码频道治理面 + old_channel_no
DELETE /api/v1/channels/{no}—归档{ok, channel_no, archived_at}
GET /api/v1/channels/{no}/capacity—看这条频道的体量total_messages / total_text_bytes / total_images / total_image_bytes / earliest_msg_at
GET /api/v1/channels/{no}/senders—列发送者白名单{ok, channel_no, senders[]}，每项 sender_id + enabled
POST /api/v1/channels/{no}/senders{sender_id, enabled?}加或停一个发送者{ok, channel_no, sender_id, enabled}
  • PUT 可提交这 11 项：name、max_level、max_images、rate_limit、max_body_bytes、strict_auth、muted、daily_msg_limit、daily_image_limit、daily_bytes_limit、sender_whitelist_mode；未提交的字段保持原值。
  • 频道治理面另外还回 channel_no、created_at、archived_at。
  • 读路径永不含 secret；它只在创建与重置这两条响应里出现。
  • 每一项恒带 subscribed（这台设备接没接入这条）；一条都没接入时是全 false，不是缺这个键。
  • 数字型治理位填 0 表示沿用服务端默认值；muted / strict_auth / sender_whitelist_mode 是 0/1 位，0 就是「关」。
  • join：错密钥 401；未知号码、别的 Space、已归档一律 404；空号码 400；重复接入幂等。
  • leave：幂等，没接入过也回 200，removed:false。
  • subscription-mode：回的是服务端实际生效值，客户端以它为准；填 2、-1 一律 400。
  • rotate-secret：旧 secret 即刻作废。
  • reset-channel-no：旧号即刻作废，历史随迁、密钥不变。
  • 归档后停止接收新消息（第三方收 403），历史保留，不可撤销。
  • 白名单的 enabled 省略＝加上并能发；显式 false 是停用而不是删除。
  • 建频道的那台设备默认接入自己刚建的那条。

接入是投递过滤器，不是权限边界

join 用频道号加密钥，只证明「我有权往这条频道发」；服务端据此把这条频道记进这台设备的订阅集。跨 Space 的频道即使知道密钥也接不进来，回 404。

subscribed_only=0（默认）收本 Space 全部频道；=1 时实时帧、断线回放、REST 历史与搜索一起只走已接入的频道。开了过滤又一条没接入，就是收不到任何内容。

接入之后，这条频道接入前的消息也拉得到：过滤按频道，不按接入时刻。

消息、已读与删除

方法 · 路径参数 / body做什么成功时回什么
GET /api/v1/messagesafter_seq=0 · channel_no? · limit=200（夹到 1..500）增量补拉；after_seq=0 即全量恢复历史{messages[], tombstones[], latest_seq, has_more}
GET /api/v1/messages/{id}—取单条全文一条消息对象
PUT /api/v1/state/read[{channel_no, sender_id, last_read_seq}]批量置已读{ok, updated}
DELETE /api/v1/messages/{id}—删一条{ok, id, deleted_at}
DELETE /api/v1/messageschannel_no 必填 · sender_id?清一个会话；省略 sender_id 清整个频道{ok, channel_no, sender_id, deleted, deleted_at}
GET /api/v1/searchq 必填 · channel_no? · sender_id? · type? · since? · limit?服务端全文搜索（中文 ngram）{results[], has_more}
  • 帧里带 truncated:true 时，靠 GET /api/v1/messages/{id} 取回未截断的正文。
  • 置已读会逐条向同组其他端广播 read 帧；已读游标只增不减。
  • 删一条会同时把图片标成待删，并向同组其他端广播 tombstone{id}。
  • 清空整会话或整频道是「一条 UPDATE + 一条 scope 帧」：sender_id 为空时下发 tombstone{scope:{channel_no, sender_id:null}}，客户端据此清掉该频道下所有会话。
  • 清空是幂等的：本来就空时回 deleted=0，不报 404；省略 sender_id 时响应里的 sender_id 是空串。
  • 搜索的每条结果只有 snippet，不含全文；要全文按 id 再取一次。

一次完整流程

签名要现算、响应要私钥解，所以这一组不适合手工 curl。下面是按顺序的调用形状与字段名。

  1. 首启注册：设备自己生成两对密钥，只上传公钥 
    POST /api/v1/devices/register
  {enc_pubkey, sign_pubkey, name, platform}
  -> {device_id, group_id, token, recovery_code, server_pub_fp}
    响应是密封盒，上面这行是解开后的键。recovery_code 与 token 都只在这一次出现。
  2. 建一条频道，把 secret 抄下来 
    POST /api/v1/channels
  {name:"服务器告警", max_level:"error"}
  -> {channel_no, secret, ...}
    建频道这台设备默认已接入这条。
  3. 换到路径 A 写一条，不再需要设备签名 
    curl -sS http://127.0.0.1:7404/message \
  -H 'Content-Type: application/json' \
  --data-binary @payload.json
    payload 里的 channel / secret 就是上一步那一对；字段全表见 入站 API。
  4. 增量补拉：after_seq 用自己存的水位 
    GET /api/v1/messages?after_seq=1041&limit=200
  -> {messages[], tombstones[], latest_seq, has_more}
    has_more 为真就接着用新一页的 latest_seq 往下拉。
  5. 打开会话即置已读 
    PUT /api/v1/state/read
  [{"channel_no":"12345678","sender_id":"grafana","last_read_seq":1042}]
  -> {ok, updated}
  6. 取图片与头像字节：仍带签名头，但响应不加密 
    GET /api/v1/media/{id}/0?size=thumb
GET /api/v1/avatars/{sha256_hex(sender_id)}
  7. 全文搜索：参数顺序不能动 
    GET /api/v1/search?q=CPU&channel_no=12345678&since=0&limit=50
  -> {results[], has_more}
    只带要用的参数，但顺序必须按 q, channel_no, sender_id, type, since, limit。

状态码与含义

HTTPerror该怎么做
401unauthorized只有「设备无效或已吊销」该清本地身份，其余一律修请求
409replaynonce 撞了，换新 nonce 重签一次
409device_limit_reachedSpace 已满 5 台，先吊销一台
404not_found媒体按 hint 分支，不要只看状态码
429rate_limited每设备 300/min；正常客户端撞不到，撞到了说明有循环
400invalid_param唯一会明确告诉你哪里不对的一类
500—只在跑旧镜像的部署上见得到；升级后坏请求回 400 信封
  • 401 的 hint 只会是这几句：缺少设备 token、缺少签名头 X-PB-Device/Ts/Nonce/Sig、设备无效或已吊销、nonce 长度不足、ts 必须是 epoch 毫秒、clock_skew、bad_signature。
  • clock_skew 与 bad_signature 都只能修请求：清本地身份等于丢掉这台设备的密钥。
  • 404 的 hint 是槽位状态机的一部分：媒体接口回 pending / ready / failed / deleted / purged，头像接口只回 avatar。
  • purged 就别再重试；pending 值得稍后再取一次。
  • 错误体形状固定：{"ok":false,"error":"...","hint":"..."}，hint 没有内容时是空串。
  • 429 带 Retry-After 响应头。
  • 跨 Space 访问与「记录不存在」是同一句话，不会告诉你别人的消息 ID 或头像 token 是否存在。

写客户端时的四条注意

  • 空 body 的 POST 不能只换 method：OkHttp 会拒「有 body 却没设 BodyPublisher」，也会拒「POST 复用 GET 请求」。rotate-secret、reset-channel-no、rotate-recovery-code 三处要显式带空体。
  • canonical 里的 query 必须是原始串，别用「解析成 map 再拼」的结果。
  • 先验签再落库，失败不留半条。server_pub_fp 首连记下，之后指纹变了就该拒绝而不是弹框问一下。
  • 已读游标只增不减：服务端对已读状态是后写覆盖并广播，一个迟到的旧帧就能把游标退回去。

怎么确认自己实现对了

「看起来实现了」与「逐字节一致」是两件事。按这个顺序对：

  • 测试向量：contracts/testvectors/vectors.json，固定输入配固定期望输出，覆盖签名、REST 鉴权、密封盒、帧、棘轮与摘要。跨语言对齐只认这一份。
  • 参考实现：packages/core/（Java，三端共用）与 Windows 的 C# 加密层。
  • 跑一次端到端自检：起好服务端后照 安装与部署 那一步跑一遍，它模拟一台设备走完整条链路。

实时下发（握手、帧类型、断线补拉、密钥轮换）不在这一页，见 长连接与加密。

写入侧：入站 API —— 一条 POST /message，凭据放 body。
跨 Space 的运维视图（列全部频道与设备、搜全部消息、定时推送、吊销设备）在另一套鉴权上：管理台 API，它用一条口令换出来的 JWT，不需要这页的四个签名头，响应也不加密。
