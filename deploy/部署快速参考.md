# PushBox Docker 部署快速参考

> 起步只有两个变量必填：**库地址**与**库口令**。其余拓扑默认值已经烘焙在镜像里。

---

## 🚀 主路径：一个容器，两个变量

这一条**不用克隆仓库、也不用 `.env`**——`docker run` 的取值直接进容器环境，剩下的一切镜像自己知道。

```bash
docker run -d --name pushbox \
  -p 7404:7404 \
  -e PB_DB_HOST=192.0.2.20 -e PB_DB_PASSWORD='<强口令>' \
  -v pushbox-media:/app/data/media -v pushbox-logs:/app/logs \
  docker.io/iamplusdev/push-box:latest   # 或钉本次的版本号，两者是同一份镜像
```

`192.0.2.20` 是 RFC 5737 的文档保留地址，**照抄一定连不上**——换成你那台库的局域网 IP 或服务名。

飞牛/群晖的「创建容器」表单里填什么，见 [NAS 部署指南](NAS部署指南.md) 路径 C：**存储位置加两行**
（`/app/data/media`、`/app/logs`），**环境变量只填两个**。存储位置留空的话，`docker rm` 会把图片一起删掉。

`docker.io/iamplusdev/push-box` 这一个镜像里同时有 API、WebSocket、入站端点和 Web 管理台：
`deploy/Dockerfile` 的 node 阶段把 `web-admin` 打进 jar 的 `classpath:/static/`，由同一个 Spring Boot
进程在同一个端口吐出来——**没有第二个前端容器，也不需要额外反代规则与 CORS 配置**。
管理台在**根路径 `/`**（不是 `/admin`，SPA 没配 vite base），打开就是登录页。

不给别的值时的样子：端口 7404、本地文件存储（图片落在 `pushbox-media` 卷里，明文 + 每文件 600 权限，
entrypoint 会出声提醒一次）、管理台**关闭**、库名与库用户名都是 `pushbox`、Flyway 首次启动自动建表。

### 镜像之外只有一件事：库和账号要先存在

服务端不会替你建库（代码里没有建库动作，Flyway 只建表），所以那两行变量指向的库必须已经存在。
在库所在那台机器上跑一次就够：

```sql
CREATE DATABASE IF NOT EXISTS pushbox
  CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;
CREATE USER IF NOT EXISTS 'pushbox'@'%' IDENTIFIED BY '<强口令>';   -- 必须是 '%'：另一个容器连过来的来源不是 localhost
GRANT SELECT, INSERT, UPDATE, DELETE, CREATE, ALTER, INDEX, DROP, REFERENCES
  ON pushbox.* TO 'pushbox'@'%';
FLUSH PRIVILEGES;

SELECT @@ngram_token_size;   -- 期望 2；不是 2 就搜不出中文长句
```

两条边界别等起完容器才发现：

- **库只能是 MySQL 8.0 / 8.4**。`V1__init.sql` 用了 `utf8mb4_0900_ai_ci` 与 `FULLTEXT … WITH PARSER ngram`，
  MariaDB 与 MySQL 5.7 过不去。
- **Hub 上那份镜像只有 linux/amd64**（发布工作流没传 `platforms`）。ARM 机型要自己构建：
  `docker build -f deploy/Dockerfile -t pushbox:local .`——这一步才需要克隆仓库，因为它读的是仓库里的 `Dockerfile`。

### 想换形态就在同一条命令后面追加变量，别去改镜像

| 想要的形态 | 追加 |
|------|------|
| 开管理台 | `-e PB_ADMIN_SECRET='<openssl rand -base64 32>' -e PB_ADMIN_JWT_SECRET='<另一个不同的强随机值>'` |
| 外接桶 | `-e PB_STORAGE_TYPE=s3 -e PB_S3_ENDPOINT -e PB_S3_ACCESS_KEY -e PB_S3_SECRET_KEY`，再加 `-e PB_S3_OBJECT_ENCRYPT=sse-c -e PB_S3_MASTER_KEY='<openssl rand -base64 32>'` |
| 本地图片也要加密 | `-e PB_S3_OBJECT_ENCRYPT=sse-c -e PB_S3_MASTER_KEY='<openssl rand -base64 32>'`（主钥一旦有对象落库就**不可轮换**） |
| 改端口 | `-e PB_SERVER_PORT=8081` 并把 `-p` 的右侧同步成 8081 |
| 库地址只写完整串 | 用 `-e PB_DB_URL='jdbc:mysql://…'` 替代 `PB_DB_HOST`（两个都给时以 `PB_DB_URL` 为准） |

管理台那两项的规则一起记：要么**都给**（互不相同、各 ≥32 字节；只给一个、给弱值或两者同值，容器直接拒绝启动），
要么**都不给**（管理台整个关闭，那些接口一律回 403「管理台未启用」，客户端收发照旧——这是安全状态，不是漏配）。
`PB_ADMIN_SECRET` 是人要输的那份口令，`PB_ADMIN_JWT_SECRET` 是签票据的钥；换后者等于作废全部已登录会话，换前者不会。

### 已经有桶：同一条命令换成落桶

```bash
docker run -d --name pushbox \
  -p 7404:7404 \
  -e PB_DB_HOST=192.0.2.20 -e PB_DB_PASSWORD='<强口令>' \
  -e PB_STORAGE_TYPE=s3 \
  -e PB_S3_ENDPOINT=http://192.0.2.30:7101 \
  -e PB_S3_ACCESS_KEY='<AK>' -e PB_S3_SECRET_KEY='<SK>' \
  -e PB_S3_BUCKET=pushbox \
  -e PB_S3_OBJECT_ENCRYPT=sse-c -e PB_S3_MASTER_KEY='<openssl rand -base64 32>' \
  -v pushbox-logs:/app/logs \
  docker.io/iamplusdev/push-box:latest
```

- `PB_STORAGE_TYPE=s3` 不能省：镜像默认烘焙的是 `local`，只给 `PB_S3_*` 不给这个开关，那几项一个字都不读，
  entrypoint 只会 WARN「配了但读不到」，图片照旧落本地目录。
- `pushbox-media` 那个卷在这里没用了（对象落桶），日志卷还是要。**桶要先自己建**（见下面「桶要建一次」），
  跟别的系统共用一个桶可以，但 PushBox 只认自己那套对象键。
- `s3 + none` 直接拒启，没有 local 那种"只出声"的余地——见下面「加密口径」。逃生阀是
  `-e PB_ALLOW_PLAINTEXT_MEDIA=1`，正路是 `sse-c` + 主钥（主钥用过就不可轮换）。
- `PB_S3_PATH_STYLE` 默认 `true`（MinIO / RustFS 对），阿里云 OSS 或 AWS 按服务商文档可能要 `false`；
  桶名与区域不是 `pushbox` / `us-east-1` 就改上面那两行。

### 三条不能省的

- **`PB_STORAGE_TYPE=local` 时那两个卷要挂**。对象字节落在 `PB_STORAGE_LOCAL_PATH`（镜像内默认
  `/app/data/media`），不挂卷等于把图片写在容器可写层里，`docker rm` 之后全没。日志同理。
- **端口以 `PB_SERVER_PORT` 为准**，默认 7404，`EXPOSE` 写的也是它；改了要同步 `-p <宿主>:<新端口>`。
- **`/app/data` 归 uid 10001**。镜像里的运行用户是 `pushbox(10001)`，绑定挂载会把宿主目录的属主
  带进来，宿主目录若不是它可写，entrypoint 的写入探针会当场拒绝启动并给出两种修法
  （改用 named volume，或 `sudo chown -R 10001:10001 <宿主目录>`）。

### 验收：在容器里取，不要在宿主上取

```bash
docker exec pushbox curl -s http://127.0.0.1:7404/healthz
# 期望最后一段：{"ok":true,"db":"up","storage":"up","uptime_ms":…}
```

**别在宿主上 `curl http://localhost:7404/healthz`**：`InternalAccessFilter` 只认 `getRemoteAddr()`，
经端口映射进来的连接在容器里看到的是网桥网关而不是 127.0.0.1，会被回 **404**（拒绝时故意不用 403，
免得扫描器确认这里有个运维端点）。这不是故障；要从宿主直接看，把这套网络分到的子网写进
`PB_SECURITY_INTERNAL_CIDRS`。同理，容器状态 `healthy` 只代表 TCP 探活通了，不等于 `db=up`。
镜像里有 `curl`（`eclipse-temurin:21-jre` 自带），没有 mysql 客户端——原因见下面「健康检查 db=down」。

### 在 NAS 的图形界面里装（飞牛 / 群晖 / 1Panel）

那种界面只有"逐条加环境变量"的表格、**没有 `.env` 这一层**，所以走
**[docker-compose.nas.yml](docker-compose.nas.yml)** + **[NAS部署指南.md](NAS部署指南.md)**：
那本 compose 文件的取值行里没有任何解析阶段的必填插值，改两行就能 `up`；表格里要填的还是同样那两个变量。

## 🐳 形态二：compose（要反代 / 监控 / 自带桶时才走）

**为什么这一条要 `git clone` 而主路径不用**：`docker-compose.yml`、`Caddyfile`、
`docker-compose.monitoring.yml` 和那几段 sidecar 定义都是**文件**，它们装不进 `pushbox` 镜像里；
`.env` 只是给这些文件记账的那一层。只要一个容器时用不到它们。要 Caddy 反代、要 Prometheus/Grafana，
或者想让 compose 顺手把 MySQL 与 RustFS 一起起来，才需要这一节。

拓扑三选一，都靠 `.env` 里的地址区分，compose 文件本身不用改。

### 拓扑 A：复用已有的 MySQL 与桶（推荐生产环境）

```bash
# 1. 克隆并进入部署目录
git clone https://github.com/iamplusdev/push-box.git
cd push-box/deploy

# 2. 准备配置文件
cp env/prod.env.example .env

# 3. 一键生成所有密钥（Linux/macOS）
source <(cat <<'EOF'
PB_DB_PASSWORD=$(openssl rand -base64 24)
PB_S3_ACCESS_KEY=$(openssl rand -hex 16)
PB_S3_SECRET_KEY=$(openssl rand -base64 32)
PB_ADMIN_SECRET=$(openssl rand -base64 32)
PB_ADMIN_JWT_SECRET=$(openssl rand -base64 32)
PB_S3_MASTER_KEY=$(openssl rand -base64 32)

sed -i "s|^PB_DB_PASSWORD=.*|PB_DB_PASSWORD=$PB_DB_PASSWORD|" .env
sed -i "s|^PB_S3_ACCESS_KEY=.*|PB_S3_ACCESS_KEY=$PB_S3_ACCESS_KEY|" .env
sed -i "s|^PB_S3_SECRET_KEY=.*|PB_S3_SECRET_KEY=$PB_S3_SECRET_KEY|" .env
sed -i "s|^PB_ADMIN_SECRET=.*|PB_ADMIN_SECRET=$PB_ADMIN_SECRET|" .env
sed -i "s|^PB_ADMIN_JWT_SECRET=.*|PB_ADMIN_JWT_SECRET=$PB_ADMIN_JWT_SECRET|" .env
sed -i "s|^PB_S3_MASTER_KEY=.*|PB_S3_MASTER_KEY=$PB_S3_MASTER_KEY|" .env

# 只报"填了几行"，不把值打到屏幕上：这一步的输出会留在终端回滚缓冲里，
# 顺手粘进聊天工具或 CI 日志的概率比抄错一位口令高得多。
echo "✅ 6 个密钥已生成并填入 .env（PB_DB_PASSWORD / PB_S3_*×3 / PB_ADMIN_SECRET / PB_ADMIN_JWT_SECRET）"
echo "   管理台登录用 PB_ADMIN_SECRET 那一行，自己从 .env 里看；PB_ADMIN_JWT_SECRET 是签名钥，永远用不到人眼看。"
EOF
)

# 4. 编辑 .env，填写实际的 S3/MinIO/RustFS 地址
# vi .env  # 修改 PB_DB_URL、PB_S3_ENDPOINT 等

# 5. 启动服务
docker compose up -d

# 6. 等就绪（日志里出现 Started PushboxServerApplication 就够了，通常 30~60 秒）
docker compose logs -f pushbox-server    # Ctrl-C 退出

# 7. 验收：浏览器打开 http://<这台机器的IP>/ （走 Caddy，端口是 PB_HTTP_PORT，默认 80）
#    这一套把 7404 只绑宿主环回，手机/PC 直连 :7404 是连不通的——那是设计，不是故障。
#    再在容器里取一次 /healthz（它只认容器环回，从宿主打过去是 404）：
docker compose exec pushbox-server curl -s http://127.0.0.1:7404/healthz
```

要监控栈就多带一本文件（Prometheus + Grafana 都在里面，只绑 127.0.0.1）：

```bash
docker compose -f docker-compose.yml -f docker-compose.monitoring.yml up -d
```

这条网络分到的子网要写进 `PB_SECURITY_INTERNAL_CIDRS`，否则进程好好的、targets 全 403。

### 拓扑 B：库和桶也让 compose 一起起来

取消 `docker-compose.yml` 里 `mysql` / `rustfs` 那两段的注释，主机改成服务名
（`PB_DB_URL=jdbc:mysql://mysql:3306/pushbox?…`、`PB_S3_ENDPOINT=http://rustfs:9000`），
再补一个 `MYSQL_ROOT_PASSWORD`（只在初始化用）。嫌手写麻烦可以直接用 `docker-compose-wsl.yml`，
那一份已经把自带拓扑配好了。

**建库建账号这一步照样在你自己身上**：那两段起来的是空实例，`pushbox` 库与 `'pushbox'@'%'` 用户仍要按
上面那段 SQL 建一次；Flyway 的 DDL 只允许落在这个库里。

### 拓扑 C：不用桶（本地文件系统存储）

```bash
# 1-2. 同上

# 3. 使用本地存储配置
cat > .env <<'EOF'
# PB_DB_URL 整条写死也行；只填 PB_DB_HOST/PORT/NAME 时 entrypoint 会拼出同一条串。
PB_DB_URL=jdbc:mysql://<DB_HOST>:3306/pushbox?useSSL=false&allowPublicKeyRetrieval=true&serverTimezone=Asia/Shanghai&characterEncoding=utf8
PB_DB_USERNAME=pushbox
PB_DB_PASSWORD=<强口令>
PB_STORAGE_TYPE=local
PB_STORAGE_LOCAL_PATH=/app/data/media
# 本地模式明文落盘只出声、不拦启动（自己的盘 + 每文件 600，威胁模型和共享桶不一样）。
# 想真加密就改成 PB_S3_OBJECT_ENCRYPT=sse-c + PB_S3_MASTER_KEY=$(openssl rand -base64 32)，
# 注意主钥一旦用过不可轮换。
PB_S3_OBJECT_ENCRYPT=none
# 管理台想要就填这两个（必须不同、各 ≥32 字节）；留空则管理台关闭，服务照常跑。
PB_ADMIN_SECRET=
PB_ADMIN_JWT_SECRET=
EOF

# 4. 启动服务（对象落进 named volume pushbox_server_media，见下一段）
docker compose up -d

# 5-7. 同上
```

**优势**：无需部署 MinIO/RustFS，一条 `up` 就能起，适合个人或小团队轻量级部署。
**注意**：本地存储模式下仍需 MySQL 数据库，只是不需要对象存储服务。

对象的去向要说清楚，因为它决定备份怎么做：compose 把 `/app/data/media` 挂在一个 **named volume**
（`pushbox_server_media`）上，不是宿主的 `./data/media`。原因和日志用 named volume 一模一样——
绑定挂载会把宿主目录的属主带进容器，而 Docker 替缺目录建出来的宿主目录属 root，容器里的
`pushbox(10001)` 写不动。named volume 首挂时继承镜像里那个目录的属主，所以 `up` 完就能写。

想改成看得见的路径（方便直接 `tar`）就把 volumes 那行换成 `- ./data/media:/app/data/media`，
代价是先把宿主目录交给运行用户：`sudo mkdir -p ./data/media && sudo chown -R 10001:10001 ./data/media`。
两种挂法都会先过 entrypoint 的写入探针，探不过就拒绝启动并把上面这两种修法打出来。

```bash
# 查对象实际落在哪（named volume 的挂载点，备份脚本的 MEDIA_DIR 就填它）
docker volume inspect pushbox_server_media -f '{{.Mountpoint}}'
```

### 加密口径（两种存储分档，2026-10-22 起）

`PB_S3_OBJECT_ENCRYPT` 管的是**对象字节**，跟"用不用对象存储服务"无关：`local` 模式下
`LocalFileStorage` 同样按这个值决定落盘的是明文还是 `KeyWrap.seal` 封装后的密文，读侧按
`media_objects`/`senders` 各自记的 `enc_mode` 逐对象解读。但"忘了配就等于明文"这一关**按拓扑分档**：

| 组合 | 结果 |
|------|------|
| `local` + `sse-c` + 主钥 | 磁盘上是密文，主钥丢了图片永久读不出来；主钥**不可轮换** |
| `local` + `none` | **只出声**：entrypoint 与 `ProdPlaintextMediaGuard` 各打一条 WARN，正常启动。图片就在自己这块盘上，权限 600（NTFS 上不生效），跟"别人能读的那个桶"不是同一个威胁 |
| `s3` + `none` 且不开 `PB_ALLOW_PLAINTEXT_MEDIA=1` | **拒绝启动**，报的是 `ProdPlaintextMediaGuard` 那段话（共享桶里明文对象谁都能捞） |
| `s3` + `none` + 逃生阀开 | 放行，用于迁移期 |
| `sse-c` 但主钥缺失/长度不对 | 拒绝启动（entrypoint 与 `S3Config` 各查一遍，都不打印值本身） |

逃生阀 `PB_ALLOW_PLAINTEXT_MEDIA` 现在只对 `s3` 有意义；`local` 不需要它也不会被它拦住。
注意它**不能当启动门槛用**：`PB_S3_OBJECT_ENCRYPT` 在镜像里有默认值，`${VAR:?}` 那类插值只会查"有没有配"，
永远查不到"配的是明文"，所以这条判据必须在进程里做。

## 📋 关键配置项速查

| 变量 | 说明 | 示例 |
|------|------|------|
| `PB_DB_HOST` | **必填**，数据库地址（服务名或局域网 IP） | `192.0.2.20`；同一个 Compose 项目里填服务名 `mysql` |
| `PB_DB_PASSWORD` | **必填**，数据库密码 | `<openssl rand -base64 24>` |
| `PB_DB_PORT` / `PB_DB_NAME` / `PB_DB_USERNAME` | 有默认值 `3306` / `pushbox` / `pushbox`，只对不上时才改 | — |
| `PB_DB_URL` | 想手写整条 JDBC 串就设它（设了就不再看 `PB_DB_HOST`） | `jdbc:mysql://<DB_HOST>:3306/pushbox?...` |
| `PB_STORAGE_TYPE` | 镜像默认 `local`；`docker-compose.yml` 显式传 `s3` | `local` \| `s3` |
| `PB_S3_ENDPOINT` | 对象存储地址（`s3` 模式必填） | `http://<S3_HOST>:7101` |
| `PB_S3_ACCESS_KEY` | S3 Access Key（`s3` 模式必填） | `<openssl rand -hex 16>` |
| `PB_S3_SECRET_KEY` | S3 Secret Key（`s3` 模式必填） | `<openssl rand -base64 32>` |
| `PB_ADMIN_SECRET` | 管理台登录口令 | `<openssl rand -base64 32>`，**按需**——留空即管理台禁用，这是安全状态不是漏配 |
| `PB_ADMIN_JWT_SECRET` | 管理台登录票据的签名钥 | `<openssl rand -base64 32>`，**开了管理台才必填，且不能与上面同值** |
| `PB_S3_OBJECT_ENCRYPT` | 对象加密模式 | 镜像默认 `none`：`local` 只出声，`s3` 会拒绝启动。生产用 `sse-c` |
| `PB_ALLOW_PLAINTEXT_MEDIA` | 允许明文**对象存储** | 只对 `s3` 有意义；`local` 不需要它 |
| `PB_S3_MASTER_KEY` | SSE-C 主钥 | `<openssl rand -base64 32>`（sse-c 必填，且落库后不可轮换） |
| `PB_DB_WAIT_SECONDS` | 启动时等库可达的秒数，默认 60 | 第一次初始化空库（NAS 上普遍要 1～2 分钟）撞超时就把这条调大 |
| `PB_SECURITY_INTERNAL_CIDRS` | 能访问 `/actuator`、`/healthz` 的网段 | 留空=只放行容器环回（默认）；跑监控时显式写这条网络分到的子网 |

除这两类之外没有别的门槛：**必填只有 `PB_DB_HOST`（或 `PB_DB_URL`）+ `PB_DB_PASSWORD` 两项**，
口令类变量一律不给默认值。模板里的其余主机都是占位符（`<S3_HOST>`），要换成自己的地址；真实内网地址不要提交回仓库。
`PB_ADMIN_JWT_SECRET` 短于 32 字节、与 `PB_ADMIN_SECRET` 同值，容器都会在启动阶段直接拒绝运行；
但只设了 `PB_ADMIN_SECRET` 而漏掉它，也是拒绝启动而不是"静默降级成不校验签名"。

`PB_S3_ENDPOINT` 的端口跟着拓扑走，别互相抄：`rustfs/rustfs:latest` 镜像监听 **9000**（S3）/ 9001（Console），
而 §11.1 那台远端存储机把实例挂在 **7101**。配错端口时 `/healthz` 救不了你：`s3` 那一路只判配置非空、
不探测可达性（`HealthzController.storageConfigValid`），所以错地址会一路绿灯，直到第一条带图的消息在抓取阶段
停在 `failed` 才看得见；`local` 那一路是真去写一个探针文件，写不动就报 `storage=down`。

## 🪣 桶要建一次（S3 模式）

服务端不会自动建桶（代码里没有 CreateBucket），仓库里也没有任何 provisioning 步骤，
所以 `PB_S3_BUCKET` 指向的桶必须先存在。用 `mc`（或 RustFS 控制台）建一次：

```bash
mc alias set pb "$PB_S3_ENDPOINT" "$PB_S3_ACCESS_KEY" "$PB_S3_SECRET_KEY"
mc mb --ignore-existing "pb/${PB_S3_BUCKET:-pushbox}"
mc ls pb            # 能看到桶才算这一步过了
```

**手上没有 `mc` 就别去现找**：2026-10-20 实测 `minio/mc` 与 `minio/minio` 在 Docker Hub 都已取不到
（`hub.docker.com/v2/repositories/minio/mc` → 404），`dl.min.io/client/mc/release/linux-amd64/mc` → **410 Gone**。
CI 以前就是拉 `minio/mc` 建桶的，现在改用 AWS CLI v2（Linux 安装包 `https://awscli.amazonaws.com/awscli-exe-linux-x86_64.zip`，实测 200）。等价命令：

```bash
export AWS_ACCESS_KEY_ID="$PB_S3_ACCESS_KEY" AWS_SECRET_ACCESS_KEY="$PB_S3_SECRET_KEY" \
       AWS_DEFAULT_REGION=us-east-1
# region 只是 SigV4 的签名字段，RustFS 不看它；裸 IP 的 endpoint 会自动走 path-style。
aws --endpoint-url "$PB_S3_ENDPOINT" s3api create-bucket --bucket "${PB_S3_BUCKET:-pushbox}"
aws --endpoint-url "$PB_S3_ENDPOINT" s3api head-bucket --bucket "${PB_S3_BUCKET:-pushbox}"   # 退 0 才算过
```

这两条 2026-10-20 在本地对真 `rustfs/rustfs:latest` 容器实测过：`create-bucket` 退 0、重复执行不报错、`head-bucket` 确认桶在。

判据是上面这条 `mc ls` / `head-bucket` 的退出码，别看 `/healthz`；CI 的服务端 job（`.github/workflows/ci.yml`）里同一动作是自动做的。

## 🆘 故障排查

### 容器启动失败

```bash
# 查看详细错误（主路径用 docker logs pushbox）
docker compose logs pushbox-server | tail -50

# 常见原因（entrypoint 的报错自己就带修法，照着那几行读比这里全）：
# ❌ 连不上库 / 库端口不可达 → 那句报错按顺序给了四条：PB_DB_HOST 填成 127.0.0.1（容器里的环回是它自己）、
#    库那层没发布端口、库容器自己在崩溃循环（docker logs <库容器> --tail 20 会明说）、防火墙拦了入站。
#    第一次起空库撞超时不算故障：库的初始化在 NAS 上普遍要 1～2 分钟，把 PB_DB_WAIT_SECONDS 调大（默认 60）
# ❌ 本地存储目录不可写 → 改用 named volume，或把宿主目录 chown -R 10001:10001
# ❌ s3 模式没配 PB_S3_*，或 PB_S3_OBJECT_ENCRYPT=none → 补三项；加密配成 sse-c + PB_S3_MASTER_KEY，确要明文再显式设 PB_ALLOW_PLAINTEXT_MEDIA=1（local 模式不受这条拦，只出声）
# ❌ PB_ADMIN_SECRET / PB_ADMIN_JWT_SECRET 太短或同值 → 各填一个 openssl rand -base64 32；不需要管理台就把两项都留空
# ❌ 数据库连接失败（1045）→ 口令与库里那个用户的对不上，或用户没建成 'pushbox'@'%'
```

### Web 管理台 403 / 429

```bash
# 先分清是"没开"还是"口令错"：两项都留空时管理台整个关闭，一律回 403「管理台未启用」，那是合法状态。
# 口令不对时（compose 形态）先看 .env 里那一行还在不在（重生成过就会对不上）；NAS 界面里去看那条变量
grep PB_ADMIN_SECRET .env

PB_ADMIN_SECRET=$(openssl rand -base64 32)
sed -i "s|^PB_ADMIN_SECRET=.*|PB_ADMIN_SECRET=$PB_ADMIN_SECRET|" .env
docker compose restart pushbox-server

# 429 = 同一来源 IP 连错口令到阈值后被锁（默认 5 次 / 5 分钟），响应里的 hint 会写还要等多久。
# 这不是故障，是限速在起作用；等一下或换一个来源 IP。
# 注意 PB_ADMIN_JWT_SECRET 也一起换的话，所有已登录会话会当场失效、需要重新登录——
# 这正是把它和登录口令拆成两把的目的：换口令不该顺手作废签名钥，反之也一样。
```

### 健康检查 db=down

```bash
# db=down 是 /healthz 真去借了一条连接、那条连接没起来。先在容器里看一眼：
docker compose exec pushbox-server curl -s http://127.0.0.1:7404/healthz

# 再往下就只能是 Java 那侧的日志，第一条异常把原因写全了：
docker compose logs pushbox-server | grep -iE 'HikariPool|Access denied|Communications link|to database' | head
#   Access denied for user 'pushbox'@'<来源 IP>'  → 口令不对，或用户没建成 'pushbox'@'%'（写成 localhost 时，
#                                                    另一个容器连过来的来源就不是 localhost，口令全对也照样 1045）
#   Access denied for user 'pushbox'@'%' to database '<库名>' → 库名对不上，或那个用户没有这个库的权限。
#                                                    MySQL 8 在这种配法下报的是 access denied，不是 "Unknown database"
#   Communications link failure                    → 地址或端口不可达；先看 entrypoint 那条 TCP 预检过了没有
# 那句 `using password: ***` 里的 *** 是我们自己的日志脱敏把 YES/NO 一起遮了（§13），不是口令。
```

**不要在容器里现装 mysql 客户端**：容器跑的是 uid 10001，`apt-get update` 直接 `Permission denied`，
要装得 `docker exec -u root`，而装进可写层的东西 `docker rm` 就没了。上面那两条（`/healthz` 的 `db` 字段 +
Hikari 的第一条异常）已经把"口令错 / 地址错 / 库名错"分开了；真要手工敲 SQL，去库所在那台机器上敲。

## ⚙️ 自定义端口（可选）

主路径只有一个端口：`-e PB_SERVER_PORT=8081` 并把 `-p` 右侧同步改成 8081。容器内的 `/dev/tcp` 探活跟着
这个变量走，`EXPOSE` 只是元数据，真正生效的是 `-p` 与这一个变量。

compose 那套的默认端口是后端 7404、Caddy HTTP 80：

```bash
# 编辑 .env，添加以下行
PB_SERVER_PORT=8888      # 改后端端口为 8888
PB_HTTP_PORT=8080        # 改 Caddy HTTP 端口为 8080

# 重启服务
docker compose up -d
```

Caddy 会自动反代到新的后端端口，无需修改 Caddyfile。

## 🔐 HTTPS 配置（可选）

本项目 Caddy 只监听 80 端口做 HTTP 反代，**不管理 SSL 证书**。如需 HTTPS，请在前面挂 Nginx / Traefik 等做 TLS 终止。

### Nginx 反向代理示例

```nginx
server {
    listen 443 ssl http2;
    server_name pushbox.example.com;

    ssl_certificate     /etc/nginx/ssl/pushbox.crt;
    ssl_certificate_key /etc/nginx/ssl/pushbox.key;

    location / {
        proxy_pass http://127.0.0.1:80;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 300s;
        proxy_send_timeout 300s;
    }
}
```

**客户端配置：**
- Android/Windows 服务端地址填 `https://pushbox.example.com`

### 内网/Tailscale 场景

直接使用 HTTP，无需 HTTPS：
- 客户端地址：`http://IP:端口` 或 `http://域名`
