入站 API（写入）

入站 API：第三方写入

整个入站面只有一个端点。第三方不需要注册设备、不持有任何加密材料、不参与帧加密——一次 POST 就完成投递。

端点

POST   {base}/message

  • 路径是 /message，不在 /api/v1 下。前缀由 pb.ingest.base-path 配置（默认 /message），反代可以整段改名。没有 /message/media 之类的第二个写入口——图片走同一个端点的 images[] 字段。
  • 请求头只需要 Content-Type: application/json。凭据全部在 body 里，绝不进 URL 或 header：URL 会落进访问日志、反代日志和浏览器历史，而消息正文与凭据一旦进日志就是泄露（这也是服务端访问日志默认关的原因）。
  • GET /healthz 无 token，但有来源白名单：默认只放行环回，其余网段必须显式写进 PB_SECURITY_INTERNAL_CIDRS（pb.security.internal-cidrs）。它会真的对数据库做一次 isValid（2 秒超时），storage.type=local 时还会往存储目录写一个探测文件再删掉，任一项不通就回 503、通了一起回 200。所以它是就绪探针（readiness），不能当存活探针（liveness）用——库抖一下就被 K8s 杀掉重启，只会把故障放大成重启循环。响应只有 {ok,db,storage,uptime_ms}，不带版本号、SQL 与连接池参数。

请求体字段

字段类型必填说明
channelstring必填频道号（8 位数字）。与 secret 一起构成凭据
secretstring必填频道密钥。只在创建/重置那一次响应里出现过，忘了只能重置
contentstring必填正文。上限 32768 字节（UTF-8，频道可下调）；超出即 413，不会被静默截断后收下
typestring可选text（默认）/ markdown / link / file。未知值降级为 text，不拒绝整条消息
levelstring可选info（默认）/ warning / error。会被频道 max_level 向下截断，响应回显的是生效值
sender_idstring可选发送方标识，会话线的分界线；省略或空归到 unknown（也就是同一个会话）。截断 64 字符。可以含中文与 /——它不会进 URL，头像接口用的是它的 sha256
sender_namestring可选显示名，截断 64 字符。同一 sender_id 后续可以改，客户端看到的就是最新那份
sender_avatarstring可选头像外链（http/https），由服务端抓回落对象存储。抓取失败不拦消息，只是这条不带头像
titlestring可选标题，截断 512 字符。服务端生成 summary 时优先用它
urlstring可选附带的跳转链接，客户端"打开链接"按钮的目标
images[]string[]可选图片外链数组，默认最多 4 条、单条 URL ≤1024 字符、只允许 http/https（data: 内联图明确不支持）。详见图片
msg_keystring可选幂等键，截断 64 字符，频道内唯一。见幂等
tsnumber可选业务时间，秒或毫秒都收（<1e11 视为秒）。见时间戳
noncestring条件仅当频道开启 strict_auth 时必填，且 ts/nonce/sign 三件套必须同时给。见strict_auth
signstring条件

未知字段会被忽略，不会报错

服务端反序列化关闭了 fail-on-unknown-properties。好处是老脚本多带几个字段不会被拒；代价是拼错字段名不会有任何提示——"我明明传了 sendername 为什么没显示名字"这类问题，先核对拼写。

响应

受理成功一律 200（不是 201，幂等重放也是 200，客户端不必区分）。含义是"正文与抓取任务已入库"，不代表任何一台设备已收到。

{
  "ok": true,
  "id": "01J8ZK3Q7M2XW4V9HTNBSFY6PA",   // ULID，可直接用于 GET /api/v1/messages/{id}
  "seq": 1042,                          // Space 内单调递增水位号
  "summary": "服务端生成的摘要",          // 标题优先，按 pb.notify.summary-chars 截断
  "media_status": "pending",            // 库里那份聚合值：无图=none，有图受理瞬间=pending
  "media_count": 2,                     // 图片槽位数（头像不占槽位）
  "level": "warning"                    // max_level 截断后的实际生效值
}
  • summary 由服务端算，保证各端与通知栏用的是同一句话；上限 pb.notify.summary-chars（默认 60 字符）。
  • 幂等重放命中历史记录时，返回的是那条原始记录的 id/seq/summary——不是重新生成的。
  • 错误响应形状固定：{"ok":false,"error":"invalid_credential","hint":""}——hint 永远是字符串，没有提示时是空串而不是 null；429 另外带一个 Retry-After 响应头。任何错误都不会回显你提交的字段值（防泄露、防枚举）。

错误码

HTTPerror什么时候该怎么做
400invalid_paramchannel/secret 缺失、content 空、images 超条数或非 http(s)、body 不是合法 JSON修脚本，重试没有意义
401invalid_credential频道不存在与密钥错共用这一句话——不给枚举频道号码留缝隙核对频道号与密钥；连错 5 次会触发锁定
403channel_locked凭据错误累计到阈值被锁（默认 5 次 / 5 分钟窗口，锁 5 分钟），或频道已归档等窗口过去；归档则这个频道不会再开
403forbidden频道开了"只允许白名单发送者"，而这个 sender_id 不在名单里去客户端频道 →「发送者白名单」加进去

429rate_limited来源 IP / 频道 / 日配额任一超限。hint 是可重试秒数（频道与 IP 是 60，日配额是 86400）按 hint 退避；日配额只能等次日

500—服务端异常响应不带 stacktrace 与 message，看服务端脱敏日志（正文不会在里面）

幂等：msg_key

同一频道内相同 msg_key 重复提交，服务端直接返回原结果：不重复入库、不重复通知、不重复抓图。给任何会重试的投递方（Alertmanager、队列消费者、CI runner）都该带上它。

# 用告警的 fingerprint 当幂等键，重启/resend 风暴就不会刷屏
"msg_key": "{{ .CommonLabels.alertname }}-{{ .CommonLabels.instance }}"

不传 msg_key 就是纯"至多一次入库"：网络超时后你自己重试，很可能落两条。

时间戳 ts

  • 省略或 ≤0 → 用服务端接收时间。
  • 秒或毫秒都收（< 1e11 视为秒并自动乘 1000）——这是对外形状，两种都得接。
  • 越出 ±300s 的 ts 一律回落到服务端时间。消息落在时间线哪一格是事实，不该由提交方说了算：第三方脚本的时钟漂移、甚至一个随手填的年份，都会把消息甩到几天前，让"最新一条"永远不是最新。

因此 ts 只适合表达"事件在 5 分钟内发生的哪一刻"，不适合回填历史。要回填历史，就把 ts 省略掉、把真实时间写进正文。

strict_auth：可选的 HMAC 签名

默认关闭——频道密钥本身已经是"知道就能写"的凭据。开启后（频道治理 →「强制校验 sender」）请求必须带 ts/nonce/sign：

canonical = channel + "\n" + ts + "\n" + nonce + "\n" + sha256_hex(content)
sign      = hex( HMAC-SHA256( key = secret, data = canonical ) )
  • sha256_hex(content) 是正文 UTF-8 字节的小写十六进制 sha256——签的是正文本身，所以中间人改不了内容也伪造不了来源。
  • ts 必须存在且在 ±300s 内；nonce 10 分钟内不得重复（服务端有去重缓存）。
  • 签名不匹配回 401 invalid_credential，与密钥错同一句话——签名校验失败本身也不该成为可探测信号。
  • 比较是常量时间的，不给侧信道留缝。
import hashlib, hmac, json, time, urllib.request, uuid

secret, channel = "<频道密钥>", "12345678"
content = "构建失败：unit-test 3 个用例不过"
ts, nonce = int(time.time() * 1000), uuid.uuid4().hex

canonical = "\n".join([channel, str(ts), nonce,
                       hashlib.sha256(content.encode()).hexdigest()])
sign = hmac.new(secret.encode(), canonical.encode(), hashlib.sha256).hexdigest()

body = json.dumps({"channel": channel, "secret": secret, "content": content,
                   "type": "text", "level": "error", "sender_id": "ci",
                   "ts": ts, "nonce": nonce, "sign": sign}).encode()
req = urllib.request.Request("https://push.example.com/message", body,
                             {"Content-Type": "application/json"})
print(urllib.request.urlopen(req).read().decode())

图片：images[] 与 sender_avatar

两个字段传的都是外链，图片本体一律由服务端抓回来转存进对象存储。桶是私有的，第三方给的 URL 不会出现在客户端里。

入站校验

SSRF 闸

默认 禁抓私网与 100.64.0.0/10（CGNAT，Tailscale 就在这段里）。要让服务端去抓内网图片，必须把 host 显式加进 pb.media.allow-hosts——它是精确 host 或 host:port，不是前缀匹配，留空就是"当前图片来源全为公网"。

异步与状态

  • 200 绝不等抓图。槽位先落 pending，抓取线程池排队（等待位有上限 pb.media.queue-capacity，排不进去当场记 queue_full 并照常下发消息——绝不无界堆积，也绝不让消息卡在"永远没有第一帧"）。
  • 带图的消息进合并窗口（pb.notify.media-wait，默认 3s）：图文齐全只发一条帧，纯文字立刻下发。
  • 重试：pb.media.retry-max 是含入站首次在内的总抓取次数（默认 3），用完就停在 failed 不再打扰；两次尝试至少隔 retry-interval。
  • 删除后对象不会立刻真删：delete-grace（默认 168h）之后由巡检真删，状态从 deleted 变 purged。探针 ⑯ 就是靠这个变化确认桶里的字节真被删掉了。

图片是"尽力而为"的附件

正文可用性永远优先：抓图失败不会让消息消失，坏头像也不会拒绝整条投递。客户端把失败的格子画成「已失效」，而不是留一个转圈。

闸门是进程内 60 秒滚动窗口，不是分布式限流

多实例部署时，实际放行量约等于「单实例阈值 × 实例数」。这一版没有引 Redis 做全局限流：自托管的常态是单实例，多实例部署时把它当成"每实例各自的保护"就够，别把它当成对外承诺的配额。

每道闸门被拒都有指标：pushbox.ingest.rate_limited{gate=channel|ip|device}、pushbox.ingest.quota_exceeded{type=daily}、白名单拒绝计数等，见服务端 README 的指标表。
