使用说明

使用说明

PushBox 不是聊天软件，它是一条单向的通知通道：你在 Grafana、脚本、CI 里 POST /message，消息就出现在手机与 PC 上。所以"用一遍"只有四步：连上服务端 → 建频道 → 往频道号发一条 → 在会话线里看它。

整体形状

① 设备注册App 首次启动填服务器地址，本机生成两对密钥，服务端只存公钥，回一份恢复码
② 建频道频道号（对外投递地址）+ 密钥（只显示一次）
③ 第三方 POST唯一一个写入口，凭据全在请求体里
④ 长连接下发加密帧到每一台设备，出通知、进会话线

一句话理解"频道"

频道 = 一个投递入口 + 一套治理位（提醒强度上限、速率、图片数、白名单…）。它不是收件人，也不属于某个人；同一 Space 下的所有设备都会收到同一个频道的消息——除非某台设备开了「只接收已接入的频道」。会话线则是"频道 × 发送者"的交集——同一个告警频道里，Grafana 和 Jenkins 会是两条独立的会话。

① 第一次打开（Android）

首启页标题是「连接你的 PushBox」，只有三个输入：

字段填什么注意
服务器地址https://push.example.com（或联调时的 http://10.0.2.2:8080）只填 scheme+host[:port]，不要带路径。下方「最近使用」会记住打过的地址
设备名称这台手机叫什么会出现在其他端的「设备与同步」列表里
恢复码（可选）已有空间时填它留空就是创建我的空间；填了就是我有恢复码加入

两对密钥（X25519 用于加密、Ed25519 用于签名）在本机生成，私钥永不离开这台设备；服务端只拿到公钥，注册响应里的 token 等价于账号口令，所以它连响应体一起过密封盒加密。

恢复码那一页不能跳过

它是找回全部历史与设备的唯一凭据，服务端只存它的哈希——丢了没有任何找回途径，也没有"忘记密码"。抄下来（或让另一台设备扫屏上的二维码）再点「我已抄好」。泄露它等于任何人可读你的消息。

注册成功后紧接着是「让消息随时到达」引导页（见后台常驻）——在国产 ROM 上，这一步比任何功能都更决定"能不能收到"。

② 建频道，拿到接入凭据

「我的」→「接入」→「新建频道」→ 填频道名称（留空则用设备名）→ 创建。紧接着出现「接入信息（密钥只显示这一次）」卡，三项都能一键复制：

  • 频道号：8 位数字，第三方投递时填进 channel 字段。
  • 频道密钥：填进 secret。只在创建与重置这两次响应里出现，列表接口永远不返回它。
  • 接入命令：一整行可直接粘进第三方软件的 curl。

PC 端的「频道」页是同一套东西（新建频道、复制密钥、复制整行 curl、治理设置、容量报表、白名单），不需要"先在手机上建好再同步"。

频道上能做的四类操作

操作后果可撤销?
重置密钥旧密钥即刻作废，第三方必须换新的（用旧的会收到 401）；频道号、历史都不动否
换发新频道号旧号作废（往旧号投会 401/404），历史随迁、密钥不变；本机该频道下的会话设置会丢失并重新拉历史否
频道静默消息照收、照入库、照下发，只是帧里的 notify 关掉——历史不会因为静默而消失，那是"屏蔽"不是"静音"是
归档停止接收新消息（第三方投递收到 403），历史消息保留否
清空删除该频道下全部历史消息与图片，各端同步移除；频道本身与接入地址保留否

「治理设置」里可以改：提醒强度上限、单次最多图片数、每分钟条数上限、单条正文最大字节、每日条数/图片/字节上限、强制校验 sender、只允许白名单发送者。填 0 表示沿用服务端默认值；未提交的项不会被静默清空。

加入别人建的频道（同 Space 内）

同一 Space 里，一台设备建的频道默认每台设备都收得到。想只看其中几条，就打开「只接收已接入的频道」（Android 在「我的 → 接入」页，PC 在设置 → 频道，默认关）。这开关是逐设备的：手机上开不影响 PC，PC 上开也不影响手机；打开它不会顺手把已有频道批量退订。

开了之后，没接入的频道照投、照入库，只是不再下发到这台设备，会话列表里也就不会出现它。要收就在同一页填「加入频道」那两格，只填两项：

  • 频道号：8 位数字。只能接本 Space 内可见的频道——跨 Space 一律 404，密钥对上也一样。
  • 频道密钥：32 位，创建/重置时给出的那份。填错回 401，且不计入频道的失败次数（它是确认号码写对了，不是读侧的暴破面）。

频道详情里的「接入」/「取消接入」按钮作用在同一件事上——PC 上取消接入不需要再输密钥，号码已经在你选中的那一行了。退出接入随时可点、可重复点（没接入过也回成功，只是 removed=false）；加入同样幂等。列表里每一条都带已接入 / 未接入标记，开关的当前值以服务端回显为准，不看本地缓存。

接入是投递过滤器，不是权限边界

密钥证明的是"你拿得到这个频道的凭据"，不是"你是这个 Space 的成员"——能接入的前提本来就是你已经在这个 Space 里。所以它只能减少这台设备收到的内容，不可能让它看到别人的 Space。

过滤对实时帧、断线补发、REST 历史、搜索四处同时生效；一旦接入某个频道，它接入之前的历史也一并放开（过滤按频道，不按接入时间）。所以开着过滤又一条都没接入＝这台设备收不到任何消息，两端都会在这一状态把话直说。

自己建的频道在创建那一刻自动接入，所以不会出现"开了过滤结果把自己新加的频道静音了"这种静默失效。

③ 往频道发第一条消息

把接入信息里那行 curl 跑一次就行（完整字段表见入站 API）：

cat > payload.json <<'JSON'
{
  "channel": "12345678",
  "secret": "<频道密钥>",
  "type": "markdown",
  "level": "error",
  "sender_id": "grafana",
  "sender_name": "Grafana 告警",
  "title": "node-3 CPU 持续 > 90%",
  "content": "### 触发规则\n`HighCpu` 5 分钟平均值 **93.2%**\n- 面板：https://grafana/d/ab12\n- 处理：先看 `top`，再决定是否重启采集器"
}
JSON

curl -sS https://push.example.com/message \
  -H 'Content-Type: application/json' \
  --data-binary @payload.json

返回的是受理回执，不是"客户端已收到"：

{"ok":true,"id":"01J8ZK3Q7M2XW4V9HTNBSFY6PA","seq":1042,
 "summary":"node-3 CPU 持续 > 90%｜### 触发规则 `HighCpu` 5 分钟平均值 …",
 "media_status":"none","media_count":0,"level":"error"}
  • summary 由服务端生成（标题 + 正文截断），客户端通知栏直接用，不用再算一遍。
  • level 回显的是频道 max_level 向下截断后的实际生效值——你传 error、频道上限是 warning，这里就回 warning。
  • 带 images[] 时 media_status 是 pending，抓取是异步的，200 绝不等抓图（第三方超时普遍 5–10s）。
  • seq 是全 Space 单调递增的水位号，客户端靠它做补拉与已读游标。

手机锁屏上大概一秒内就该出现通知（同机/同局域网 MySQL 实测端到端 49ms）。如果没出现，先回来看后台常驻，再怀疑链路。

会话线上的操作（长按）

  • 置顶 / 取消置顶：只影响本机排序。
  • 免打扰 / 取消免打扰：消息照常进来，角标也不计它——静音的会话不该在图标上催你。
  • 重命名：只改本机显示名，服务端不知道。
  • 设头像：从相册选一张，只存本机。
  • 锁屏隐藏内容：锁屏上只显示"收到 1 条新消息"。
  • 清空聊天记录：本机即刻清空，同时通知服务端落 tombstone 同步到其他端；这一条是不可撤销的跨端操作。

对话页里的操作

  • 筛选：全部 / 未读 / 已读，再点一下提示条回到全部。
  • 在会话中搜索：与筛选正交（可以同时"只看未读"再搜），命中显示"命中 N 条"，点一条结果会滚到并高亮那条消息。
  • 长按消息：复制文本 / 保存图片 / 查看原始 JSON / 删除。删除会广播 tombstone，其他端同一秒消失。
  • 展开全文：长正文在帧里被截断时（truncated），点它按 id 从服务端取未截断的全文。
  • 正文支持一个克制的 Markdown 子集：标题、粗体/斜体、行内代码、代码块、有序/无序列表、引用、链接、表格。不支持图片语法与嵌套列表——渲染器要能被单测断言，越简单越可靠。

通知与打扰

打扰程度由三处共同决定，越靠后越优先：

开关在哪语义
level + 频道 max_level服务端info / warning / error，服务端向下截断后写进帧，客户端按它映射通知渠道强度
新消息通知设置 → 通知关掉后消息仍会接收，只是不再弹通知
静默时段设置 → 通知时段内非紧急消息只进通知栏，不响铃、不横幅；error 级别仍可打扰
会话免打扰长按会话只影响这一条会话线，且不计入角标
频道静默频道治理整个频道不再弹通知，历史照常

通知里会带发送者头像（服务端转存的那份）；大图文通知在图片就绪后补上。锁屏隐藏内容的那条会话，锁屏只显示"PushBox · 收到 1 条新消息"。

一个频道，两台设备同时收到

能，前提是这两台是同一个 Space 里的两台设备。第三方的那一发 POST /message 只让消息落库一次（一个全局 seq），随后服务端遍历这个 Space 里每一条在线连接，各自用它自己的会话密钥封一份发出去——Android 与 PC 拿到的是同一句明文、两条互不相干的信封，几乎同一秒出现在两台机器上。服务端日志里那句 消息已下发 … 在线下发=2，数的就是这里发出去的连接数；它是"两端到底通不通"最省事的自查处。

  • 身份不能拷。会话表按设备身份唯一，同一个 device_id 的新连接会直接顶掉旧的那条。把一端的身份文件复制到另一台机器，得到的不是"两台设备"而是"两台抢一条连接"——症状是只有一端收得到、且随启动顺序漂移，全程不报错。加第二台的正当路径是首启时把恢复码交出去——Android 是那个可选的「恢复码（可选）」输入框，PC 是「我有恢复码，加入已有空间」那一屏——让它注册成另一个 device_id。
  • 唯一会让两端不一致的功能是「只接收已接入的频道」：它是逐设备的过滤器（见上面），默认关，所以开箱即用就是两端全收；某一端打开它又没接入这条频道，就只有那一台静默，另一端照常。
  • "同时"只对当时在线的连接成立。另一端离线期间的消息不会丢，它在重连时按自己的游标补拉回来；Android 的省电/轮询模式下不等长连接，最快 15 分钟一轮。
  • 通知各弹各的，红点是共享的。level 与频道静默共同决定的 notify 位是频道级、在受理时就定下，所以两端一起响或一起不响；而"会话免打扰"是本机判断，只让那一台不弹，消息照常入库、红点照常。任何一端读过之后 read 帧会广播给同组其他端，红点约 30–50ms 内一起灭。

多端同步：已读、删除、断线

  • 已读是游标，不是布尔。打开会话即 PUT /api/v1/state/read 把该会话的 last_read_seq 推上去，服务端再向同组其他端广播 read 帧——所以手机读完，PC 的红点约 30–50ms 内消。
  • 游标只增不减：服务端对已读是"后写覆盖"，客户端必须自己守住单调，否则一个迟到的旧帧会把已读退回去。
  • 删除是 tombstone：单条按 id，整会话/整频道按 scope。清空走"一条 UPDATE 标完 + 一条 scope 帧"，逐条删除是错的（可能上千条，既打爆 SQL 往返也让其他端收到上千帧）。
  • 断线重连：连接带上 since_seq，服务端循环补发到追平后回一个 resume_ok；落后超过 2000 条则回 resume_gap，让客户端改走 REST 全量补拉。补发的帧 notify=false，不会重复弹通知。
  • 离线那台什么时候补齐：PC 只有"重连 + 上面那条补拉循环"这一条路，没有轮询兜底——它断网期间靠指数退避（1s→60s）反复重试，链路一活就把缺的补齐。Android 的省电/轮询模式才是另一套：那时不挂长连接，由 WorkManager 每 15 分钟发一轮 REST（SyncWorker），换来的是实时性，界面上有一条"消息可能延迟"的提示条。

图片会发生什么

images[] 传的是外链，图片本体由服务端抓回来存进对象存储；桶是私有的，客户端只从 GET /api/v1/media/{id}/{idx} 取字节。链路是：入站先落 pending 槽位 → 抓取线程下载（SSRF 闸默认禁私网）→ 生成 ≤512px 缩略图 → PutObject → 回写 → 合并窗口（默认 3s）到齐后发一条图文齐全的消息帧。

格子状态你在客户端看到
pending占位灰块，就绪后由 media_ready 帧原地补图，不重复通知
ready正常显示；列表用 size=thumb，点开用 full；没有缩略图时服务端直接降级发原图，客户端不用写"404 再请求一次 full"的分支
failed / queue_full红字「已失效」格——重试次数（默认 3）用完就停在这里，不再打扰
deleted / purged消息被删后槽位转 deleted；过了宽限期（默认 168h）真删对象、转 purged，此时"再重试也不会有图"

图片是"尽力而为"的附件，不是承诺

消息正文的可用性永远优先于图片：抓图失败不会让消息消失，坏头像也不会拒绝整条投递（content 才是必填）。要"图必须到位"，那需要的是对象存储级的可靠性设计，不在这条通道的范围内。

让消息随时到达（Android）

这一节是 Android 端最容易"看起来坏了"的地方：Android 的后台限制不是 bug，是设计。PushBox 靠前台服务 remoteMessaging 维持长连接，但 ROM 会积极冻结后台——保活靠系统白名单，不是我们自己硬拉服务。

设置 →「后台常驻」四项：

项说明
忽略电池优化加入白名单后待机才不会冻结通道；状态显示「已允许后台运行 / 仍可能被系统休眠冻结」
通知渠道设置去系统设置确认各会话渠道的提醒强度（系统层面关掉，App 里怎么配都没用）
自启动与后台锁定国产 ROM 需在应用信息里允许自启动；在最近任务里下拉/长按 PushBox 卡片点锁形图标，避免一键清理误杀
极致省电轮询模式关闭常驻长连接，改为约每 15 分钟批量补拉。更省电，但消息延迟到达；开启后顶部会有横幅提示

省电模式本身也会被察觉：系统处于省电模式时顶部出现「后台通道可能被冻结，通知可能延迟」的横幅——与其让用户以为是推送丢了，不如说明当前处于什么状态。

PC 端（Windows）

首启窗口与手机同构：服务器地址 + 设备名称，「创建新的个人空间」或「我有恢复码，加入已有空间」。PC 上没有恢复码——恢复码只在手机上「我的 → 设置 → 设备与同步」里显示和出码，所以要先在手机上打开二维码让 PC 扫，或抄文本。

主界面是两栏（默认 1080×680，可以拖到很窄）：左栏会话列表 + 顶部搜索（Ctrl+F），右栏对话区。顶栏左侧是连接状态，右侧是「设置」。

  • 关闭窗口 = 最小化到托盘（可在设置里改），托盘菜单与设置页是同一份开关，改哪边都一样。
  • 开机自启默认关——自启是"装完就多了一个后台进程"，该由用户明确点一下。
  • 静默时段与"新消息通知"在设置 → 通知；时段内只有 error 还会出声。
  • 频道管理与手机功能对齐：新建频道、接入/退出频道、复制密钥/频道号/整行 curl、提醒强度上限、治理设置、容量报表、发送者白名单、重置密钥、换发新频道号、轮换恢复码（只发起，显示仍以手机为准）、设备列表与吊销。
  • 已读、删除、清空的操作语义与手机完全一致——两端走的是同一套 REST 与同一套帧。

换机、加设备、吊销

  • 一个 Space 最多 5 台设备。满了注册会直接 409 device_limit_reached，得先吊销一台。
  • 换机 / 加第二台：新设备首启填恢复码（或扫码）。加入之后这台设备不会再显示恢复码——它只有"已经登录的那台"能重新导出。
  • 吊销：该设备 token 即刻失效、在线连接被当场踢掉，其余端即刻刷新设备列表。
  • 轮换恢复码：旧码即刻失效，已登录的设备不受影响；新码只显示这一次。
  • Android 的「更换服务器」会清空本机身份、会话与消息并用新地址重新注册——它是"换一台服务端"，不是"改个域名"。

用之前要知道的边界

它不是聊天软件

客户端没有发送口。第三方只能 POST /message，你不可能从手机回一条消息。想做双向，得自己再加一个写入服务端。

服务端明文存库

加密只做"服务端 → 客户端"这一跳，为的是能全文搜索。能读到数据库的人=能读到全部消息。所以库不要放公网、账号权限按最小给。

消息永久保留

没有自动过期。跑几年得自己清（或用频道「清空」）。日计数器有回收，消息没有。

管理台是运维视图，不是第二个 App

自带 Web 管理台（跨 Space 看频道/设备/消息、定时推送、吊销设备），接口契约见 管理台 API。但它改不了频道治理位——静音、发送者白名单、日配额、strict_auth、频道号重置仍然只在 App 的「频道治理」里；建频道与重置密钥也只为脚本留了接口，控制台没有按钮。
