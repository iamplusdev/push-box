使用说明

PushBox 不是聊天软件，它是一条单向的通知通道：你在 Grafana、脚本、CI 里 POST /message，消息就出现在手机与 PC 上。用一遍只有四步：设备连上服务端 → 建频道 → 往频道号发一条 → 在会话线里看它。

整体形状

① 设备注册首启填服务器地址，本机生成密钥，服务端回一份恢复码
② 建频道频道号（投递地址）+ 密钥（只显示一次）
③ 第三方 POST唯一一个写入口，凭据全在请求体里
④ 长连接下发加密帧到每一台设备，出通知、进会话线

一句话理解「频道」

频道 = 一个投递入口 + 一套治理位（提醒强度上限、速率、图片数、白名单）。它不是收件人：同一 Space 下的所有设备都会收到同一频道的消息，除非那台设备开了「只接收已接入的频道」。

会话线是「频道 × 发送者」的交集：同一个告警频道里，Grafana 和 Jenkins 是两条独立的会话。

① 第一次打开（Android）

首启页标题是「连接你的 PushBox」，只有三个输入：

字段填什么注意
服务器地址https://push.example.com（联调时 http://10.0.2.2:7404）只填 scheme+host[:port]，不要带路径
设备名称这台手机叫什么会出现在其他端的「设备与同步」列表里
恢复码（可选）已有空间时填它留空就是创建我的空间；填了就是加入已有空间

设备密钥在本机生成，私钥不离开这台设备；服务端只拿到公钥。

恢复码那一页不能跳过

它是找回全部历史与设备的唯一凭据，服务端只存它的哈希——丢了没有任何找回途径，也没有「忘记密码」。抄下来，或让另一台设备扫屏上的二维码，再点「我已抄好」。泄露它等于任何人可读你的消息。

注册成功后紧接着是「让消息随时到达」引导页（见后台常驻）。国产 ROM 上这一步比任何功能都更决定「能不能收到」。

② 建频道，拿到接入凭据

  1. 底栏「频道」→「新建频道」→ 填名称（留空则用设备名）→ 创建 PC 端的「频道」页是同一套功能，不需要先在手机上建好再同步。
  2. 在「接入信息」卡里复制这三样
    • 频道号：8 位数字，第三方投递时填进 channel。
    • 频道密钥：填进 secret。只在创建与重置这两次响应里出现，列表接口永远不返回它。
    • 接入命令：一整行可直接粘进第三方软件的 curl。
  3. 之后要再看密钥，就长按频道 →「复制密钥」 复制的是本机留存的那一份。换过设备或清过 App 数据后这一组会显示「本机没有这份密钥」——此时唯一的出路是重置密钥，再回去改第三方配置。

频道上能做的四类操作

操作后果可撤销?
重置密钥旧密钥即刻作废（用旧的会收到 401）；频道号与历史不动否
换发新频道号旧号作废（往旧号投会 401/404）；历史随迁、密钥不变，本机该频道的会话设置会丢失并重新拉历史否
频道静默消息照收、照入库、照下发，只是不再弹通知；历史不会因静默而消失是
归档停止接收新消息（第三方投递收到 403），历史保留否
清空删除该频道全部历史消息与图片，各端同步移除；频道本身与接入地址保留否

「治理设置」里可以改：提醒强度上限、单次最多图片数、每分钟条数上限、单条正文最大字节、每日条数/图片/字节上限、强制校验 sender、发送者白名单。填 0 表示沿用服务端默认值；没提交的项不会被清空。

加入别人建的频道（同 Space 内）

  1. 打开「只接收已接入的频道」 Android 在「我的 → 接入」页，PC 在设置 → 频道，默认关。这个开关逐设备生效：手机上开不影响 PC。打开它不会把已有频道批量退订。
  2. 在同一页填「加入频道」：频道号 + 频道密钥
    • 只能接本 Space 内可见的频道；跨 Space 一律 404，密钥对上也一样。
    • 密钥填错回 401。
  3. 看列表里的「已接入 / 未接入」标记确认结果 接入、退出都可以重复点：没接入过也回成功，只是 removed=false。

接入是投递过滤器，不是权限边界

它只能减少这台设备收到的内容，不可能让你看到别人的 Space。过滤对实时帧、断线补发、REST 历史、搜索四处同时生效；一旦接入某个频道，它接入之前的历史也一并放开。

所以开着过滤又一条都没接入 = 这台设备收不到任何消息。自己建的频道在创建那一刻自动接入。

③ 往频道发第一条消息

把接入信息里那行 curl 跑一次就行（完整字段表见入站 API）：

cat > payload.json <<'JSON'
{
  "channel": "12345678",
  "secret": "<频道密钥>",
  "type": "markdown",
  "level": "error",
  "sender_id": "grafana",
  "sender_name": "Grafana 告警",
  "title": "node-3 CPU 持续 > 90%",
  "content": "### 触发规则\n`HighCpu` 5 分钟平均值 **93.2%**\n- 面板：https://grafana/d/ab12\n- 处理：先看 `top`，再决定是否重启采集器"
}
JSON

curl -sS https://push.example.com/message \
  -H 'Content-Type: application/json' \
  --data-binary @payload.json

返回的是受理回执，不是「客户端已收到」：

{"ok":true,"id":"01J8ZK3Q7M2XW4V9HTNBSFY6PA","seq":1042,
 "summary":"node-3 CPU 持续 > 90%｜### 触发规则 `HighCpu` 5 分钟平均值 …",
 "media_status":"none","media_count":0,"level":"error"}
  • summary 由服务端生成（标题 + 正文截断），通知栏直接用。
  • level 回显的是频道 max_level 截断后的实际生效值：你传 error、频道上限是 warning，这里就回 warning。
  • 带 images[] 时 media_status 是 pending；回执不等抓图。
  • seq 是全 Space 单调递增的水位号，客户端靠它做补拉与已读。

手机锁屏上大概一秒内就该出现通知。没出现的话先看后台常驻，再怀疑链路。

长按会话能做的事

  • 置顶 / 取消置顶：只影响本机排序。
  • 免打扰 / 取消免打扰：消息照常进来，但不计入角标。
  • 重命名 / 设头像：只改本机显示，不上传。
  • 锁屏隐藏内容：锁屏只显示「收到 1 条新消息」。
  • 清空聊天记录：本机即刻清空，同时同步到其他端；不可撤销。

对话页里

  • 在会话中搜索：点顶栏放大镜，命中显示「命中 N 条」，点一条结果会滚到并高亮那条消息。
  • 时间线没有全部 / 未读 / 已读筛选：往上滚看历史，找内容用搜索。
  • 长按消息：复制文本 / 保存图片 / 查看原始 JSON / 删除。删除会同步到其他端。
  • 展开全文：正文过长被截断时（truncated），点它按 id 从服务端取全文。
  • 正文支持的 Markdown：标题、粗体/斜体、行内代码、代码块、有序/无序列表、引用、链接、表格。不支持图片语法与嵌套列表。

通知与打扰

打扰程度由下面几处共同决定，越靠后越优先：

开关在哪语义
level + 频道 max_level服务端info / warning / error，服务端截断后写进帧，客户端按它映射通知强度
新消息通知设置 → 通知关掉后消息仍会接收，只是不再弹通知
静默时段设置 → 通知时段内非紧急消息只进通知栏；error 级别仍可打扰
会话免打扰长按会话只影响这一条会话线，且不计入角标
频道静默频道治理整个频道不再弹通知，历史照常

通知里会带发送者头像；大图文通知在图片就绪后补上。开了「锁屏隐藏内容」的会话，锁屏只显示「PushBox · 收到 1 条新消息」。

一个频道，两台设备同时收到

能，前提是这两台是同一个 Space 里的两台设备。第三方一发 POST /message 只让消息落库一次，服务端再给每条在线连接各封一份发出去——Android 与 PC 拿到同一句明文、两条互不相干的信封，几乎同一秒出现在两台机器上。

  • 设备身份不能拷。同一个 device_id 的新连接会直接顶掉旧的那条：把身份文件复制到另一台机器，得到的不是两台设备而是两台抢一条连接，症状是只有一端收得到、且随启动顺序漂移，全程不报错。加第二台的正当路径是首启时填恢复码，让它注册成另一个 device_id。
  • 「同时」只对当时在线的连接成立。另一端离线期间的消息不会丢，重连时按自己的游标补拉；Android 的省电轮询模式下最快 15 分钟一轮。
  • 通知各弹各的，红点是共享的。级别与频道静默决定的 notify 是频道级，两端一起响；「会话免打扰」是本机判断，只让那一台不弹。任何一端读过之后，另一端的红点随即灭掉。
  • 唯一会让两端收得不一样的是「只接收已接入的频道」：它逐设备生效，默认关。

多端同步：已读、删除、断线

  • 已读是游标，不是布尔：打开会话即把该会话的 last_read_seq 推上去（PUT /api/v1/state/read），服务端再向同组其他端广播 read 帧——手机读完，PC 的红点随即消。
  • 游标只增不减：自研客户端要自己守住单调，否则一个迟到的旧帧会把已读退回去。
  • 删除是 tombstone：单条按 id，整会话/整频道按 scope；其他端同一秒消失。
  • 断线重连：连接带上 since_seq，服务端循环补发到追平后回一个 resume_ok；落后超过 2000 条回 resume_gap，客户端改走 REST 全量补拉。补发的帧 notify=false，不会重复弹通知。
  • 离线那台什么时候补齐：PC 只有「重连 + 补拉」这一条路，断网期间按指数退避（1s→60s）反复重试。Android 的省电/轮询模式不挂长连接，改为约每 15 分钟发一轮 REST，界面上会有「消息可能延迟」的提示条。

图片会发生什么

images[] 传的是外链：服务端把图抓回来存进你自己的存储，客户端只从 GET /api/v1/media/{id}/{idx} 取字节。链路是：入站先落 pending 槽位 → 抓取 → 生成缩略图 → 存好回写 → 到「图文合并窗口」（默认 3s）后发一条图文齐全的消息帧。

格子状态你在客户端看到
pending占位灰块，就绪后原地补图，不重复通知
ready正常显示；列表用 size=thumb，点开用 full；没有缩略图时服务端直接发原图，客户端不用写重试分支
failed / queue_full红字「已失效」格——重试次数（默认 3）用完就停在这里
deleted / purged消息被删后槽位转 deleted；过了宽限期（默认 168h）真删对象、转 purged

图片是「尽力而为」的附件，不是承诺

正文永远优先：抓图失败不会让消息消失，坏头像也不会拒绝整条投递（只有 content 必填）。

让消息随时到达（Android）

这是 Android 端最容易「看起来坏了」的地方：系统会积极冻结后台，保活靠系统白名单，不是应用自己硬拉服务。

设置 →「后台常驻」四项：

项说明
忽略电池优化加入白名单后待机才不会冻结通道；状态显示「已允许后台运行 / 仍可能被系统休眠冻结」
通知渠道设置去系统设置确认各会话渠道的提醒强度：系统层面关掉，App 里怎么配都没用
自启动与后台锁定国产 ROM 需在应用信息里允许自启动；在最近任务里长按 PushBox 卡片点锁形图标，避免一键清理误杀
极致省电轮询模式关闭常驻长连接，改为约每 15 分钟批量补拉。更省电，但消息延迟到达；开启后顶部有横幅提示

系统处于省电模式时，顶部会出现「后台通道可能被冻结，通知可能延迟」的横幅。

PC 端（Windows）

  • 首启与手机同构：服务器地址 + 设备名称，「创建新的个人空间」或「我有恢复码，加入已有空间」。PC 上不显示恢复码——它只在手机的「我的 → 设置 → 设备与同步」里出码，所以先让手机出二维码或抄文本。
  • 主界面两栏：左栏会话列表 + 顶部搜索（Ctrl+F），右栏对话区。顶栏左侧是连接状态，右侧是设置。
  • 关闭窗口 = 最小化到托盘（可在设置里改）；托盘菜单与设置页是同一份开关。
  • 开机自启默认关。
  • 频道管理与手机功能对齐：新建频道、接入/退出、复制密钥/频道号/整行 curl、治理设置、白名单、重置密钥、换发新频道号、设备列表与吊销。
  • 已读、删除、清空的操作语义与手机完全一致。

换机、加设备、吊销

  • 一个 Space 最多 5 台设备：满了注册会回 409 device_limit_reached，得先吊销一台。
  • 换机 / 加第二台：新设备首启填恢复码（或扫码）。加入之后这台设备不再显示恢复码——只有已登录的那台能重新导出。
  • 吊销：该设备 token 即刻失效、在线连接被当场踢掉，其余端即刻刷新设备列表。
  • 轮换恢复码：旧码即刻失效，已登录的设备不受影响；新码只显示这一次。
  • Android 的「更换服务器」会清空本机身份、会话与消息并用新地址重新注册——它是换一台服务端，不是改个域名。

用之前要知道的边界

它不是聊天软件

客户端没有发送口。第三方只能 POST /message，你不可能从手机回一条消息。

服务端明文存库

加密只做「服务端 → 客户端」这一跳，为的是全文搜索。能读到数据库的人＝能读到全部消息：库不要放公网，账号权限按最小给。

消息永久保留

没有自动过期。要清理就自己清，或用频道「清空」。

管理台是运维视图

自带 Web 管理台（看频道/设备/消息、定时推送、吊销设备），契约见 管理台 API。但它改不了频道治理位：静音、白名单、日配额、换发频道号仍然只在 App 的「频道治理」里。
