概览

把告警、CI、脚本的消息，推送到你自己的设备上

一条 POST /message 投进服务端，PushBox 负责存下来、抓图转存、加密下发——你的 Android 手机与 Windows PC 几乎同时收到通知。不接厂商推送、不经第三方转发，消息与图片全在你自己的机器上。

约 50 ms受理到通知到账（服务端与 MySQL 同机）
3 端Java 服务端 · Android Compose · Windows WPF
0需要额外账号的服务依赖：只要 MySQL 8，图片落本地目录或对象存储

一条消息走过的路

校验通过就立刻回执，抓图和下发都在回执之后——第三方等不起的那几秒不由它承担。

你的程序Grafana、CI、cron、内网服务，只需一个频道号 + 密钥
受理校验凭据、幂等、分配 seq、生成摘要，立即 200
抓图转存外链图片并发抓取 → 缩略图 → 存进你的存储
加密下发每台设备自己的会话钥加密同一帧，多端同时到达
客户端入库、出通知；一端点进会话，另一端红点随即消失

三端各自是什么

Java 服务端

收消息、存 MySQL、抓图转存、加密下发。管理台就在它的根路径 / 上。

Android

Compose 客户端：长连接接收、系统通知、多端已读同步。需要一次保活设置。

Windows

WPF 桌面客户端：托盘常驻，可选开机自启。数据与身份都在当前用户目录下。

信任边界：为什么服务端是明文

服务端到设备这一跳是加密的；服务端库里存的是明文。这是唯一需要记住的边界。

明文换来了什么

全文索引能命中正文、服务端能生成摘要、能替你抓取外链图片。这三件事都要读得到内容。

到设备这一跳加密

每台设备一对 X25519 + Ed25519；帧走 HKDF 派生的 AES-256-GCM 通道，REST 响应走一次性 sealed-box。中间人拿不到正文。

密钥只能写不能读

拿到 secret 能往这个频道推，但读不到任何历史。读历史要设备密钥或恢复码。

生产环境请上 HTTPS。帧加密补的是链路，TLS 补的是「服务端本身可信」，两者互不替代。证书做法见 安装与部署。

功能

图文同帧

外链图片由服务端抓取、转存，在合并窗口（默认 3s）内把图文并进同一条消息帧下发。

多端同时 + 已读同步

同一条消息给每台在线设备各封一份信封，手机与 PC 几乎同一秒到账。游标只增不减，一端已读不会把另一端的红点点亮回去。

全文搜索

MySQL ngram 全文索引加客户端本地索引两段合并，输入即查，命中可定位到那一条消息。

频道治理

按频道限级别、图片数、正文长度、频率与配额，支持白名单发送者。每台设备还能只接收自己接入的频道。

断线不丢

重连带 since_seq，服务端按游标循环补拉，追平才回 resume_ok；落后过多改走 REST 全量拉。

换机找回

一个恢复码加入同一个 Space 并回放全部历史。恢复码可随时轮换，旧码立即失效。

三分钟跑起来

  1. 起服务端：只要本机有一个 MySQL 8 
    JAVA_HOME=/path/to/jdk-21 mvn -B -DskipTests package
bash infra/run-dev.sh                                 # 监听 7404
# 第一次启动没有配置文件，它自己开一个安装页：浏览器打开 http://127.0.0.1:7404/ 填库地址与口令，
# 提交后同一个进程接着启动，不用重启；就绪后页面自动跳到管理台
    建库、Docker 部署、HTTPS 的完整步骤见 安装与部署。
  2. 确认它起来了 
    curl -sS http://127.0.0.1:7404/healthz
    期望 {"ok":true,"db":"up","storage":"up",...}；任一项不通回 503。这条只在本机直连时给得出 200——容器部署时 /healthz 只认容器环回，验收方式见 安装与部署。
  3. 在管理台建频道，发第一条消息 
    curl -sS http://127.0.0.1:7404/message \
  -H 'Content-Type: application/json' \
  --data-binary @payload.json
    入站接口是 POST {base}/message，不在 /api/v1 下，凭据写在请求体里。payload 形状见 首页示例 与 入站 API。
  4. 回来看这一行的 code 200 表示已入库并排进下发，手机与 PC 同一秒出通知；401 是频道号或密钥不对；429 是超过了频道的限速。

常见问题

能不能当个人聊天工具？

不能。它是单向接收的：只有第三方 POST /message 写入，客户端没有发送框。

手机和电脑能同时收到同一条推送吗？

能，只要它们是同一个 Space 里的两台设备。身份文件不要互拷：同一个 device_id 的新连接会顶掉旧的，症状是只有一端收得到且全程不报错。细节见 使用说明。

服务端挂了会丢消息吗？

没拿到 200 的那次 POST 就是没受理，重试请用同一个 msg_key（服务端按它幂等）。已受理的消息永久保留在库里，设备重连后按游标补齐。

为什么中文正文被截断了？

单帧超过 32KB 时服务端按码点裁剪正文并置 truncated:true，客户端用 GET /api/v1/messages/{id} 回捞全文。

能在公网上裸跑 HTTP 吗？

不建议。帧加密保证链路读不到正文，但 secret 是在 body 里明文送的。请上 HTTPS，或把入站口只开在内网。
