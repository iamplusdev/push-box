安装与部署

安装与部署

先跑服务端，再装两端。三端各自都可以独立构建——服务端与 Android/Windows 之间没有构建依赖，只有协议依赖。

前置要求

组件用途要求
JDK构建与运行服务端21（core 编译下限 17）
MavenJava 侧构建3.9+
MySQL主存储与全文索引8.0 / 8.4，且 ngram_token_size=2
对象存储图片与头像转存任意 S3 兼容（本项目实测 RustFS）
Node.js验收探针18+，探针目录里 npm install 一次即可
Android SDK客户端构建compileSdk 36、AGP 9.2.1、Gradle 9.6.1
.NET SDKPC 客户端8.0，仅 Windows（Win10 19041 起）；打包另需 Inno Setup 6

服务端

① 建库

表结构交给 Flyway（首次启动自动执行 V1…V5），但库和账号要先建好。中文全文检索的前提是 ngram_token_size=2——它不在默认值上时，建库脚本跑不通或搜索退化成 LIKE。

CREATE DATABASE IF NOT EXISTS pushbox
  CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;
CREATE USER IF NOT EXISTS 'pushbox'@'%' IDENTIFIED BY '<自行生成强口令>';
GRANT SELECT, INSERT, UPDATE, DELETE, CREATE, ALTER, INDEX, DROP, REFERENCES
  ON pushbox.* TO 'pushbox'@'%';        -- Flyway 需要 DDL 权限；只给 pushbox 库，不给全局
FLUSH PRIVILEGES;

-- 确认分词器（8.4.6 与 8.0.46 实测默认已是 2）
SELECT @@ngram_token_size;              -- 期望 2

本机实例上把 'pushbox'@'%' 换成 'pushbox'@'localhost' + 'pushbox'@'127.0.0.1' 更贴切：JDBC 走 TCP 到 127.0.0.1 时 MySQL 认的主机名是 localhost，两个都建才不会因为解析方式而连不上。

② 凭据：只走环境变量

这是一条硬规则。配置文件里出现明文口令就算事故——它会随仓库和 mvn package 打出来的 jar 一起出去。

cp deploy/env/prod.env.example deploy/env/local.env    # local.env 已在 .gitignore
# 要填：PB_DB_PASSWORD、PB_S3_ACCESS_KEY、PB_S3_SECRET_KEY（开 sse-c 再加 PB_S3_MASTER_KEY）

application-dev.yml 里 password: ${PB_DB_PASSWORD}刻意不留默认值：忘了 source 就该启动失败，而不是拿空口令去连库、把配置问题伪装成 Access denied。

③ 对象存储

  • 建一个私有桶（默认名 pushbox）。桶不需要匿名可读——读侧走服务端代理，客户端拿签名 GET 要字节。
  • pb.s3.path-style: true 不是可选项：endpoint 是裸 IP 时虚拟主机风格（bucket.<存储机>:7101）无法解析。
  • 想开桶内加密（SSE-C）：openssl rand -base64 32 生成主钥填进 PB_S3_MASTER_KEY，再 --pb.s3.object-encrypt=sse-c。主钥一旦有对象落库就永不轮换（换了旧封装钥解不开，等于图片全丢）；缺失或长度不对时进程在构造期直接拒绝启动，不会静默写明文。
  • 桶能力回归（可选）：node deploy/probe/rustfs-capability.mjs。

④ 构建与运行

export JAVA_HOME=/path/to/jdk-21        # 机器默认 JAVA_HOME 常常是 JDK 8
mvn -B -DskipTests package              # server/target/pushbox-server-1.1.0.jar
bash deploy/run-dev.sh                  # 默认 8080；脚本自己 source deploy/env/local.env

换端口、改配置一律往后加参数即可（Spring 的命令行覆盖比改 YAML 更适合联调）：

bash deploy/run-dev.sh --server.port=8081 \
  --pb.ws.replay-batch=5 \
  --pb.s3.delete-grace=2s --pb.s3.purge-interval=5s

⑤ 自检

curl -sS http://127.0.0.1:8080/healthz
cd deploy/probe && npm install          # 只需一次（依赖 ws）
node p0-e2e.mjs                         # 默认打 127.0.0.1:8080；末行 N/N 且 0 失败才算这套装对了
PB_BASE=http://127.0.0.1:8081 node p0-e2e.mjs

探针是一个"软件版 Android 设备"：自己生成两把密钥，逐字节复刻握手、签名、帧加密、补拉与频道接入过滤。它跑通之后，客户端侧只剩 UI 与存储，不会再有协议层意外。

⑥ 单元测试的跑法与两个坑

source deploy/env/local.env
mvn -B -pl core,server test             # 260/260（core 38 + server 222）
  • 必须 -pl core,server 同 reactor：单跑 server 会用本地仓库里的旧 core jar，新加的类报 NoClassDefFoundError。
  • 碰库/碰桶的用例挂 @EnabledIfEnvironmentVariable(named="PB_S3_ACCESS_KEY")，忘了 source 就是静默 skip。看到用例总数变小先查环境变量，不要改测试。

生产部署

容器（拓扑 A / B）

deploy/Dockerfile 是多阶段构建（Maven 构建层 → temurin:21-jre 运行层，非 root UID 10001）。docker-compose.yml 给两种拓扑：

拓扑起什么怎么切
A（默认）pushbox-server + caddy把 PB_DB_URL / PB_S3_ENDPOINT 指到已有的那台 MySQL / 桶。不要写 SPRING_DATASOURCE_URL：prod profile 里唯一的映射点是 application-prod.yml，两个名字各声称拥有同一个键时，排查盯 yml 会看不出真实取值来自哪
B（完全独立）再加上 mysql:8.4（带 --ngram_token_size=2）与 rustfs取消 compose 里那两段的注释，地址改回 service-name；嫌手写麻烦可以直接用现成的 docker-compose-wsl.yml
 
cd deploy
cp env/prod.env.example .env            # 填真值；.env 不提交
docker compose up -d                    # 拉 CI 推到 Docker Hub 的镜像
# 想跑自己的代码（fork、离线、改了服务端）：本地构建走本文件的 build: 段，context 是仓库根
docker compose up -d --build
# 监控栈（Prometheus + Grafana）在另一本文件里，要监控才多传一个 -f：
docker compose -f docker-compose.yml -f docker-compose.monitoring.yml up -d
诚实说明

生产这套资产在 2026-10-20 用隔离 project 真起过一次 docker compose up（MySQL / RustFS 复用测试栈），一轮下来撞出并修掉五个"配置里写了、进程不消费"的缺陷——完整清单见 RELEASE-CHECKLIST.md 与 CHANGELOG。还没验过的是另一件事：从 Docker Hub 拉 CI 产物那条路（镜像要等首次 tag 才推），以及真实 TLS/反代前置。第一次上生产仍然请留一次现场验证的余量。

HTTPS 与自签 CA

当前联调走的是裸 HTTP（内网）。生产要么用 Caddy 的 Let's Encrypt，要么走自签根 CA。两端接证书的方式完全不同：

# 在一台"管理机"上跑，不在部署机上跑
PUSHBOX_HOST=pushbox.internal PUSHBOX_IP=<部署机IP> deploy/ca/gen-ca.sh
# 只把 certs/pushbox.crt、pushbox.key、pushbox_ca.crt 拷到部署机的 deploy/certs/
# 根 CA 私钥 pushbox_ca.key 离线保存，绝不进仓库、绝不上部署机
端接法要注意
Android把根 CA 写进 res/xml/network_security_config.xml，release 构建连 http:// 必须失败系统 CA 里的自签证书不应被接受，只信任内置那一份
Windows代码侧零改动（裸 HttpClient / ClientWebSocket），唯一入口是系统根存储：
certutil -addstore -user Root ca.cer		-user = 当前用户，不需要管理员。已经在跑的进程不会回头重读根存储，WS 重连不算新进程 ⇒ 换证书的动作是"退出再起一次"。撤销要按指纹删，按 CN 删会被系统确认框拦掉且没删成
服务端deploy/Caddyfile 里 tls 指向那三本证书，WS 的 read/idle 300s、body 64MB、/actuator 不外泄叶子到期用同一根 CA 重签即可，各端已信任的根不用动

绝不绕过证书校验。全项目 grep 不到 ServerCertificateCustomValidationCallback / DangerousAcceptAnyServerCertificate / ServicePointManager——"没有绕过"是靠没有代码来保证的。

备份

MYSQL_HOST= PB_DB_PASSWORD=... PB_S3_ACCESS_KEY=... \
AGE_RECIPIENT=<age 公钥或 ssh 公钥> [RUSTFS_DATA_DIR=/path/to/data/rustfs] \
  deploy/backup/backup.sh

产物是 pushbox-<UTC>.sql.gz.age（mysqldump --single-transaction，InnoDB 一致性快照，不锁表）与 rustfs-<UTC>.tar.age。因为库里是明文，异地上传前必须加密；桶是唯一图片源，丢了不可恢复。挂 cron / systemd timer 定时跑。

观测

  • GET /healthz 与 /actuator/health|info|prometheus，内网 only（环回 + RFC1918 + 链路本地，公网来源 403），健康详情 show-details: never。
  • Grafana 面板用真实指标名 pushbox_*（含 pushbox_media_queue_depth，这个名字只有一处在写，别双写撞车）。

Android 客户端

cd android
./gradlew :app:assembleDebug
adb install -r app/build/outputs/apk/debug/app-debug.apk

构建前先确认三件事，都是本机踩过的：

  1. android/local.properties 里的 sdk.dir 只能用正斜杠（sdk.dir=D:/Apps/DE/Android/Sdk）。Properties 会把 \A 这类转义吃掉，写成 D:\Apps\... 会让 AGP 拿到 D:AppsDEAndroidSdk，然后在 SdkLocator 抛一个"文件名、目录名或卷标语法不正确"的 IOException——堆栈完全不指向配置文件。
  2. gradle-wrapper.properties 的 distributionUrl 目前指向本地 zip。换机器或要公开构建时改回 https://services.gradle.org/distributions/gradle-9.6.1-all.zip。
  3. settings.gradle.kts 写死了阿里云镜像（全局 ~/.gradle/init.gradle 够不到 pluginManagement），内网构建时按需调整。

连接地址在首启页填：http://10.0.2.2:8080（模拟器访问宿主机）或开发机的局域网地址（真机，须与服务器同网段）。填完走"注册新 Space"或"用恢复码加入"。

装机后建议立即做完 保活引导——这是本项目体验成败的关键，不依赖厂商推送就要付出让 ROM 放行的代价。

Windows 客户端

开发运行

dotnet build windows/PushBox.sln
dotnet run --project windows/PushBox.Windows

安装包（推荐给别人用时）

bash windows/installer/build-installer.sh            # publish + ISCC
bash windows/installer/build-installer.sh --skip-publish   # 只改了 .iss 时重编一次
取舍为什么
self-contained（约 56MB，269 本顶层文件）"装到干净机器"这条验收不接受"请先装 .NET 桌面运行时"。判据只能看包内容：{app} 里 coreclr/hostfxr/hostpolicy/System.Private.CoreLib/PresentationFramework 五本同时存在——本机装了 SDK，所以"这台能不能起"永远为真、证明不了任何事
per-user、无 UAC（PrivilegesRequired=lowest + %LOCALAPPDATA%\Programs\PushBox）这一版要写的 HKCU 与要落的 pushbox.db 本来就在当前用户下。提升成管理员装会把它们落到另一个用户的配置单元里，表现为"通知不弹、托盘点了没反应"，而不是安装报错
版本号只从 csproj 的 <Version> 读出来传进脚本日志里"启动 {Version}"与安装包显示的版本必须是同一个数，两处各写一份就等着有一天对不上
卸载不删 %LOCALAPPDATA%\PushBoxidentity.json 是 DPAPI 绑当前用户的，删掉等于把"重装后认回同一个 Space"堵死；日志与历史库同理

前提：装 Inno Setup 6（脚本会找 ISCC.exe，可用 ISCC= 覆盖）。没装就只跑到 publish 那一步并说明缺什么——这个脚本不会打"假装成功"的包。

数据落在哪

全在 %LOCALAPPDATA%\PushBox\：identity.json（身份与私钥，DPAPI）、pushbox.db（消息/会话/FTS5/游标）、settings.json（四个开关）、logs\（脱敏留痕）。

装完先跑两条体检

# 十二条真服务端判据（服务端要自己起在 8081，别占用你手上的 8080）
dotnet run --project windows/PushBox.LiveCheck -- http://127.0.0.1:8081

# 不连服务端的系统集成冒烟：HKCU 两处真写进去了、托盘真出来了、toast 真弹出来了
dotnet run --project windows/PushBox.Windows -- --notify-smoke notify-smoke.txt

LiveCheck 每跑一次会在开发库里留下一个 Space 和两台设备——这跟探针一样的代价，别在生产库上跑。

端口与交接

  • 服务端默认 8080。联调时代理/脚本一律起在 8081，避免撞上你自己手上那个实例。
  • Caddy 在 compose 里对外是 80/443，/actuator 与指标端口只绑 127.0.0.1。
  • SSRF 闸默认禁抓私网与 100.64.0.0/10。要让服务端去抓内网图片，必须显式把 host 加进 pb.media.allow-hosts（精确 host 或 host:port，不是前缀匹配）。
