安装与部署

安装与部署

先起服务端，再装两端。服务端与 Android、Windows 之间没有构建依赖，只有协议依赖，所以三端可以各装各的。

前置要求

组件要求
MySQL8.0 / 8.4，且 ngram_token_size=2
图片存储本地一个目录，或任意 S3 兼容桶（可选项）
JDK / Maven自己构建服务端时才需要：JDK 21、Maven 3.9+
Docker容器部署时唯一需要的一项
Android8.0 起；直接装发布的 APK
WindowsWindows 10 19041 起，安装包自带运行时

本机起服务端

这条路径不需要桶、不需要 Docker，只要本机有一个 MySQL 8。

  1. 建库和账号；表结构不用管，首次启动会自动建 
    CREATE DATABASE IF NOT EXISTS pushbox
  CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;
CREATE USER IF NOT EXISTS 'pushbox'@'localhost' IDENTIFIED BY '<强口令>';
GRANT SELECT, INSERT, UPDATE, DELETE, CREATE, ALTER, INDEX, DROP, REFERENCES
  ON pushbox.* TO 'pushbox'@'localhost';
FLUSH PRIVILEGES;

SELECT @@ngram_token_size;   -- 期望 2；不是 2 就搜不出中文长句
    JDBC 走 TCP 到 127.0.0.1 时 MySQL 认的主机名是 localhost；连不上的话把同一个账号再建一份 'pushbox'@'127.0.0.1'。
  2. 构建并启动，第一次会停在安装页上 
    export JAVA_HOME=/path/to/jdk-21    # 机器默认的 JAVA_HOME 常常还是 JDK 8
mvn -B -DskipTests package
bash deploy/run-dev.sh              # 监听 7404
    没有配置文件时进程先开一个安装页然后停在那里，不会退出。换端口、改单项配置一律往后加参数：bash deploy/run-dev.sh --server.port=8081 --pb.s3.delete-grace=2s（命令行优先级高于配置文件）。
  3. 在浏览器里填配置 
    http://127.0.0.1:7404/
    填库地址/端口/库名/用户名/密码，勾不勾对象存储，管理台口令。「测试连接」按钮先单独判库，提交整份配置时它还会真连一次库和桶——任何一项不过就不写文件、把原因回给你，所以不存在"配了一半"这种状态。提交成功后配置落进 server/data/config/pushbox.json（已 gitignore，权限 600），同一个进程接着启动，不用重启；之后再启动就直接读文件，安装页不再出现。
  4. 确认它起来了 
    curl -sS http://127.0.0.1:7404/healthz
    期望 {"ok":true,"db":"up","storage":"up","uptime_ms":…}；任一段是 down 时进程回 503。/actuator/health 是另一本形状，只回 {"status":"UP"}（组件明细被 show-details: never 挡住）。
  5. 登录管理台，建第一个频道 浏览器打开服务端根路径 http://127.0.0.1:7404/，口令就是安装页里填的那个管理台口令——留空则管理台整个不开放（登录回 403「管理台未启用」），收发消息不受影响。JWT 签名钥不用你填，服务端自动生成并回写配置文件。然后「频道 → 新建」。频道号和密钥就是要填进推送工具的那一对；密钥只在创建和重置的那一刻显示一次。
  6. 可选：跑一次端到端自检 
    cd deploy/probe && npm install      # 只需一次
node p0-e2e.mjs                     # 默认打 127.0.0.1:7404
PB_BASE=http://127.0.0.1:8081 node p0-e2e.mjs   # 端口不同时自己指
    它模拟一台设备走完整条链路：握手、注册、发消息、收帧、补拉、图片。末行 N/N 且 0 失败 才算这套装对了。它会在库里留下测试 Space 和设备，别对生产库跑。

图片存在哪里

后端怎么开适合
本地目录（默认）安装页里不勾「启用对象存储」，图片落 data/media（容器里 /app/data/media）本机起步、单机部署
对象存储安装页里勾上，再填地址 / 区域 / 桶名 / Access Key / Secret Key，桶名默认 pushbox要独立备份、要多机、要桶生命周期
  • 桶不需要匿名可读：图片字节由服务端取回后再发给设备，桶对客户端可以完全不可见。
  • endpoint 是 IP 或裸主机名时「Path Style」保持勾上，虚拟主机风格的域名解析不出来；接阿里云 OSS 或 AWS 时按服务商文档取消。
  • 想让对象在桶里是密文：勾上「加密存储」，再填一个加密口令（至少 12 个字符，由服务端用 Argon2id 派生出 KEK）；高级项里也可以改填一把主钥（openssl rand -base64 32）。两者只能留一个，同时填安装页会拒绝。开关只影响新写入的对象，历史对象按各自记录的形态读。
  • 图片从哪抓也有一道门：抓取器默认拒绝一切回环 / 私网 / CGNAT 地址（防 SSRF），所以图床在内网时必须在安装页「图片抓取放行主机」里点名——写 host 或 host:port，逗号分隔，精确等值匹配，不带 http:// 也不带路径，没有通配。少了这一项的表现是每条图片都静默失败（media_objects.error=ssrf_blocked），客户端只看到图不见了。放行是按主机点名的，没有"整段放开私网"的开关。
KEK 一旦有对象落库就不能换

换口令或换主钥等于旧封装钥全部解不开，表现为图片集体不见了，而且不可恢复。口令本身不存库：app_state.media_kek_v1 只存随机盐、KDF 参数与校验值，所以库还在、口令没变，重启/重装容器都能读回旧图；反过来，口令忘了与主钥丢了等价。请把它和数据库口令放在一起备份。

Docker 部署

镜像在 Docker Hub 上，里面同时装着服务端与 Web 管理台：同一个进程、同一个端口吐 API、长连接和页面，同源，所以不需要 CORS，反代也只要一条规则。镜像里没有任何配置——没有 ENV、没有必填变量、没有占位值；第一次启动它自己开一个安装页，你在浏览器里填完，配置落进 /app/data/config/pushbox.json，同一个进程接着启动，不用重启容器。

  1. 建账号；库和表都不用管，安装页与首次启动会建 
    CREATE USER IF NOT EXISTS 'pushbox'@'%' IDENTIFIED BY '<强口令>';
GRANT SELECT, INSERT, UPDATE, DELETE, CREATE, ALTER, INDEX, DROP, REFERENCES
  ON pushbox.* TO 'pushbox'@'%';
FLUSH PRIVILEGES;

SELECT @@ngram_token_size;   -- 期望 2；不是 2 就搜不出中文长句
    账号必须是 'pushbox'@'%'：写成 localhost 时，另一个容器连过来的来源就不是 localhost，口令全对也照样 1045。库由安装页执行 CREATE DATABASE IF NOT EXISTS 建出来，表由 Flyway 首次启动建。库只能是 MySQL 8.0/8.4（建表脚本用了 utf8mb4_0900_ai_ci 与 FULLTEXT … WITH PARSER ngram）。Hub 上那份镜像只有 linux/amd64，ARM 机型要自己构建。
  2. 起容器：一个变量都不用给，不用克隆仓库、不用 .env 
    docker run -d --name pushbox \
  -p 7404:7404 \
  -v pushbox_data:/app/data \
  docker.io/iamplusdev/push-box:latest
    只有一个卷：/app/data 里同时装配置、图片与日志，所以 NAS 表单的「存储位置」只有一行要选、chown 只 chown 一次、备份只指一个目录。容器内端口固定 7404，要换就换 -p 的左侧。
  3. 浏览器打开 http://127.0.0.1:7404/，把配置填进去 填库地址/端口/库名/用户名/密码；勾不勾对象存储（勾了就把地址、桶名、AK/SK 填全）；勾不勾加密（勾了就填一个至少 12 字符的口令）；管理台口令（留空 = 管理台不开放，登录回 403「管理台未启用」，收发不受影响）；运维网段（留空 = /healthz 与 /actuator/** 只有容器自己能读）；图片抓取放行主机（图床在内网时必须点名，见图片存在哪里）。库地址别填 127.0.0.1——容器里的环回是它自己，安装页会当场把这句话告诉你。旁边有「测试连接」按钮先单独判库；提交整份配置时它会真连一次库和桶（桶那一步是真写一个对象再删掉，所以桶要你先建好），任何一项不过就不写文件、把原因回给你。
  4. 验证：在容器里取 
    docker exec pushbox curl -s http://127.0.0.1:7404/healthz
    期望 {"ok":true,"db":"up","storage":"up","uptime_ms":…}。验收在容器里做：从宿主打过去会拿到 404，因为服务端只认容器环回（拒绝时故意不用 403，免得扫描器确认这里有个运维端点）。要宿主或监控直接读到它，就在安装页的「运维网段」里把这套网络分到的子网填进去。镜像里有 curl、没有 mysql 客户端。
  5. 登录管理台，建第一个频道 管理台在根路径 /（不是 /admin），登录口令就是安装页里填的那一个。JWT 签名钥不用你填，服务端自动生成并回写配置文件——所以没有"两个密钥必须不同且各 32 字节"这种要记的东西了。然后「频道 → 新建」——频道号和密钥就是要填进推送工具的那一对，密钥只在创建和重置的那一刻显示一次。

在 NAS 的图形界面（飞牛 / 群晖 / 1Panel）里装时没有 .env 这一层，而这一版正好也不需要它：「存储位置」只有一行——把容器内 /app/data 映射到 NAS 上一个文件夹（镜像声明了唯一一个 VOLUME，较新的表单会带出容器内路径，宿主文件夹仍要你选；建好后先 sudo chown -R 10001:10001 <那个文件夹>，否则入口脚本会当场判死并把这句修法打出来；留空则删容器时配置、图片、日志一起没），「环境变量」一行都不用填。剩下的全在浏览器那张表单上。逐步说明见仓库的 deploy/NAS部署指南.md，compose 版见 deploy/docker-compose.nas.yml。

要反代 / 监控 / 自带库和桶时：compose 形态

为什么这一条要克隆仓库而上面不用：docker-compose.yml、Caddyfile、docker-compose.monitoring.yml 和那几段 sidecar 定义都是文件，它们装不进 pushbox 镜像里。只要一个容器时用不到它们。.env 现在只装第三方容器的口令（mysql、rustfs、grafana）与反代域名——服务端的配置一项都不在里面。

  1. 取 compose 与配置模板 
    git clone https://github.com/iamplusdev/push-box.git
cd push-box/deploy
cp env/prod.env.example .env        # .env 不提交
    仓库里只要这几本书，机器上不用装 JDK 和 Maven——跑起来的那份是 Hub 上的镜像。只起服务端 + Caddy 时 .env 里必填的只有 PB_CADDY_HOST；其余几个键分别只在取消注释 mysql / rustfs 服务段、或挂上监控那本文件时才需要，它们喂的是那些第三方镜像。
  2. 起容器 
    docker compose pull           # 从 Docker Hub 取镜像
docker compose up -d
    Caddy 的 depends_on: service_healthy 不会被安装页卡住：没配置完的容器停在安装页上，那时 /healthz 根本不存在，但 7404 已经有人监听——所以 healthcheck 判的是端口通不通。要监控再多加一本书：docker compose -f docker-compose.yml -f docker-compose.monitoring.yml up -d。
  3. 浏览器打开 http://<PB_CADDY_HOST>/ 完成安装 安装页也走同一条反代，不需要额外的端口或路径规则。用 compose 自带的 mysql / rustfs 时，表单里填 mysql 与 http://rustfs:9000——同一网络内用服务名，不要填宿主 IP。要让 Prometheus 抓到指标，把这套网络分到的子网填进「运维网段」，否则进程好好的、targets 全 403。
  4. 验证 
    docker compose exec pushbox-server curl -s http://127.0.0.1:7404/healthz
    同样是在容器里取，理由上面写过一次了。
拓扑起什么安装页里怎么填
A：已有 MySQL 与桶（默认）服务端 + Caddy库地址填那台 MySQL 的 IP，勾上对象存储并把地址指到那个桶
B：全都自己起再加 mysql:8.4 与对象存储取消 compose 里那两段的注释，表单里地址写 service-name（mysql / http://rustfs:9000）；嫌手写麻烦直接用 docker-compose-wsl.yml + deploy-wsl.sh，后者的 setup 子命令会替你调安装页接口。那两段起来的是空实例，建账号照样在你自己身上
C：不用桶服务端 + MySQL，图片落卷不勾对象存储就行，图片落 /app/data/media
  • /app/data 必须挂卷，compose 里已经挂成 named volume pushbox_data。改成宿主目录时注意属主要能被容器里的账号写（uid 10001）：这条有启动阶段的写入探针兜，写不进就当场退出并给出两种修法，不会拖到第一条带图的消息才看出来。
  • 「要不要加密」现在是表单上一个开关，不再是一道拒绝启动的闸门——勾不勾由你表态，勾了就必须填口令或主钥（二选一，同时填会被拒）。桶侧明文的代价说清楚：任何拿到同一组 AK/SK 的读者都能直接把图片读走。
  • 装完之后要改配置：直接编辑 /app/data/config/pushbox.json 再重启容器；把那个文件删掉，下次启动就回到安装页，用「从库里找回上一次的配置」能把原来那份拉回来（副本存在 app_state.runtime_config_v1）。

HTTPS 与自签 CA

内网裸 HTTP 可以跑，但接了公网就得上证书。两条路：Caddy 的 Let's Encrypt（有公网域名时最省事），或自建根 CA 签一张内部域名。

  1. 签一套证书（在一台管理机上跑，不在部署机上） 
    PUSHBOX_HOST=pushbox.internal PUSHBOX_IP=<部署机IP> deploy/ca/gen-ca.sh
# 只把 certs/pushbox.crt、pushbox.key、pushbox_ca.crt 拷到部署机的 deploy/certs/
# 根 CA 私钥 pushbox_ca.key 离线保存：不进仓库、不上部署机
  2. 服务端：把 Caddyfile 的 tls 指到那三本证书 主机名从 PB_CADDY_HOST 读，改一处即可。叶子证书到期用同一根 CA 重签，各端已信任的根不用动。
  3. Windows：把根 CA 装进当前用户的根存储 
    certutil -addstore -user Root pushbox_ca.cer
    -user 不需要管理员权限。已经跑着的程序不会回头重读根存储，换证书的动作是「退出再起一次」；撤销证书要按指纹删。
  4. Android：根 CA 内置在 APK 里 用自签证书时要用带这份根的构建；系统根存储里的自签证书不会被接受。
两端都不跳过证书校验

帧加密补的是链路，TLS 补的是「服务端本身可信」，两者互不替代。

备份

  1. 一条命令把库和图都备走 
    MYSQL_HOST=<DB_HOST> PB_DB_PASSWORD=... PB_S3_ACCESS_KEY=... \
AGE_RECIPIENT=<age 或 ssh 公钥> [RUSTFS_DATA_DIR=/path/to/data/rustfs] \
  deploy/backup/backup.sh
    这里那几个 PB_* 是备份脚本自己的入参（值就是安装页里填的那几项，可以从 /app/data/config/pushbox.json 里抄），不是服务端读的环境变量——服务端一个环境变量都不读。产物是 pushbox-<UTC>.sql.gz.age 与 rustfs-<UTC>.tar.age：库用一致性快照导出不锁表，导出后立刻加密。因为库里存的是明文，异地上传前必须加密；图片只有一份，在桶或那个目录里，丢了不可恢复。加密口令/主钥也要一起备——KEK 不可轮换，丢了等于旧图片全废。挂 cron 或 systemd timer 定时跑。

Android

  1. 装上 APK 安装包放在 GitHub Releases，找 pushbox-release-<版本号>.apk。还没有对应版本时先从源码编：cd android && ./gradlew :app:assembleDebug，再 adb install -r。
  2. 首启填服务器地址 模拟器填 http://10.0.2.2:7404，真机填这台机器的局域网地址（须与服务器同网段）。上了 HTTPS 就填域名，端口省略。
  3. 注册新 Space，或用恢复码加入已有 Space 注册后会给出一个恢复码：把它抄在纸上。它是换机、重装、忘记设备密钥时唯一的找回途径。
  4. 立刻做完保活引导 见 使用说明 · 让它在国产 ROM 上活着。不依赖厂商推送，就要付出让系统放行的代价，这一步决定体验成败。

Windows

  1. 运行安装包 安装包同样在 GitHub Releases，文件名 PushBox-Setup-<版本号>-win-x64.exe（每个 Release 页上就是本次那一个），装在当前用户的 %LOCALAPPDATA%\Programs\PushBox，不需要管理员权限，也不需要先装 .NET。第一次双击时 SmartScreen 会先挡一道「Windows 保护了你的电脑」，点更多信息 → 仍要运行即可。自己编译：bash windows/installer/build-installer.sh（需要 Inno Setup 6）。
  2. 首启填服务器地址并接入 和 Android 一样：注册新 Space 或用恢复码加入；频道可以在管理台建好后在设备上接入。
  3. 要知道的两件事 开机自启默认关闭，在设置里打开。卸载不会删 %LOCALAPPDATA%\PushBox：身份、历史库和日志都留着，重装后仍然认回同一个 Space。

数据全在 %LOCALAPPDATA%\PushBox\：identity.json（设备身份与私钥）、pushbox.db（消息与会话）、settings.json（开关）、logs\。

端口

  • 服务端固定 7404（安装页里可以改，但容器内改了就要同步改 -p 的右侧与 Caddyfile 的上游，所以通常别改）；要换端口就换宿主侧的映射，compose 形态下对外那一层由 PB_HTTP_PORT（默认 80）决定。
  • Caddy 在前面时对外 80/443；/actuator 与指标端口只绑 127.0.0.1，公网来源访问监控端点会得到 403。
  • 服务端默认不去抓私网地址的图片。要让内网图片进消息，把主机名精确加进 pb.media.allow-hosts（写 host 或 host:port，不是前缀匹配）。
