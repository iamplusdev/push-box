PushBox

任何程序一条 POST /message，消息就推送到你自己的手机和电脑。服务端存下来、抓图转存、加密下发，多端几乎同时到账。

快速上手 → 了解它怎么工作 📄
  • 三端源码：Java 服务端 · Android · Windows
  • 只依赖 MySQL 8 与一个 S3 兼容桶
  • 不接厂商推送，不经第三方转发

它做的三件事

把"第三方产生的消息"送到"你人在的那块屏幕"上，中间不留别人的服务器。

01 收得进来

一个频道号加一个密钥，任何脚本、Grafana、CI、cron 都能发。凭据只写不读，重复提交按 msg_key 幂等。

02 存得明白

正文与图片都存在你自己的 MySQL 与对象存储里，全文索引能搜、摘要服务端生成、外链图片抓取转存。

03 送得到位

长连接加密下发到每台设备，手机与 PC 同时出通知；一边点开会话，另一边红点随即消失。断线按游标补齐，每台设备还可以只收自己接入的那几条频道。

一条消息走过的路

受理只写库、立刻回执；图片抓取与加密下发都在回执之后，第三方等不起的那几秒不由它承担。

你的程序Grafana、CI、cron、内网服务，只需一个频道号 + 密钥
受理校验凭据、幂等、分配 seq、生成摘要，立即 200 回执
抓图转存外链图片并发抓取 → 缩略图 → 存进对象存储（超预算先出正文）
加密下发每台设备自己的会话钥加密同一帧，多端同时到达
客户端入库、出通知，点进会话把已读报回去，别的端红点随之消失

装在你机器上的样子

单向接收：气泡统一左对齐，不做"发送方 / 接收方"双色；告警级别只用气泡左侧一条 3px 色条表达。

一个绕不开的取舍

服务端到客户端这一跳是加密的（X25519 + AES-256-GCM 帧通道，REST 响应走一次性 sealed-box）；服务端库里存的是明文。

明文是刻意的

只有这样全文索引才能命中正文、服务端才能生成摘要、才能替你抓取外链图片。

密钥只能写不能读

拿到 secret 能往这个频道推，但读不到任何历史；读历史要设备密钥或恢复码。"加入频道"用的也是这一对凭据，它只把这条频道登记进这台设备的接收集，不多给任何读权限。

请上 HTTPS

帧加密补的是链路，TLS 补的是"服务端本身可信"，两者互不替代。deploy/Caddyfile 给了两条路。

端到端加密被评估过并否决了——它的代价正是上面三件功能。展开版在 概览 · 信任边界。
