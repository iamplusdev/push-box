安装与部署

安装与部署

先起服务端，再装两端。服务端与 Android、Windows 之间没有构建依赖，只有协议依赖，所以三端可以各装各的。

前置要求

组件要求
MySQL8.0 / 8.4，且 ngram_token_size=2
图片存储本地一个目录，或任意 S3 兼容桶（可选项）
JDK / Maven自己构建服务端时才需要：JDK 21、Maven 3.9+
Docker容器部署时唯一需要的一项
Android8.0 起；直接装发布的 APK
WindowsWindows 10 19041 起，安装包自带运行时

本机起服务端

这条路径不需要桶、不需要 Docker，只要本机有一个 MySQL 8。

  1. 建库和账号；表结构不用管，首次启动会自动建 
    CREATE DATABASE IF NOT EXISTS pushbox
  CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;
CREATE USER IF NOT EXISTS 'pushbox'@'localhost' IDENTIFIED BY '<强口令>';
GRANT SELECT, INSERT, UPDATE, DELETE, CREATE, ALTER, INDEX, DROP, REFERENCES
  ON pushbox.* TO 'pushbox'@'localhost';
FLUSH PRIVILEGES;

SELECT @@ngram_token_size;   -- 期望 2；不是 2 就搜不出中文长句
    JDBC 走 TCP 到 127.0.0.1 时 MySQL 认的主机名是 localhost；连不上的话把同一个账号再建一份 'pushbox'@'127.0.0.1'。
  2. 把口令放进环境变量，别写进配置文件 
    cp deploy/env/local.env.example deploy/env/local.env
# 必填只有 PB_DB_PASSWORD 一项，其余按需改
# local.env 已在 .gitignore 里，它不该出现在任何一次提交中
    配置文件里 password: ${PB_DB_PASSWORD} 故意不留默认值：忘了 source 就直接启动失败，而不是拿空口令去连库、把配置问题伪装成 Access denied。
  3. 构建并启动 
    export JAVA_HOME=/path/to/jdk-21    # 机器默认的 JAVA_HOME 常常还是 JDK 8
mvn -B -DskipTests package
bash deploy/run-dev.sh              # 监听 7404，自己 source deploy/env/local.env
    换端口、改配置一律往后加参数：bash deploy/run-dev.sh --server.port=8081 --pb.s3.delete-grace=2s。
  4. 确认它起来了 
    curl -sS http://127.0.0.1:7404/healthz
    期望 {"ok":true,"db":"up","storage":"up","uptime_ms":…}；任一段是 down 时进程回 503。/actuator/health 是另一本形状，只回 {"status":"UP"}（组件明细被 show-details: never 挡住）。
  5. 登录管理台，建第一个频道 浏览器打开服务端根路径 http://127.0.0.1:7404/，口令就是 PB_ADMIN_SECRET 的值——dev 配置自带一个占位口令，本地起步直接用；对外部署必须自己换一个。然后「频道 → 新建」。频道号和密钥就是要填进推送工具的那一对；密钥只在创建和重置的那一刻显示一次。
  6. 可选：跑一次端到端自检 
    cd deploy/probe && npm install      # 只需一次
node p0-e2e.mjs                     # 默认打 127.0.0.1:7404
PB_BASE=http://127.0.0.1:8081 node p0-e2e.mjs   # 端口不同时自己指
    它模拟一台设备走完整条链路：握手、注册、发消息、收帧、补拉、图片。末行 N/N 且 0 失败 才算这套装对了。它会在库里留下测试 Space 和设备，别对生产库跑。

图片存在哪里

后端怎么开适合
local（默认）什么都不用配，图片落 PB_STORAGE_LOCAL_PATH，默认 ./data/media本机起步、单机部署
s3PB_STORAGE_TYPE=s3 加 PB_S3_ENDPOINT / PB_S3_ACCESS_KEY / PB_S3_SECRET_KEY，桶名默认 pushbox要独立备份、要多机、要桶生命周期
  • 桶不需要匿名可读：图片字节由服务端取回后再发给设备，桶对客户端可以完全不可见。
  • endpoint 是 IP 或裸主机名时 pb.s3.path-style 保持 true，虚拟主机风格的域名解析不出来。
  • 想让对象在桶里是密文：主钥 PB_S3_MASTER_KEY=$(openssl rand -base64 32)，再加 --pb.s3.object-encrypt=sse-c。开关只影响新写入的对象，历史对象按各自记录的形态读。
主钥一旦有对象落库就不能换

换主钥等于旧封装钥全部解不开，表现为图片集体不见了，而且不可恢复。请把它和数据库口令放在一起备份。

Docker 部署

镜像在 Docker Hub 上，里面同时装着服务端与 Web 管理台：同一个进程、同一个端口吐 API、长连接和页面，同源，所以不需要 CORS，反代也只要一条规则。起步只必填两项——库地址与库口令，其余拓扑默认值已经烘焙在镜像的 ENV 里。

  1. 建库和账号；表结构不用管，首次启动会自动建 
    CREATE DATABASE IF NOT EXISTS pushbox
  CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;
CREATE USER IF NOT EXISTS 'pushbox'@'%' IDENTIFIED BY '<强口令>';
GRANT SELECT, INSERT, UPDATE, DELETE, CREATE, ALTER, INDEX, DROP, REFERENCES
  ON pushbox.* TO 'pushbox'@'%';
FLUSH PRIVILEGES;

SELECT @@ngram_token_size;   -- 期望 2；不是 2 就搜不出中文长句
    账号必须是 'pushbox'@'%'：写成 localhost 时，另一个容器连过来的来源就不是 localhost，口令全对也照样 1045。库只能是 MySQL 8.0/8.4（建表脚本用了 utf8mb4_0900_ai_ci 与 FULLTEXT … WITH PARSER ngram）。Hub 上那份镜像只有 linux/amd64，ARM 机型要自己构建。
  2. 起容器：两个变量，不用克隆仓库、不用 .env 
    docker run -d --name pushbox \
  -p 7404:7404 \
  -e PB_DB_HOST=<库的IP或服务名> -e PB_DB_PASSWORD='<强口令>' \
  -v pushbox-media:/app/data/media -v pushbox-logs:/app/logs \
  docker.io/iamplusdev/push-box:latest
    不给别的值时：端口 7404、本地文件存储（图片落 pushbox-media 卷，明文 + 每文件 600 权限，启动时出声提醒一次）、管理台关闭、库名与库用户名都是 pushbox。要换形态就在同一条命令后面追加同名变量：PB_STORAGE_TYPE=s3 加 PB_S3_* 外接桶，PB_S3_OBJECT_ENCRYPT=sse-c 加 PB_S3_MASTER_KEY 让本地图片也加密（主钥一旦有对象落库就不可轮换），PB_SERVER_PORT 改端口（-p 右侧要跟着改）。镜像之外没有第二件事——第 1 步那个库建好就到此为止。
  3. 已经有一个桶？同一条命令让它落桶 
    docker run -d --name pushbox \
  -p 7404:7404 \
  -e PB_DB_HOST=<库的IP或服务名> -e PB_DB_PASSWORD='<强口令>' \
  -e PB_STORAGE_TYPE=s3 \
  -e PB_S3_ENDPOINT=http://<桶机的IP>:7101 \
  -e PB_S3_ACCESS_KEY='<AK>' -e PB_S3_SECRET_KEY='<SK>' \
  -e PB_S3_BUCKET=pushbox \
  -e PB_S3_OBJECT_ENCRYPT=sse-c -e PB_S3_MASTER_KEY="$(openssl rand -base64 32)" \
  -v pushbox-logs:/app/logs \
  docker.io/iamplusdev/push-box:latest
    和上一条命令比只多了 5 行、少了一个卷。PB_STORAGE_TYPE=s3 不能省：镜像默认是 local，只给 PB_S3_* 不给这个开关，那几项一个字都不读（启动时会点名提醒"配了但读不到"），图片照旧落本地目录。对象落桶后 pushbox-media 那个卷就没用了，日志卷还是要。桶要你先建好，程序不建桶；跟别的系统共用一个桶可以，但只读写 PushBox 自己那套对象键。PB_S3_PATH_STYLE 默认 true（MinIO / RustFS 是对的），阿里云 OSS 或 AWS 按服务商文档可能要 false；桶名与区域不是 pushbox / us-east-1 就改上面那两行。图片明文落在桶上是拒绝启动的——桶侧任何拿到同一组 AK/SK 的读者都能直接读走，所以要 sse-c + 主钥，或显式 -e PB_ALLOW_PLAINTEXT_MEDIA=1 表态。
  4. 验证：在容器里取 
    docker exec pushbox curl -s http://127.0.0.1:7404/healthz
    期望 {"ok":true,"db":"up","storage":"up","uptime_ms":…}。验收在容器里做：从宿主打过去会拿到 404，因为服务端只认容器环回（拒绝时故意不用 403，免得扫描器确认这里有个运维端点）。要宿主或监控直接读到它，就把这套网络分到的子网写进 PB_SECURITY_INTERNAL_CIDRS。镜像里有 curl、没有 mysql 客户端。
  5. 要管理台就补两个密钥，浏览器打开根路径 
    # 加在第 2 步那条命令里，然后重新起一次
-e PB_ADMIN_SECRET="$(openssl rand -base64 32)" \
-e PB_ADMIN_JWT_SECRET="$(openssl rand -base64 32)"
    要用管理台这两个值就必须都有、互不相同、各自至少 32 字节，只填一个或填弱值容器会直接拒绝启动。两个都留空是一个合法状态：管理台整个关闭，那些接口一律回 403「管理台未启用」，客户端收发不受影响。管理台在根路径 /（不是 /admin），登录口令就是 PB_ADMIN_SECRET。然后「频道 → 新建」——频道号和密钥就是要填进推送工具的那一对，密钥只在创建和重置的那一刻显示一次。

在 NAS 的图形界面（飞牛 / 群晖 / 1Panel）里装时没有 .env 这一层。用「创建容器」表单的话，只有两处要自己动手：存储位置加两行——容器内 /app/data/media 与 /app/logs 各映射到 NAS 上一个文件夹（建好后先 sudo chown -R 10001:10001 <那个文件夹>；留空则删容器时图片一起没）；环境变量只填两个——PB_DB_HOST 与 PB_DB_PASSWORD，表单里显示出来的其余项都是默认值。要外接桶就把 PB_STORAGE_TYPE=s3 与 PB_S3_* 六行一次加齐。逐步说明见仓库的 deploy/NAS部署指南.md 路径 C，compose 版见 deploy/docker-compose.nas.yml。

要反代 / 监控 / 自带桶时：compose 形态

为什么这一条要克隆仓库而上面不用：docker-compose.yml、Caddyfile、docker-compose.monitoring.yml 和那几段 sidecar 定义都是文件，它们装不进 pushbox 镜像里；.env 只是给这些文件记账的那一层。只要一个容器时用不到它们。

  1. 取 compose 与配置模板 
    git clone https://github.com/iamplusdev/push-box.git
cd push-box/deploy
cp env/prod.env.example .env        # .env 不提交
    仓库里只要这几本书，机器上不用装 JDK 和 Maven——跑起来的那份是 Hub 上的镜像。
  2. 生成口令填进 .env，不要手编弱值 
    PB_DB_PASSWORD=$(openssl rand -base64 24)
PB_ADMIN_SECRET=$(openssl rand -base64 32)
PB_ADMIN_JWT_SECRET=$(openssl rand -base64 32)
sed -i "s|^PB_DB_PASSWORD=.*|PB_DB_PASSWORD=$PB_DB_PASSWORD|" .env
sed -i "s|^PB_ADMIN_SECRET=.*|PB_ADMIN_SECRET=$PB_ADMIN_SECRET|" .env
sed -i "s|^PB_ADMIN_JWT_SECRET=.*|PB_ADMIN_JWT_SECRET=$PB_ADMIN_JWT_SECRET|" .env
    管理台登录用 PB_ADMIN_SECRET；PB_ADMIN_JWT_SECRET 是签名钥，两个一起填时必须不同且各不短于 32 字节，只填一个容器就拒绝启动。改口令不会作废已登录的会话，反之也一样。
  3. 按自己的情况选拓扑，然后起容器 
    docker compose pull           # 从 Docker Hub 取镜像
docker compose up -d
    要监控再多加一本书：docker compose -f docker-compose.yml -f docker-compose.monitoring.yml up -d，并把那条网络分到的子网写进 PB_SECURITY_INTERNAL_CIDRS，否则进程好好的、targets 全 403。
  4. 验证 
    docker compose exec pushbox-server curl -s http://127.0.0.1:7404/healthz
    同样是在容器里取，理由上面写过一次了。
拓扑起什么改哪几行
A：已有 MySQL 与桶（默认）服务端 + CaddyPB_DB_URL、PB_S3_ENDPOINT 指到那台 MySQL 与那个桶
B：全都自己起再加 mysql:8.4 与对象存储取消 compose 里那两段的注释，地址写 service-name；嫌手写麻烦直接用 docker-compose-wsl.yml。那两段起来的是空实例，建库建账号照样在你自己身上
C：不用桶服务端 + MySQL，图片落卷PB_STORAGE_TYPE=local，PB_S3_* 留空
  • compose 只认 PB_* 这一套名字，不要再写 SPRING_DATASOURCE_URL 之类的别名——两个名字各声称拥有同一个键时，排查会看不出真实取值来自哪。
  • 拓扑 C 的 /app/data/media 必须挂卷，compose 里已经挂成 named volume pushbox_server_media。改成宿主目录时注意属主要能被容器里的账号写（uid 10001）：这条现在有启动阶段的写入探针兜，写不进就当场退出并给出两种修法，不会拖到第一条带图的消息才看出来。
  • 「不许静默写明文」这条卡的是桶：PB_STORAGE_TYPE=s3 时 none 会拒绝启动，要么开 sse-c 配主钥，要么显式 PB_ALLOW_PLAINTEXT_MEDIA=1。local 只打一条 WARN——对象在部署者自己的盘上、逐文件 600 权限，硬拦只会逼人为了过检查去配一个用不到的桶。

HTTPS 与自签 CA

内网裸 HTTP 可以跑，但接了公网就得上证书。两条路：Caddy 的 Let's Encrypt（有公网域名时最省事），或自建根 CA 签一张内部域名。

  1. 签一套证书（在一台管理机上跑，不在部署机上） 
    PUSHBOX_HOST=pushbox.internal PUSHBOX_IP=<部署机IP> deploy/ca/gen-ca.sh
# 只把 certs/pushbox.crt、pushbox.key、pushbox_ca.crt 拷到部署机的 deploy/certs/
# 根 CA 私钥 pushbox_ca.key 离线保存：不进仓库、不上部署机
  2. 服务端：把 Caddyfile 的 tls 指到那三本证书 主机名从 PB_CADDY_HOST 读，改一处即可。叶子证书到期用同一根 CA 重签，各端已信任的根不用动。
  3. Windows：把根 CA 装进当前用户的根存储 
    certutil -addstore -user Root pushbox_ca.cer
    -user 不需要管理员权限。已经跑着的程序不会回头重读根存储，换证书的动作是「退出再起一次」；撤销证书要按指纹删。
  4. Android：根 CA 内置在 APK 里 用自签证书时要用带这份根的构建；系统根存储里的自签证书不会被接受。
两端都不跳过证书校验

帧加密补的是链路，TLS 补的是「服务端本身可信」，两者互不替代。

备份

  1. 一条命令把库和图都备走 
    MYSQL_HOST=<DB_HOST> PB_DB_PASSWORD=... PB_S3_ACCESS_KEY=... \
AGE_RECIPIENT=<age 或 ssh 公钥> [RUSTFS_DATA_DIR=/path/to/data/rustfs] \
  deploy/backup/backup.sh
    产物是 pushbox-<UTC>.sql.gz.age 与 rustfs-<UTC>.tar.age：库用一致性快照导出不锁表，导出后立刻加密。因为库里存的是明文，异地上传前必须加密；图片只有一份，在桶或那个目录里，丢了不可恢复。挂 cron 或 systemd timer 定时跑。

Android

  1. 装上 APK 安装包放在 GitHub Releases，找 pushbox-release-<版本号>.apk。还没有对应版本时先从源码编：cd android && ./gradlew :app:assembleDebug，再 adb install -r。
  2. 首启填服务器地址 模拟器填 http://10.0.2.2:7404，真机填这台机器的局域网地址（须与服务器同网段）。上了 HTTPS 就填域名，端口省略。
  3. 注册新 Space，或用恢复码加入已有 Space 注册后会给出一个恢复码：把它抄在纸上。它是换机、重装、忘记设备密钥时唯一的找回途径。
  4. 立刻做完保活引导 见 使用说明 · 让它在国产 ROM 上活着。不依赖厂商推送，就要付出让系统放行的代价，这一步决定体验成败。

Windows

  1. 运行安装包 安装包同样在 GitHub Releases，文件名 PushBox-Setup-<版本号>-win-x64.exe（每个 Release 页上就是本次那一个），装在当前用户的 %LOCALAPPDATA%\Programs\PushBox，不需要管理员权限，也不需要先装 .NET。第一次双击时 SmartScreen 会先挡一道「Windows 保护了你的电脑」，点更多信息 → 仍要运行即可。自己编译：bash windows/installer/build-installer.sh（需要 Inno Setup 6）。
  2. 首启填服务器地址并接入 和 Android 一样：注册新 Space 或用恢复码加入；频道可以在管理台建好后在设备上接入。
  3. 要知道的两件事 开机自启默认关闭，在设置里打开。卸载不会删 %LOCALAPPDATA%\PushBox：身份、历史库和日志都留着，重装后仍然认回同一个 Space。

数据全在 %LOCALAPPDATA%\PushBox\：identity.json（设备身份与私钥）、pushbox.db（消息与会话）、settings.json（开关）、logs\。

端口

  • 服务端默认 7404；容器里对外由 PB_HTTP_PORT（默认 80）决定。
  • Caddy 在前面时对外 80/443；/actuator 与指标端口只绑 127.0.0.1，公网来源访问监控端点会得到 403。
  • 服务端默认不去抓私网地址的图片。要让内网图片进消息，把主机名精确加进 pb.media.allow-hosts（写 host 或 host:port，不是前缀匹配）。
